# 5.4 安装器加入 PATH

> 状态：已实现，待 VM 验收
> 日期：2026-11-05
> 目标：安装/修复后，新终端可以直接运行 `WinAppGuard.exe`，不用写完整路径或手动改 PATH。

## 1. 行为

### 安装 / 修复

`WinAppGuardSetup.exe --install` 或 `--repair` 成功后：

- 把 `C:\Program Files\WinAppGuard` 追加到 **系统 PATH**（Machine）；
- 已存在时不重复追加（大小写、尾部反斜杠、引号、`%ProgramFiles%` 变量都视为同一项）；
- 保留原来的值类型：
  - `REG_EXPAND_SZ` 仍然是 `REG_EXPAND_SZ`；
  - `REG_SZ` 仍然是 `REG_SZ`；
- 修改后广播 `WM_SETTINGCHANGE`，新启动的进程能拿到新 PATH；
- 安装继续使用原来的退出码；PATH 写入失败只警告，不假称安装失败。

### 卸载

`WinAppGuardSetup.exe --uninstall` 成功删除安装目录后：

- 从系统 PATH 移除 `C:\Program Files\WinAppGuard`；
- 只移除这一项，其它 PATH 项保留；
- 如果安装目录没有删掉（文件被占用等），**不**移除 PATH，避免留下“程序还在但命令找不到”的状态；
- PATH 移除失败会报告，并以部分卸载（退出码 3）结束。

### 已经打开的终端

修改环境变量不会刷新已经打开的终端。安装器会广播变更，但用户仍需：

```text
关闭当前终端 → 从开始菜单重新打开 → WinAppGuard.exe --version
```

## 2. 实现

| 文件 | 作用 |
|---|---|
| `src/WinAppGuard.Core/EnvironmentPath.cs` | PATH 字符串的纯函数：`Contains` / `Add` / `Remove` |
| `src/WinAppGuard.Setup/PathRegistration.cs` | 读写 Machine PATH，保留值类型，广播变更 |
| `src/WinAppGuard.Setup/Program.cs` | 安装/修复后调用 `TryAdd`；卸载删目录后调用 `TryRemove` |
| `tools/SelfCheck/Program.cs` | PATH 去重、删除、大小写、引号、空值测试 |

### 安全边界

- 只追加/删除安装目录，不修改其它 PATH 项；
- 不展开或重写其它项里的环境变量；
- PATH 超过 30000 字符时拒绝修改并提示；
- 注册表打不开或没有权限时返回失败，由安装器提示手动添加；
- 不把安装目录写到用户 PATH，避免“只有当前用户能用”；
- 安装器仍然需要管理员权限；不新增服务、驱动或自动启动项。

## 3. 验证

### 自动化

```text
dotnet build WinAppGuard.sln -c Debug    0 警告 0 错误
SelfCheck --cli-test                     通过（含 PATH 字符串测试）
```

### VM 手工

1. 记录安装前的系统 PATH：

```powershell
$key = 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Environment'
(Get-ItemProperty $key).Path
(Get-Item $key).GetValueKind('Path')
```

2. 运行 5.4 Setup（安装或 `--repair`）。
3. 确认注册表里出现了安装目录，且值类型没变：

```powershell
$key = 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Environment'
(Get-ItemProperty $key).Path -split ';' | Where-Object { $_ -like '*WinAppGuard*' }
(Get-Item $key).GetValueKind('Path')
```

4. **关掉所有终端，从开始菜单重新打开 PowerShell**：

```powershell
WinAppGuard.exe --version
WinAppGuard.exe --status --json
```

预期：直接可用，不需要完整路径。

5. 再执行一次 `--repair`，确认 PATH 里没有重复项。
6. 卸载：

```powershell
& 'C:\Program Files\WinAppGuard\WinAppGuardSetup.exe' --uninstall
```

7. 重开终端，确认：

```powershell
$key = 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Environment'
(Get-ItemProperty $key).Path -split ';' | Where-Object { $_ -like '*WinAppGuard*' }
```

预期：没有 WinAppGuard 项；其它 PATH 项还在。

### 边界

- 安装目录已在 PATH 中（用户手动添加）：安装不重复添加；卸载会移除该项，因为目录即将删除。
- PATH 中写的是 `%ProgramFiles%\WinAppGuard`：安装/卸载都能识别为同一项。
- PATH 项带引号或尾部反斜杠：去重和删除都能识别。
- 多用户：系统 PATH 对所有用户生效；每个用户新开的终端都能用。
- 便携版/未安装：不会自动加入 PATH，仍使用完整路径。

## 4. 不在 5.4 范围

- 把安装目录加入**用户** PATH；
- 自动修改 `PATHEXT`；
- 安装时创建 `wag` 别名；
- 自动刷新已经打开的终端（Windows 不支持）。
