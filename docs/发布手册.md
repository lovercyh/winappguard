# WinAppGuard 发布手册

从零到产出一个可发布的单文件 exe。

---

## 一、环境准备

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 x64（开发机） |
| .NET SDK | 10 或更高 |
| 权限 | 需要管理员（脚本会调 UAC） |
| 目标机器 | Windows 10 / 11 x64，**不需要装 .NET**（自包含发布） |

```powershell
dotnet --version      # 应输出 10.x
```

---

## 二、构建

```powershell
# 日常调试构建（快）
dotnet build WinAppGuard.sln -c Debug

# 发布配置构建（会带 RID，慢一些）
dotnet build WinAppGuard.sln -c Release
```

要求：**0 个警告、0 个错误**。出现警告要当错误对待，别放过去。

---

## 三、发布

### 产品

```powershell
powershell -ExecutionPolicy Bypass -File .\build\publish.ps1
```

产出：`dist\WinAppGuard.exe`

- win-x64 自包含，约 49 MB
- **单文件**，脚本会检查发布目录里除 exe 和 pdb 外没有别的文件
- 内嵌图标（`Resources\app.ico`）
- 版本号来自 `src\WinAppGuard\WinAppGuard.csproj` 的 `<Version>`

### 自检工具（不随产品发布）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\publish-check.ps1
```

产出：`dist-tools\WinAppGuard.SelfCheck.exe`

## 四、发布前必须做的事

### 1. 确认版本号

编辑 `src\WinAppGuard\WinAppGuard.csproj`：

```xml
<Version>1.0.0</Version>
```

同时建议填上（会显示在 exe 的「属性 → 详细信息」里）：

```xml
<Company>你的公司或你的名字</Company>
<Copyright>Copyright © 2026 你的名字</Copyright>
```

### 2. 跑出厂审计

证明这一版没有引入第三方库、也没有偷偷多出联网能力：

```powershell
.\dist-tools\WinAppGuard.SelfCheck.exe --audit `
    .\src\WinAppGuard\bin\Release\net10.0-windows\win-x64\WinAppGuard.dll
```

要看到：

- **零第三方库**：引用的程序集全部来自 .NET 框架
- **联网边界受控**：网络类型只有 `TcpClient` / `NetworkStream`，**都在预期清单内**。
  一旦出现 `HttpClient` / `Dns` / `SslStream` 之类会直接判失败 ——
  那说明有人在别处新增了联网路径，必须先解释清楚再发布
- **无绕过**：没有用 P/Invoke 直接调 `ws2_32` / `winhttp` / `wininet` / `dnsapi`
  （只检查托管类型的话，那种写法能绕过去，这一项就是防它的）
- P/Invoke 清单与上一次发布相比没有意外新增

> 为什么审计的是 DLL 而不是 exe：单文件 exe 是宿主程序，我们的代码被打包在里面，
> 直接读它的元数据读不到。审计 DLL 得到的引用关系和打包后的 exe 是一致的。

### 3. 跑 IP 归属自检

```powershell
.\dist-tools\WinAppGuard.SelfCheck.exe --ownership-core-test   # 离线，不联网，17 项
.\dist-tools\WinAppGuard.SelfCheck.exe --ownership-test        # 会联网（whois.cymru.com:43），5 项
```

要看到两个都是 `通过 = 全部，失败 = 0`。
`--ownership-test` 会打印每个地址是「会发送」还是「本地拦截」——
后者必须覆盖掉所有私有 / 回环 / 链路本地地址。

### 4. 跑防火墙自检

```powershell
.\dist-tools\WinAppGuard.SelfCheck.exe
```

要看到 `检查项总数 = 42，通过 = 42，失败 = 0`，并且收尾时残留规则为 0。

### 5. 跑开机自启自检

```powershell
.\dist-tools\WinAppGuard.SelfCheck.exe --autostart-test
```

要看到任务内容逐项核对通过（尤其是**执行时长不限 `PT0S`**），并且收尾时残留任务为 0。

### 6. 按验收清单逐条勾选

见 [`验收清单.md`](验收清单.md)。至少要覆盖：

- 主界面按钮状态机（切标签页不失效）
- 设置页布局（长文字不压住按钮）
- 单实例（连续双击只有一个托盘图标）
- 注销 → 重新登录真的会自启
- 阻止后真的连不上、恢复后真的能连上
- **首次运行的一次性告知弹窗、以及 §H 那 10 条 IP 归属项**

> 提一句：`dist-tools\运行自检.cmd` 是发布脚本自动生成的双击启动器，
> 会把两个 IP 归属检查各跑一遍，方便在虚拟机里直接验证。

## 五、交付

给用户的就一个文件：

```
dist\WinAppGuard.exe
```

附上：

- [`../README.md`](../README.md) —— 这东西是干什么的、怎么用
- [`安全说明.md`](安全说明.md) —— 它对你系统做了什么、你怎么自查
- [`验收清单.md`](验收清单.md) 的「第三节 端到端场景」—— 用户最关心的三个故事

**需要提前告知用户的**：

1. 双击会弹 UAC 确认框，这是预期行为（它要改防火墙和计划任务）；
2. exe **没有代码签名**，SmartScreen 首次运行会提示「未知发布者」，点「仍要运行」；
3. 程序会**常驻托盘**，点 X 只是收起来，要真正退出请右键托盘图标；
4. 开机自启属于「提权持久化」，个别安全软件可能给出提示，这是机制性质，不是隐藏行为。

## 六、卸载（写进给用户的说明里）

```
1. 打开 WinAppGuard
2. 「已阻止的程序」页 → 删除全部 AppGuard 规则
3. 「设置」页 → 关闭开机自启
4. 托盘右键 → 退出
5. 删除 WinAppGuard.exe
6. （可选）删除 %LOCALAPPDATA%\WinAppGuard 目录
```

第 2、3 步不做就直接删 exe 的话，**防火墙规则和计划任务会留在系统里继续生效**。
真遇到这种情况：`wf.msc` 搜 `AppGuard` 删规则、`taskschd.msc` 删任务。

## 七、常见问题

### 发布脚本报「单文件之外还存在以下文件」

说明单文件打包没有完全生效。检查 `WinAppGuard.csproj` 里 Release 配置下这几个属性：

```xml
<PublishSingleFile>true</PublishSingleFile>
<IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
```

注意**不要**开 `PublishTrimmed` —— WinForms 大量依赖反射和 COM，裁剪后会在运行时才报错。

### 自检工具的发布目录里多出一个 `WinAppGuard.runtimeconfig.json`

这是被引用的产品工程带过来的，没用。`tools\publish-check.ps1` 会删掉它。
MSBuild 阶段拦不住（试过，挂在 `ComputeResolvedFilesToPublishList` 上也不生效），
所以放在脚本里显式处理并在注释里说明了原因。

### 改 `.ps1` 脚本之后中文变乱码

PowerShell 5.1 会按 ANSI 解析**无 BOM 的 UTF-8 脚本**。
含中文的 `.ps1` 必须存成**带 BOM 的 UTF-8**。项目里的两个发布脚本都已经处理好了。

同理：**不要**用 `Get-Content` / `Set-Content` 去批量改含中文的 `.cs` 文件，
会把中文读乱再写回去。要用 `[System.IO.File]::ReadAllText/WriteAllText` 并显式指定 UTF-8。

**同一类坑也在 `.cmd` 上（而且是更硬的坑）**：`cmd.exe` 用系统 ANSI 代码页解码批处理文件，
里面的 UTF-8 中文会被解成乱码并**破坏命令解析**（`'这是乱码' 不是内部或外部命令`）。
注意 `chcp 65001` **救不了它** —— chcp 是在文件已经被逐行解析之后才执行的。

所以：**给用户用的 `.cmd` 一律纯 ASCII**，中文只放在文件名和输出里。
`dist-tools\运行自检.cmd` 由 `tools\publish-check.ps1` 用 `ASCIIEncoding` 生成，
不要手工改它、也不要往里面加中文注释。

### `%LOCALAPPDATA%\WinAppGuard\settings.json` 是什么

1.2 起新增的设置文件，用来记住开关（目前是「查询 IP 归属」和「是否弹过一次告知」）。
**只存布尔值，不存 IP**。如果你要验证「默认值」，把它删掉即可 ——
删掉后 IP 归属查询会重新变成开启、一次性告知会重新弹一次。

### 页面布局又出现了控件重叠

检查是不是又用了「`AutoSize` 控件 + 绝对坐标 + 固定高度容器」这个组合 ——
它在文字长度会变化的地方**必然**出问题。改用 Dock 布局：
长度会变的文字放进一个 `Dock=Fill` + `AutoScroll` 的容器，
固定高度的按钮/开关用 `Dock=Bottom` 或 `Dock=Top` 钉住。
（「数据与隐私」面板在 1.2 就是这么改的 —— 改之前它是固定高度 214，文案一加长就会压住下面的开关。）

另外 `AutoScroll` 和 `Anchor = Right` **不能**同时用：容器每布局一次控件就变宽一次
（实测从 1361 涨到 2532），右边会跑出画面。要么只锚左上、手动算宽度，要么别用 AutoScroll。
