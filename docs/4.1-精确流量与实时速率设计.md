# 4.1 精确流量统计与实时速率设计

> 状态：已批准并实现（2026-10-28）。
> 范围：A1 按包精确流量（TCP + UDP）+ A2 实时速率与 5 分钟曲线 + Npcap 变为安装前置。
> **不做**：抓包导出、载荷解析、DPI/SNI、UDP 扫描检测、每程序独立曲线。

## 1. 目标与边界

- 流量页只有一个数据源：**Npcap**。ETW 不再提供任何流量数字，只为 IDS 保留 flow 回调。
- 字节口径：**IP 载荷**（TCP/UDP 头 + 数据），不含以太网/IP 头；与 iperf3 报告值可对齐。
- 含重传、含被本程序 WFP 拒绝的入站包（包确实到了网卡）；**不含回环**。
- 只存内存，服务重启或「清空」后归零；不落盘、不外传。

## 2. 数据流

```
Npcap (NDIS)
  │ BPF: tcp or udp，snaplen 192（只读头）
  ▼
NpcapTrafficCapture（Core，独立会话）
  · 每网卡一线程；2 秒去重（多网卡/虚拟交换机）
  · 解析 IPv4/IPv6 + VLAN + 扩展头；分片非首片单独计数
  · pps / pcap 丢包统计；>20 万 pps 自动 1/N 采样（默认关闭）
  ▼
TrafficAggregator（Core，纯内存）
  · 端点表快照（1 秒）→ PID → 程序路径
  · pending 2 秒重试；3 秒仍未知 → 「未归属」
  · 每程序：TCP/UDP × 入站/出站 × 字节/包数
  · 1 秒桶 + 5 分钟环形缓冲；速率 = 3 秒滑动平均
  ▼
TrafficCaptureHost（Svc）
  ▼
query.traffic（原有命令，语义切到 Npcap）
  ▼
流量页：状态行 + 曲线 + 每程序表格 + 协议明细 + 暂停/清空
```

## 3. 关键取舍

| 问题 | 决定 |
|---|---|
| 与反扫描的关系 | 独立第二份 Npcap 会话；不改 4.0 采集类（性能专项再合并） |
| 进程归属 | 出站 → 发送进程；入站 → 监听进程；查不到归「未归属」 |
| 回环 | 不计（避免客户端/服务端重复） |
| IP 分片 | 首片归属流；其余计入「未归属」 |
| 采样 | 默认关闭；仅 >20 万 pps 兜底，页面标「采样估算」 |
| 丢包 | `pcap_stats` 有值就显示；>0 标注「数据可能不完整」 |
| 暂停 | 会话级按钮，停止采集但保留已累计数字；不持久化 |
| ETW | 仅保留给 IDS；`TrafficHost` 不再累加字节 |

## 4. 协议与数据

`query.traffic` 返回追加：

- `TrafficDto`：`TcpBytesIn/Out`、`UdpBytesIn/Out`、`PacketsIn/Out`、`RateIn/Out`、`Sampled`、`Source="npcap"`。
- `TrafficSeriesDto`：`StartUtc`、`IntervalMs=1000`、`BytesIn[]`、`BytesOut[]`（≤300 点）、`Sampled`。
- `TrafficStatusDto`：`Collecting`、`Paused`、`Pps`、`Dropped`、`Sampled`、`NpcapVersion`、`LastError`。
- `ServiceStatus`：`TrafficPps`、`TrafficDropped`、`TrafficSampled`。

新增命令：`write.traffic.configure`（`Request.TrafficPaused`）。
`write.traffic.clear` 语义扩展为「清空程序计数 + 曲线」。

## 5. 安装器：Npcap 变为必需组件

顺序（用户批准）：

1. 预检（系统版本、管理员、是否已安装）；
2. 说明「4.1 起 Npcap 为必需组件」，Y/N；**N → exit 8，零系统改动**；
3. 已装 Npcap → 跳过；
4. 官方 GUI（锁定四参数）→ 0 继续 / 3010 继续并提示重启 / 1 → exit 8 / 其它 → exit 9；
5. 校验 `wpcap.dll` 存在，否则 exit 9；
6. 复制文件 / 服务 / 快捷方式 / 受保护模式密钥；
7. 启动服务 + `NpcapProbe` 只读探测网卡；**打不开只警告，exit 0**；
8. 完成。

- 修复/升级同样先做 Npcap 前置（避免“拒绝安装却把服务停了”）；
- 卸载、`--start-service`、`--recover` **永不检查 Npcap**；卸载不卸载 Npcap；
- `--without-npcap` 只保留给自动化/特殊环境（文档化，交互流程不显示）；
- 安装/修复时把 `npcap-1.90.exe` 复制到安装目录，供状态栏「点击安装」复用；
- 退出码 8 / 9 已登记在 `--help`。

## 6. 界面

流量页重写：

- 顶部说明：「精确统计（Npcap）：按网卡上真实出现的字节计数，含重传与被拒绝的入站包，不含回环。」
- 工具条：搜索、刷新、暂停/继续、清空、**每 3 秒自动刷新**（默认开启；取消后不再自动刷新）。
- 状态行：采集状态、Npcap 版本、pps、丢包、采样、统计起点、程序数、合计、选中行 TCP/UDP 明细。
- 曲线：5 分钟、每秒一点、入站/出站两条线，自绘（无第三方库）。
- 表格：程序 / 路径 / 入站 / 出站 / 下行 / 上行 / 总计 / 最后活动 / 备注。
- Npcap 不可用或驱动异常时，页面明确显示原因，不假装有数据。

## 7. 测试

### 离线自检

- `--traffic-capture-test`：方向/协议分列、归属、pending 重试、超时未归属、速率平滑、环形缓冲、清空、DTO 往返。
- `--traffic-records-test`：新列、暂停按钮、曲线控件、未归属行、pps/丢包/采样标注、980 宽布局。
- `--ui-language-test` / `--ui-dpi-test`：中英文与 150% 不截断。

### VM

- `--service-traffic-precise-test`：采集在跑、暂停/继续、曲线增长、清空。
- `--service-35-test`：DNS 仍可捕获；**回环不计**。
- 手工：iperf3 TCP/UDP 精度、1000 次短连接、3000 次 DNS、Hyper-V/VPN、24h soak。
- 安装器：拒绝/取消/失败/已装/3010/驱动异常 六条路径 + 零残留检查。

## 8. 已知限制

- 反扫描与流量各开一份 Npcap 会话，每包多一次内核到用户态拷贝（性能专项再合并）；
- IP 分片的后续分片只能计入「未归属」；
- 极短命进程可能归不到 PID（界面可见「未归属」，比例需 VM 量化）；
- 多网卡/虚拟交换机依赖 2 秒去重，重复率需 VM 实测；
- 被 WFP 拒绝的入站包仍计入（文档已写明）。
