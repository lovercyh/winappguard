# 3.6 流量记录设计

> 状态：已实现，待 VM 验收（2026-10-26）。
> 范围：新增「流量」页，按程序汇总**服务本次运行以来**的上传/下载/总计，可按时间或流量排序。
> **不做**：跨服务重启的历史落盘、定时规则、flow IDS（留给 3.7）、抓包 / URL / DPI / HTTPS 解密、内核驱动。

## 1. 目标与非目标

### 1.1 目标

1. 一眼看到「本次服务运行以来，哪个程序用得最多」；
2. 可以按总流量、上传、下载、最后活动时间、程序名排序；
3. 程序退出后记录仍保留，直到服务重启或手动清空；
4. 保留 3.5 的连接页流量列，新页面负责按程序聚合。

### 1.2 非目标

- 不做跨服务重启/重启电脑的历史（3.7 或更后）；
- 不做定时规则；
- 不做流量限额/限速；
- 不把近似值写成精确账单。

## 2. 数据来源

直接使用 3.5 已有的 `query.traffic` 快照：

```text
TrafficDto { Key, Path, Name, IsPathKnown, Pids, BytesIn, BytesOut, LastSeenUtc }
```

- 服务端 ETW `Microsoft-Windows-Kernel-Network` 持续累计；
- 按程序路径聚合；拿不到路径时按 `pid:<pid>` 兜底；
- 本次服务运行内累计，服务重启归零；
- 服务端不需要新增采集逻辑。

### 2.1 新增元数据

`ServiceResponse` 增加：

```text
DateTime? TrafficStartedUtc
```

- `query.traffic` 返回；
- `write.traffic.clear` 也返回，界面清空后直接显示新的统计起点。

## 3. 协议

协议仍是 v2，只新增一个写命令：

| 命令 | 类型 | 说明 |
|---|---|---|
| `query.traffic` | 读 | 已有；新增返回 `trafficStartedUtc` |
| `write.traffic.clear` | 写 | 清空计数，重置统计起点；需要提权 |

旧客户端不会调用新命令；新界面遇到旧服务（没有 `trafficStartedUtc`、清空返回不支持）时：

- 起点显示「未知」；
- 清空按钮保留，但失败时按普通服务错误提示，不假装成功。

## 4. 服务端

### 4.1 TrafficHost

- `StartedUtc`：服务启动时设置；`Clear()` 时重置为当前时间。
- `Clear()`：清空按程序的累计值，返回清掉的程序数，记录 `WAG-TRAFFIC-007`。
- `Snapshot()` 行为不变（已按总量降序返回，界面会再排序）。

### 4.2 ControlServer

- `query.traffic` 的响应补 `TrafficStartedUtc`；
- `write.traffic.clear` 走提权检查（`write.` 前缀），清空后返回 `Affected` 和新的 `TrafficStartedUtc`。

## 5. 界面

### 5.1 入口

新增页签「流量」/「Traffic」，放在「联网连接」之后：

```text
联网连接 | 流量 | 黑名单 | 严格模式下白名单 | 记录 | DNS | 设置
```

### 5.2 布局

- 顶部两行（约 72px）：
  - 第一行：搜索框（程序 / 路径）、刷新、清空…；
  - 第二行：统计起点 / 程序数 / 合计。
- 表格占满剩余区域：

| 列 | 内容 | 排序 |
|---|---|---|
| 程序 | 程序名 | 按名称 |
| 路径 | 完整路径；拿不到显示「（无法获取）」 | 按路径 |
| 上传 | 本次运行上传字节 | 按数值 |
| 下载 | 本次运行下载字节 | 按数值 |
| 总计 | 上传 + 下载 | 按数值（默认） |
| 最后活动 | 最后一次统计到流量的本地时间 | 按时间 |
| 备注 | 路径未知时显示「路径未知」 | 不排序 |

- 默认按总计降序；
- 点表头切换升/降序，显示排序箭头；
- 搜索过滤程序名 / 路径；
- 页面可见时每 3 秒自动刷新；手动刷新立即拉取；
- 数据没变化时不重绑表格，避免打断选中/滚动。

### 5.3 顶部说明

```text
统计自 2026-10-26 17:40:12（服务本次运行） · 共 12 个程序 · 合计 上传 1.2 GB / 下载 3.4 GB
```

- 有搜索时追加「显示 3 / 共 12 个程序」；
- 明确写「服务重启或清空后从 0 开始」。

### 5.4 清空

- 「清空…」按钮 → 确认框：
  - 将要做的：把所有程序的上传/下载计数归零；
  - 影响：只影响流量记录；规则、白名单、锁网都不变；
  - 提示：服务重启后本来也会归零；
- 确认后调用 `write.traffic.clear`（普通权限会弹一次 UAC）；
- 成功后清空表格、更新统计起点，并弹托盘提示。

### 5.5 空状态与边界

- 空状态：还没有流量记录，服务本次运行以来还没有统计到任何程序的流量；
- 路径未知：程序名显示 `PID 1234`，路径显示「（无法获取）」，备注「路径未知」；
- 流量是 ETW 近似值，短连接可能漏计；悬停提示写明；
- 程序退出后记录保留；同名路径的多个实例合并为一行。

## 6. 测试

### 6.1 离线

- 行排序：总计 / 上传 / 下载 / 最后活动 / 程序名，升降序；
- 搜索：程序名、路径、大小写；
- 格式化：0 B / 1023 B / 1 KB / 1.5 MB；
- 未知路径行：`PID n` + 「无法获取」+「路径未知」；
- 表头合计 / 显示数 / 统计起点；
- 英文界面：页签、列头、按钮、提示、空状态、清空确认框；
- 100% / 150% DPI 不截断。

### 6.2 VM

- 开两个程序下载，确认按程序聚合、总量排序正确；
- 按最后活动时间排序，确认顺序变化；
- 程序退出后记录仍在；
- 点「清空」，确认 UAC、计数归零、统计起点更新；
- 重启服务，确认从 0 开始、起点更新；
- 旧服务（3.5）场景：起点显示未知，清空失败有明确提示（可选）；
- 3.5 的流量 / DNS / 锁网回归。

## 8. 风险

| 风险 | 处理 |
|---|---|
| 每次 3 秒重绑打断选中 | 数据签名不变就不重绑 |
| 清空被误点 | 确认框 + UAC + 托盘提示 |
| 旧服务没有新字段 | 起点显示未知；清空失败明确报错 |
| 路径未知行看起来像错误 | 备注写「路径未知」，不隐藏 |
| 页面数字与连接页重复 | 连接页按连接，新页按程序；文案写清 |
