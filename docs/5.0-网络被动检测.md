# 5.0 反网络攻击（网络被动检测）

## 定位

5.0 在纯防火墙之外增加**被动网络检测**：

- Suricata 使用 Npcap 抓包，加载 ET Open 规则；Npcap 安装时必须启用 **WinPcap API-compatible Mode**（Suricata 直接加载 `wpcap.dll`）。
- WinAppGuard 只读取 Suricata 的 `eve.json`，产生告警；
- 命中规则**不会自动拦截**；
- 用户在告警详情里手动选择拦截范围，WFP 动态过滤器执行；
- 默认 10 分钟，可选 30/60 分钟，服务重启自动清空。

不是 inline IPS，不保证拦截第一个包；HTTPS 正文不可见，只做 SNI/证书/元数据。

## 组件

```text
Suricata 8.0.7（随包，外部子进程）
  → eve.json
EveAlertReader（服务）
  → 解析 alert + 五元组反查 PID
NetworkDetectionHost（服务）
  → 去重/冷却/存储/状态
「网络检测」页（界面）
  → 用户手动选择拦截
NetworkBlockHost（服务）
  → WFP 出站传输层动态过滤器
```

## 规则

- 随包 ET Open Suricata 7.0.3 规则快照；
- 标准档：12,528 条（Critical/Major + Client_Endpoint + Windows/未标注平台）；
- 全量档：52,840 条（已移除 9 条 Suricata 8 不支持的 `file.magic` 规则）；
- 手动导入规则包，不自动更新。

## 手动拦截范围

| 范围 | WFP 条件 | 影响 |
|---|---|---|
| `connection` | 本机/远端 IP+端口+协议 | 只影响当前五元组 |
| `ip-port` | 远端 IP+端口+协议 | 所有程序访问该服务 |
| `ip` | 远端地址 | 所有程序访问该 IP |

最多 200 条；拒绝 loopback/组播/未指定地址；`ip-port` 为默认。

## 边界

- 被动检测看到包时，连接可能已建立；触发请求可能已经发出。
- TCP 连接可能因丢包超时，而不是收到 RST。
- 五元组反查不到 PID 时显示未知进程，不影响告警。
- ET Open 规则可能误报；默认标准档、冷却、抑制和手动拦截降低影响。
- 不新增内核驱动；Suricata 使用已有的 Npcap。

## 验收

1. `WinAppGuard.sln` 0 警告 0 错误。
2. `SelfCheck --network-detect-test` 全部通过。
3. 安装后 `suricata.exe` 可启动，规则数正确，`eve.json` 生成。
4. 测试 HTTP/DNS/TLS 流量能产生告警。
5. 告警不自动创建 WFP 过滤器。
6. 用户点击拦截后过滤器创建，TTL 到期删除，可手动解除。
7. 服务重启后动态拦截清空，告警保留。
8. 英文界面新页面无中文残留。
