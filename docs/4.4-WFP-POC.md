# 4.4 WFP 阻断 POC（RA / DHCPv6）

> 目标：验证 Windows 主机侧 WFP 能否在 IPv6 栈处理前拦住非信任 RA / DHCPv6。
> 只改本工具的 WFP 子层，不碰 Windows 防火墙；过滤器到时自动删除，也可手动 clean。
>
> **结论（2026-10-31）**
> - DHCPv6：**通过** —— `transport` 层，过滤器期间拿不到 `fd00:6:6::110`，
>   POC 结束后立即恢复；产品已接入「临时阻断此 DHCPv6（10 分钟）」。
> - RA：**通过** —— `transport` 层，控制组能在 Windows 装上 `fd00:7:7::/64`
>   和 rogue 默认路由；加过滤器后同样的 RA 不再生效。
>   产品已接入「临时阻断此 RA（10 分钟）」。
> - ALE 层：**失败** —— 流缓存绕过，过滤器在也照样拿到地址。

## 1. 准备

- Windows 验收机（`192.168.10.32`）已装 4.4；`dist-tools` 里有 `WinAppGuard.SelfCheck.exe`。
- Kali（`192.168.10.31`）和 Windows 在同一个 IPv6 实验网。
- 先确认 Kali 的链路本地地址：

```bash
ip -6 addr show dev eth0 scope link
# 例：inet6 fe80::a00:27ff:fe12:3456/64 scope link
```

把这个 `fe80::...` 记作 `<KALI-LL>`，下面命令用它。

> 如果 RA 的源地址不是这个地址，过滤器匹配不到；以 `thc-ipv6` 实际发出的源为准。

## 1.5 三个可选的 WFP 层（重要）

POC 支持 `--layer`，不给时默认 **transport**：

| 层 | 参数 | 判定方式 | 备注 |
|---|---|---|---|
| ALE 入站授权 | `--layer ale` | 每条流授权一次 | 默认层，**对 DHCPv6 会被流缓存绕过**（实测） |
| 入站传输 | `--layer transport` | 逐包 | 默认层，RA/DHCPv6 都建议先测这个 |
| 数据报 | `--layer datagram` | 逐包，更靠近套接字 | transport 不生效时的备选 |
| 三层都挂 | `--layer all` | — | 一次确认“有层能拦”，再逐层缩到最小 |

> 2026-10-31 实测：`--layer ale`（旧默认）下，60 秒过滤器保持期间
> `ipconfig /release6 && /renew6` 仍拿到 `fd00:6:6::110` 和 DNS `fd00:6:6::53`。
> 原因：ALE 的入站授权对同一五元组只做一次，DHCPv6 客户端套接字长期存在，
> 过滤器加上后仍命中之前的放行缓存。所以 POC 默认改挂传输层，逐包判定。
> ICMP type 条件只在 ALE 层可用；传输层/数据报层的 RA 过滤器只能按
> “该地址的全部 ICMPv6”拦。

## 2. RA 阻断 POC

### Windows（管理员 PowerShell）

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
.\WinAppGuard.SelfCheck.exe --ipv6-wfp-poc ra <KALI-LL> 120 --layer transport
```

- 会弹一次 UAC；
- 看到 `已添加 RA 阻断：...（该地址的全部 ICMPv6（transport 层不支持 ICMP type））`
  表示过滤器加上了；`--layer ale` 时才是 `ICMPv6 type 134`；
- 命令会保持 120 秒，期间不要关窗口。

### Kali

用 Scapy 发 RA（`fake_router6` 不一定装了）：

```python
# /tmp/ra.py 摘要：完整脚本见 reply，关键是这三行
IPv6(src="fe80::ea23:d752:baa:a6ab", dst="ff02::1", hlim=255)
ICMPv6ND_RA(chlim=64, M=1, routerlifetime=1800)
ICMPv6NDOptPrefixInfo(prefix="fd00:7:7::", prefixlen=64, L=1, A=1, ...)
```

注意：

- IPv6 的 `hlim` **必须是 255**，否则 Windows 直接丢弃；
- 源地址必须是 Kali eth0 的链路本地地址；
- 前缀用一个新的 `fd00:7:7::/64`，避免和已有的 on-link 路由混淆；
- `fd00:7:7::/64` 的 SLAAC 地址形如 `fd00:7:7:0:...`，
  PowerShell 过滤要用 `-like 'fd00:7:7:*'`（**不是** `fd00:7:7::*`）。

### 控制组（必须先做）

不加过滤器，先证明这个 RA 会被 Windows 接受：

```powershell
Get-NetIPAddress -AddressFamily IPv6 | ? { $_.IPAddress -like 'fd00:7:7:*' }
Get-NetRoute -AddressFamily IPv6 -DestinationPrefix 'fd00:7:7::/64'
Get-NetRoute -AddressFamily IPv6 -DestinationPrefix ::/0 | ft -auto
```

应出现 `fd00:7:7:*`（`PrefixOrigin = RouterAdvertisement`）和
`fd00:7:7::/64` 路由，`::/0` 的 NextHop 多出 Kali 的链路本地地址。

清理控制组留下的东西（否则阻断期间分不清新旧）：

```powershell
Get-NetIPAddress -AddressFamily IPv6 |
    ? { $_.IPAddress -like 'fd00:7:7:*' } |
    Remove-NetIPAddress -Confirm:$false
Remove-NetRoute -DestinationPrefix 'fd00:7:7::/64' -Confirm:$false -ErrorAction SilentlyContinue
Remove-NetRoute -DestinationPrefix ::/0 -NextHop <KALI-LL> -Confirm:$false -ErrorAction SilentlyContinue
```

### 加过滤器后再测

- 过滤器期间：`fd00:7:7:*` 地址和 `fd00:7:7::/64` 路由都不应出现；
- 注意过滤器拦的是该地址的**全部 ICMPv6**（传输层没有 ICMP type 条件）；
- 已经装上的 rogue 路由/地址不会被自动删除，需要按上面的命令清理。

**通过**：过滤器期间看不到 rogue 前缀/地址，默认路由不变。
**失败**：仍然出现 → 该 WFP 层拦不住 RA，产品保持只告警。

## 3. DHCPv6 阻断 POC

> 顺序很重要：**先做「控制组」**，确认 rogue DHCPv6 能被 Windows 接受；
> 再做「加过滤器后再测」。否则“拿不到地址”可能只是 dnsmasq 没工作。

### 加过滤器（控制组通过后再做）

```powershell
.\WinAppGuard.SelfCheck.exe --ipv6-wfp-poc dhcp <KALI-LL> 120 --layer transport
```

看到 `已添加 DHCPv6 阻断：...（UDP 547->546（transport 层））` 或
`（... transport 层，本地端口条件不可用）` 表示过滤器加上了。

### Kali

```bash
sudo ip -6 addr add fd00:6:6::1/64 dev eth0
sudo dnsmasq --no-daemon --port=0 \
  --dhcp-range=fd00:6:6::100,fd00:6:6::200,64 \
  --dhcp-option=option6:dns-server,[fd00:6:6::53]
```

> 为了让 Windows 接受 `fd00:6:6::/64` 的 DHCPv6 地址，合法路由器的 RA 需要把
> `fd00:6:6::/64` 作为 **on-link** 前缀播出来（`AdvAutonomous off`，`AdvManagedFlag on`）。
> 如果只播 `fd00:4:4::/64`，控制组可能拿不到 `fd00:6:6::` 地址。

### Windows 观察

```powershell
Get-NetIPAddress -AddressFamily IPv6 |
    Where-Object { $_.IPAddress -like 'fd00:6:6::*' }

Get-DnsClientServerAddress -AddressFamily IPv6
```

**通过**：Windows 没有拿到 `fd00:6:6::` 地址，DNS 没有被 rogue 改掉。
**失败**：仍然拿到地址/DNS → WFP 对 DHCPv6 也无效，产品保持只告警。

### 控制组（必须先做，避免假通过）

不加任何过滤器，先证明 rogue DHCPv6 真的能被 Windows 接受：

1. Kali 起 dnsmasq（上面的命令）；
2. Windows 管理员 PowerShell：

```powershell
ipconfig /release6
ipconfig /renew6
Get-NetIPAddress -AddressFamily IPv6 |
    Where-Object { $_.IPAddress -like 'fd00:6:6::*' }
Get-DnsClientServerAddress -AddressFamily IPv6
```

如果控制组都拿不到 `fd00:6:6::` / rogue DNS，说明 Windows 没在发 DHCPv6，先排查：

```powershell
Get-NetIPv6Protocol
Get-NetIPInterface -AddressFamily IPv6 |
    Select-Object InterfaceAlias, Dhcp, RouterDiscovery
```

- `Dhcp` 必须是 `Enabled`；
- `RouterDiscovery` 必须是 `Enabled`；
- 路由器 RA 的 M 标志要为 1，或者手动：

```powershell
Set-NetIPInterface -InterfaceAlias "以太网" -AddressFamily IPv6 -Dhcp Enabled
ipconfig /release6
ipconfig /renew6
```

Kali 上抓包确认 Windows 发了 SOLICIT：

```bash
sudo tcpdump -i eth0 -n -vv udp port 546 or 547
```

看到 `fe80::... > ff02::1:2` 的 546→547 才算正常。

### 加过滤器后再测

控制组通过后：

1. Windows 管理员 PowerShell 运行：

```powershell
.\WinAppGuard.SelfCheck.exe --ipv6-wfp-poc dhcp <KALI-LL> 120 --layer transport --no-pause
```

2. Windows 另一个管理员 PowerShell：

```powershell
ipconfig /release6
ipconfig /renew6
Get-NetIPAddress -AddressFamily IPv6 |
    Where-Object { $_.IPAddress -like 'fd00:6:6::*' }
Get-DnsClientServerAddress -AddressFamily IPv6
```

**通过**：过滤器生效期间拿不到 `fd00:6:6::` / rogue DNS。  
3. POC 结束后（或 `clean`），再 `ipconfig /renew6`，应能重新拿到 rogue 地址/DNS——证明过滤器确实在起作用，而不是 dnsmasq 本身没响应。

## 4. 清理

```powershell
.\WinAppGuard.SelfCheck.exe --ipv6-wfp-poc clean
```

POC 命令正常结束也会自动删除；如果进程被强杀，用上面的 clean 清掉。

## 5. 记录结论

| 项目 | 结果 |
|---|---|
| RA 过滤器添加 | 成功 / 失败（错误码） |
| RA 实际拦截（transport 层） | 通过 / 失败 |
| DHCPv6 过滤器添加 | 成功 / 失败（错误码） |
| DHCPv6 实际拦截（transport 层） | 通过 / 失败 |
| DHCPv6 实际拦截（ale 层） | **失败**（2026-10-31，流缓存绕过） |
| 合法路由器/合法 DHCPv6 是否仍工作 | 是 / 否 |

- 两个都通过 → 4.4.x 加“临时阻断此 RA / DHCPv6（10 分钟）”；
- 只有 DHCPv6 通过 → 只加 DHCPv6 阻断；
- 都失败 → 保持只告警，NDP 永不阻断；
- 任何情况下都不要做成永久封禁。
