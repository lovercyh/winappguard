# 5.12：性能与热路径

> 版本：5.12.0  
> 协议：v4（不升版本）  
> 定位：降低固定开销，补齐升级与 IPC 回归；不加检测特性。

## 1. 改了什么

| 项 | 5.11.1 | 5.12.0 |
|---|---|---|
| 篡改巡检 | 全局锁内读磁盘 + 开 WFP + 枚举 | 锁外枚举/diff；内存权威快照；重建前校验 revision |
| 规则导入 | 每条规则一次 `OpenEngine` + `EnsureSublayer` | 整个导入复用一个引擎；导入后对账并记录耗时 |
| `status` | 每次打开 WFP、枚举规则 | 规则计数走快照缓存；子层/模块详情缓存 1 秒 |
| 后台刷新 | `[ThreadStatic]`，换线程重新握手 | 独立共享后台会话 + 超时/退避 |
| JSON | 包含 null 字段 | 线上省略 null；签名规范字节保持 5.11.1 形状 |
| 慢操作 | 无记录 | >200 ms 的 IPC/页面刷新、巡检/导入/status 写日志 |

## 2. 关键约束

- **协议保持 v4**：A1/A3/H3/H5 不在 5.12 范围。
- **签名兼容**：`ProtocolSigning.CanonicalBytes` 使用 `CanonicalJsonOptions`（不省略 null），
  线格式使用 `JsonOptions`（省略 null）。5.12 客户端与 5.11.1 服务端的签名仍然一致。
- **巡检不误删**：读取实际 WFP 前记录 `RuleRevision`；进锁后若 revision 变化，本轮放弃，下一轮重试。
- **写命令快照一致**：写命令开始前清空缓存，`SaveSnapshotNow` 强制从 WFP 重读后再落盘。
- **缓存失效**：规则写入/导入/巡检重建/到期清理都会更新权威快照。

## 4. 性能场景

```text
S1 status × N
S2 rules.list × N
S3 query.traffic × N
S4 query.ids × N
S5 10 会话 × 100 请求
S8 空载 10 秒（服务 CPU/工作集）
```

运行：

```powershell
dotnet run --project tools/SelfCheck/SelfCheck.csproj -c Release -- `
  --perf --perf-iterations 300 --perf-threads 10 --perf-requests 100 `
  --perf-out perf-result.json
```

S6（2000 条导入）和 S7（巡检期间并发 rules.list）需要在 VM 上单独准备数据和触发条件，
见 `docs/5.12-VM验收.md`。

## 5. 已知边界

- 性能数字依赖 VM 的 CPU/磁盘/Npcap/Suricata；只做相对比较。
- 巡检重建仍然逐条调用 `RuleEngine`（低频路径），没有改成批处理；H2 只覆盖导入。
- `QueryView` 仍是单一响应类；按域拆分留到 5.13。
- `sinceRevision` 增量刷新留到 5.13。
