# 4.4 VM 验收说明（IPv6 邻接安全）

> 4.4 = RA / DHCPv6 / NDP 的主机侧检测；默认只告警，NDP 不阻断。
> 当前生产网络没有 IPv6，因此**必须搭一个 IPv6 实验网**才能验收检测规则。
> 只在隔离网络/快照里做；RA 投毒可能改掉 Windows 的 IPv6 默认路由。

## 1. 实验网拓扑

| 角色 | 示例 IP | 说明 |
|---|---|---|
| Windows 验收机 | `192.168.10.32` | 装 4.4 + Npcap |
| Kali 攻击机 | `192.168.10.31` | thc-ipv6 / dnsmasq / Scapy |
| IPv6 路由器 VM | `192.168.10.1` | Linux + radvd，播 `fd00:4:4::/64` |

- 三台 VM 放同一个 Host-Only / 桥接二层网络；
- 路由器 VM 可以是轻量 Linux（512MB 即可）；没有第三台 VM 时，可让 Kali 临时兼做路由器
  （先 radvd，再停掉换 rogue；见第 3 节）；
- Windows 需要启用 IPv6：`Get-NetIPv6Protocol` 应为 `Enabled`；
- 验收前记录：

```powershell
Get-NetIPAddress -AddressFamily IPv6
Get-NetRoute -AddressFamily IPv6
Get-NetNeighbor -AddressFamily IPv6
```

## 2. 路由器 VM（radvd）

```bash
sudo ip addr add fd00:4:4::1/64 dev eth0
sudo sysctl -w net.ipv6.conf.all.forwarding=1

sudo apt install -y radvd
sudo tee /etc/radvd.conf >/dev/null <<'EOF'
interface eth0 {
    AdvSendAdvert on;
    MinRtrAdvInterval 3;
    MaxRtrAdvInterval 10;
    AdvManagedFlag on;
    AdvOtherConfigFlag on;
    prefix fd00:4:4::/64 {
        AdvOnLink on;
        AdvAutonomous on;
        AdvValidLifetime 2592000;
        AdvPreferredLifetime 604800;
    };
    RDNSS fd00:4:4::53 { AdvRDNSSLifetime 300; };
};
EOF

sudo systemctl restart radvd
```

Windows 侧应看到：

```powershell
Get-NetIPAddress -AddressFamily IPv6 | Where-Object { $_.IPAddress -like 'fd00:4:4::*' }
Get-NetRoute -AddressFamily IPv6 | Where-Object { $_.DestinationPrefix -eq '::/0' }
```

看到 `fd00:4:4::...` 和默认路由后，等「局域网 → IPv6 邻接」基线学习完成
（5 分钟，或路由器 + DHCPv6 + 前缀同时出现）。

## 3. Kali 工具

```bash
sudo apt update
sudo apt install -y thc-ipv6 dnsmasq radvd python3-scapy net-tools
ip -br link
ip route
ping -c 2 192.168.10.32
```

- `thc-ipv6`：`fake_router6` / `fake_advertise6` / `parasite6` / `redir6`；
- `dnsmasq`：DHCPv6 服务器；
- `radvd`：需要时让 Kali 临时当合法路由器；
- `python3-scapy`：构造特殊 NA/NS/DHCPv6。

> 没有第三台路由器 VM 时：先在 Kali 上跑 radvd 让 Windows 拿到 IPv6，
> 等基线完成；然后停 radvd，再跑 `fake_router6` / `dnsmasq` 当 rogue。
> “非基线路由器”场景最好用第二个 link-local/MAC（macvlan 或第二网卡）。

## 4. 手工用例

### A. RA

| 用例 | 命令（示例） | 预期 |
|---|---|---|
| 非基线路由器 | `sudo fake_router6 eth0 fd00:6:6::/64` | `ipv6_ra_unexpected_router` 高危 |
| 多个路由器 | 同时保留合法 radvd + rogue | `ipv6_ra_multiple_routers` 中危 |
| 前缀变化 | rogue 用不同前缀/长度 | `ipv6_ra_prefix_changed` 高危 |
| 标志/生命周期 | rogue 改 M/O 或 lifetime 100 | `ipv6_ra_flags_or_lifetime_changed` 中危 |
| RA 洪水 | 循环发送 25+ RA | `ipv6_ra_flood` 低危 |

### B. DHCPv6

用 dnsmasq 起 rogue DHCPv6：

```bash
sudo ip -6 addr add fd00:6:6::1/64 dev eth0
sudo dnsmasq --no-daemon --port=0 \
  --dhcp-range=fd00:6:6::100,fd00:6:6::200,64 \
  --dhcp-option=option6:dns-server,[fd00:6:6::53]
```

| 用例 | 预期 |
|---|---|
| 非基线 DHCPv6 服务器 | `ipv6_dhcpv6_unexpected_server` 高危 |
| 多个 DHCPv6 服务器 | `ipv6_dhcpv6_multiple_servers` 中危 |
| DNS/前缀/生命周期变化 | `ipv6_dhcpv6_option_mismatch` 中危 |
| 租期 30 秒 | `ipv6_dhcpv6_short_lease` 低危 |

### C. NDP

```bash
# 伪造 NA（按实际目标/参数调整）
sudo fake_advertise6 eth0 192.168.10.32 fd00:4:4::100
# NS/NA MITM
sudo parasite6 eth0
# Redirect
sudo redir6 eth0 192.168.10.32 fd00:4:4::1 fd00:6:6::1
```

或用 Scapy 构造：

```python
from scapy.all import *
sendp(Ether()/IPv6(src="fe80::66", dst="ff02::1")/
      ICMPv6ND_NA(tgt="fe80::1", R=1)/ICMPv6NDOptDstLLAddr(lladdr="de:ad:be:ef:00:66"),
      iface="eth0")
```

| 用例 | 预期 |
|---|---|
| 路由器 NA MAC 变化 | `ipv6_na_router_mac_changed` 高危 |
| 已知邻居 MAC 变化 | `ipv6_na_cache_mismatch` 中危 |
| 同一 MAC 多地址/频繁换 | `ipv6_na_mac_behavior` 中危 |
| 免费 NA 突发 | `ipv6_na_unsolicited_burst` 低危 |
| SLLA/TLLA 与源 MAC 不一致 | `ipv6_nd_sender_mismatch` 中危 |
| 非网关 Redirect | `ipv6_redirect_unexpected` 中危 |
| DAD 冲突 | `ipv6_dad_conflict` 中危 |

### D. 信任 / 清空 / 重置

- 选中路由器 → 「信任此路由器」→ 再发 rogue RA → 不再新增告警；
- 选中 DHCPv6 → 「信任此 DHCPv6」→ 再发 rogue ADVERTISE → 不再新增；
- DNS 页「清空」只删 `dns_*`；IPv6 页「清空」只删 `ipv6_*`；
- 「重置基线」重新学习 5 分钟，不影响 IPv4/DNS。
- 重启服务后事件、基线、信任仍在。

### E. 24h 误报

- 保留合法路由器 + DHCPv6，正常上网 24 小时，不跑攻击；
- 高危 / 中危 IPv6 事件应为 0；
- 低危（RA 洪水、免费 NA 突发、短租期）严格冷却；若出现，记录来源并判断。

### F. 界面

- 「局域网」页有 `IPv4（ARP / DHCP） / IPv6 邻接` 两个二级标签；
- IPv6 页有路由器 / DHCPv6 / 邻居 / 事件四张表；
- 托盘高危 IPv6 气泡能定位到 IPv6 页；
- 中英文、100% / 150% DPI 不截断。

## 5. WFP 阻断 POC（未完成前不提供按钮）

4.4 默认只告警。阻断需要先在 VM 做 POC：

### DHCPv6

- 层：`ALE_AUTH_RECV_ACCEPT_V6`，备选 `INBOUND_TRANSPORT_V6`；
- 条件：UDP、本地 546、远端 547、远端地址 = 非信任服务器；
- 成功：Windows 不再接受 rogue ADVERTISE/REPLY，合法服务器仍工作。

### RA

- 层：`INBOUND_TRANSPORT_V6` / `ALE_AUTH_RECV_ACCEPT_V6`；
- 条件：ICMPv6 type 134、远端地址 = 非信任路由器；
- 如果拦不住，尝试 L2 `INBOUND_MAC_FRAME_NATIVE`（按源 MAC，范围更宽）；
- 成功：Windows 不再安装 rogue 前缀/默认路由，合法 RA 仍工作。

### 结论

- 两个 POC 都通过 → 4.4.x 提供“临时阻断此 RA / DHCPv6（10 分钟）”；
- 只有 MAC 层通过 → 提供“临时阻断此设备的 IPv6”，明确提示范围；
- 都不通过 → 只告警，文档记录结论；NDP 永不阻断。
