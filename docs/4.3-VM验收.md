# 4.3 VM 验收说明

> 4.3 = 本地 DNS 劫持 / 投毒检测 + 明文 DNS 绕过检测；只告警、不阻断。
> 事件与 4.2 共用 `lan/events-YYYYMMDD.jsonl`，用 `dns_` 前缀区分。

## 1. 准备

- 验收机：Windows 10/11，已安装 4.3 验收包与 Npcap 1.90。
- 攻击机：Kali Linux，与验收机在同一二层网络。
- 正常 DNS：验收机网卡配置的 DNS（通常是网关）。
- 记录基线：验收前先正常上网 5 分钟，确认「防护 → DNS 安全」基线已就绪。

## 2. 一键自动验收

管理员 PowerShell：

```powershell
cd <项目>\dist-tools
& .\4.3-验收脚本.ps1 -LogPath "$env:USERPROFILE\Desktop\wag-4.3-验收.txt"
```

脚本会重启服务、跑离线与服务端自检，但不修改规则 / 白名单 / 防火墙。
自动检查全部通过后，再做下面的手工项。

## 3. 手工验收

### A. DNS 投毒（dnsspoof）

Kali：

```bash
sudo dnsspoof -i eth0 -f hosts.txt
```

`hosts.txt` 示例（把 bank.example 指到攻击机）：

```text
192.168.1.66 bank.example
```

预期：

- 验收机解析 `bank.example` 后 5 秒内出现高危：应答来源异常 / 事务 ID 不匹配 / 应答域名不符。
- 详情能说明“查询发往配置服务器，应答却来自攻击者”。
- 「局域网」页可能先出现网关 MAC 变化；两条事件时间线能对上。
- 点「信任此 DNS 服务器」后不再重复；取消信任后恢复。

### B. DNS 投毒（ettercap）

```bash
sudo ettercap -T -q -i eth0 -M arp:remote /192.168.1.1// /192.168.1.100//
```

在 ettercap 内启用 `dns_spoof` 插件。预期与 A 相同。

### C. 明文 DNS 绕过

在第二台 VM 起 dnsmasq（或任意 DNS 服务），把验收机 DNS 手动改成该 IP：

- 解析任意域名 → 出现「明文 DNS 绕过」中危，目标为 rogue IP。
- 点「信任此 DNS 服务器」后不再报；取消信任后恢复。
- 该规则只告警，不影响正常上网。

### D. 误报与边界

- 正常浏览、视频、游戏、系统更新 24 小时，DNS 安全告警应为 0；
  TTL 低危若出现，需人工确认是否为合法 CDN。
- DoH/DoT 看不到内容，不告警；这是已知边界。
- 上游 DNS 自己返回假数据时，只有与同请求的其它应答冲突才会命中。

### E. 落盘 / 清空 / 保留期

- 重启服务后 DNS 事件仍在。
- 「DNS 安全 → 清空」只删 `dns_*`，ARP/DHCP 事件保留。
- 「局域网 → 清空」不影响 DNS 事件。
- 保留期跟随 4.2 设置（7/15/30 天）。

### F. 界面

- 防护页四个子标签：端口扫描 / 局域网 / DNS 安全 / IDS。
- 托盘高危 DNS 气泡点击定位到 DNS 安全子标签。
- 中英文、100% / 150% DPI 不截断。
- 「每 3 秒自动刷新」默认开；取消后表格不再变化。

## 4. 通过标准

1. Kali 投毒 5 秒内出高危，详情指出请求 / 应答来源。
2. 信任后不再重复，取消信任后恢复。
3. 明文 DNS 绕过命中，可信任。
4. 正常 24h 误报 0。
5. 事件重启后仍在；清空只删 DNS 事件；保留期与 4.2 一致。
6. 四个防护子标签、托盘深链、中英文、150% DPI 正常。
7. 3.4–4.2 回归全过，构建 0 警告 0 错误。
