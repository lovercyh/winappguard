- ETW 会话 `WinAppGuard-Dns` / `WinAppGuard-Net`；

### 2.2 已知边界（不是失败）

- 流量统计 **TCP + UDP**（ETW 网络事件），按数据操作累计；短于 2 秒采样周期的事件仍可能漏计；
- 流量数字是近似值，用于看「谁在用网」，不是精确账单；
- 「本次运行」指服务本次启动，重启服务归零；
- DoH/DoT 不经过系统 DNS 客户端，DNS 页**可能看不到**，这是预期；
- 命中 hosts 文件或已经缓存且不发事件的查询，也可能没有记录。

### 2.3 2026-10-26 实测记录

- **TCP 扩展统计不可用**：`GetPerTcpConnectionEStats` 在客户端连接上
  `DataBytesIn` 始终为 **371 B**，50 MB 下载不增长；发送方向正常（服务端上传 3.7 MB）。
  因此 3.5 改用 ETW `Microsoft-Windows-Kernel-Network`。
- **ETW 独立实测**：4 MiB 下载、**277** 个事件、本进程下载 **4,194,367 B**；
  回环另一端的 PowerShell 进程上传同样为 4,194,367 B（方向归属正确）。
- **服务端实测**：本进程下载增量 **4,194,367 B**；服务 CPU **0.1%（16 核）**；
  本次新增 **326** 个事件；DNS 探针同时得到 3008（SelfCheck）和 3018（svchost）。
- **临时锁网**：60 秒、放行 6 个程序，开启/提前关闭的状态标记都正确。
- 结论：ETW 路线可用；TCP 扩展统计只保留在 POC/诊断工具里，不进入产品。

## 3. 人工检查

1. 打开一个持续下载（浏览器下载大文件 / 视频）。

3. 同时看任务管理器「性能 → 以太网」的发送/接收速率，确认量级一致。

### 3.4 临时锁网

1. 设置页 →「临时锁网 30 分钟」→ 确认。
2. 用未加白名单的程序联网（应失败）。

4. 点「关闭严格模式」提前结束。
