# 3.4 WFP 对象 DACL 收紧设计

> 状态：已实现（2026-10-25），VM 验收待执行。
> 目标：把本工具在 WFP 里的**子层与过滤器**从「SYSTEM + Administrators」收紧为
> 「SYSTEM + 所有者」，并同步改造升级、卸载、恢复路径。
> **不做**：WFP 之外的权限模型、内核/PPL、代码签名、自动更新、多所有者。

## 1. 现状

3.1–3.3 创建 WFP 对象时使用：

```
D:(A;;0xF01FF;;;SY)(A;;0xF01FF;;;BA)
```

即 SYSTEM 和 **所有管理员** 都拥有完全控制（含 `DELETE` / `WRITE_DAC`）。

因此：

- 任何管理员账户都能直接删除本工具的子层/过滤器；
- 现有「篡改防护」每 10 秒比对一次并重建，只能事后补救；
- 恶意或误操作的管理员可以反复删除，形成事实上的绕过。

3.1 已经收紧了服务、管道、受保护模式目录，但 WFP 对象留到了 3.4。

## 2. 目标 DACL

```
D:(A;;0xF01FF;;;SY)(A;;0xF01FF;;;<所有者 SID>)
```

- `O:`：对象 Owner 设为**创建者**（服务 = SYSTEM，CLI/自检 = 当前所有者），不能留成 `BA`。Windows 会给 Owner 隐式 `WRITE_DAC`，Owner 是 BA 时管理员仍能改 ACL；
- `P`：**SE_DACL_PROTECTED**，拒绝父容器的继承 ACE。没有它，WFP 会把 `Administrators` 的继承 ACE 加回来（实测）；
- `SY`：服务以 SYSTEM 运行，必须能创建/删除/查询；
- 所有者 SID：安装时的提权账户，允许其执行 `--recover`、卸载清理；
- **不再授予 `BA`**（Builtin Administrators）。

`0xF01FF` 保持不变：WFP 特定权限位（打开、添加、枚举、订阅等）加标准权限
（DELETE / READ_CONTROL / WRITE_DAC / WRITE_OWNER）。

### 所有者 SID 的来源

服务运行身份是 SYSTEM，不能用 `WindowsIdentity.GetCurrent()`。
所有者 SID 从受保护模式配置读取：

```
%ProgramData%\WinAppGuard\protected-mode\config.json  →  OwnerSid
```

读取失败或为空时：

- **不收紧**，继续使用旧的 `SY + BA`，并记录 `WAG-WFP-007`；
- 不写迁移标记，等配置修好后下次启动再迁移。

这是有意的 fail-safe：配置损坏时，系统至少还可管理，不会出现“谁都删不掉”的死局。

## 3. 创建路径

WFP 对象**只在创建时**传入安全描述符：

- `FwpmSubLayerAdd0(..., securityDescriptor)`
- `FwpmFilterAdd0(..., securityDescriptor, ...)`

**禁止**创建后再调用 `Fwpm*SetSecurityInfoByKey0`。

原因：3.1 在 VM 上实测过，后置设置会把服务启动卡死（BFE 内部锁顺序问题）。
创建时附带 SD 是官方推荐路径，也避开了这个坑。

SD 构造失败时：

1. 先退回 `SY + BA`（仍有保护，不是默认 SD）；
2. 再失败才退回默认 SD，并记录 `WAG-WFP-004/005`。

## 4. 旧对象迁移

3.1–3.3 已经创建的对象仍是旧 DACL，必须迁移。

### 4.1 判定

标记文件：

```
%ProgramData%\WinAppGuard\wfp-dacl-owner-only
```

内容为 `v3:<所有者 SID>`。服务启动时：

- 文件存在且内容与 `v3:<当前所有者 SID>` 一致 → 已迁移，跳过；
- 文件缺失、内容不同（例如 `--reset-owner` 换了所有者，或从 3.4 早期构建升级）→ 执行迁移。

### 4.2 迁移步骤

由服务在启动阶段、创建管道之前执行：

1. 读取规则快照 `rules.json`（内存中保留，删对象前先读）；
2. 用 SYSTEM 权限删除本工具的全部过滤器；
3. 删除本工具的子层；
4. 按新 SD 重建子层；
5. 按快照逐条重建过滤器：

   - 已到期的规则跳过（与篡改防护一致）；
   - IP 规则 / 程序规则、允许 / 阻止、范围、分组全部按快照恢复；
   - 重建不计入「篡改防护重建次数」，不触发托盘提示。

6. 写标记文件（所有者 SID）；
7. 记录 `WAG-WFP-011`（删除数、重建数）。

### 4.3 失败处理

- 快照不存在但已有过滤器：记录 `WAG-WFP-014`，**拒绝迁移**（宁可不收紧，也不能删掉无从重建的规则）；
- 任一步抛异常：记录 `WAG-WFP-012`，**不写标记**；
- 已经删掉的过滤器由现有篡改防护在 15 秒内按快照补回（新 SD）；
- 下次服务启动会再次尝试迁移；
- 子层删除失败时，保留旧子层；过滤器仍会按新 SD 重建，下一轮再处理子层。

迁移期间规则会有毫秒级空档，这是可接受的；文档会写明。\n\n事件码：\n\n| 码 | 含义 |\n| --- | --- |\n| `WAG-WFP-006` | owner-only SD 构造失败，回退 SYSTEM + Administrators |\n| `WAG-WFP-007` | 所有者 SID 读不到，跳过收紧 |\n| `WAG-WFP-010` | 迁移被跳过（无所有者 SID） |\n| `WAG-WFP-011` | 迁移成功（删除 / 重建数量） |\n| `WAG-WFP-012` | 迁移失败，下次重试 |\n| `WAG-WFP-013` | 迁移失败后按快照补回规则也失败 |
| `WAG-WFP-014` | 没有权威快照且已有过滤器，拒绝迁移（避免丢规则） |

## 4.4 启动时的快照保护\n\n3.4 同时修了一个 3.0–3.3 的隐患：启动时不再用「实际过滤器」覆盖 `rules.json`。\n\n- 快照不存在才写；存在就保留；\n- 如果过滤器在服务停止期间被外部删除，篡改防护仍能按快照补回；\n- 迁移前先确保快照存在，迁移失败也不会把快照截断。\n\n## 5. 卸载 / 恢复路径

收紧后，**非所有者的管理员**不能再直接删除 WFP 对象。因此：

### 5.1 卸载器

在停止服务、删文件之前做预检：

1. 如果本工具还有 WFP 对象，且当前账户不是所有者 → **直接拒绝卸载**，
   退出码 `7`，提示「请用所有者账户运行卸载」；
2. 否则按原顺序：停服务 → 删服务 → 删除 WFP 对象 → 删数据/文件。

拒绝时不做任何修改，避免“服务删了、规则还在”的半卸载状态。

### 5.2 CLI `--recover`

同样预检：

- 有 WFP 对象且当前账户不是所有者 → 退出码 `2`，明确提示所有者限制；
- 没有 WFP 对象 → 照常清理 1.x 遗留项（不需要所有者）。

不新增 CLI 退出码，沿用 `2 = 执行失败`，避免破坏脚本契约。

### 5.3 所有者判定

统一用：

```csharp
config.OwnerSid == WindowsIdentity.GetCurrent().User.Value
```

配置缺失/损坏一律视为“不是所有者”，并给出「请先由所有者修复配置」的提示。

## 6. 威胁模型与边界

**能挡住：**

- 非所有者的管理员直接删除子层/过滤器；
- 普通管理员权限的清理工具误删；
- 误操作（返回 `ACCESS_DENIED`）。

**挡不住：**

- 拥有 `SeTakeOwnershipPrivilege` / `SeRestorePrivilege` 的管理员：
  可以先夺取所有权，再改 DACL；
- 内核级恶意程序、BYOVD、直接操作 BFE；
- 离线修改磁盘/注册表。

因此文档只能写「提高门槛、让篡改更困难」，不能写「管理员绝对删不掉」。

## 7. 测试

### 7.1 离线（开发机 / CI）

- `--wfp-dacl-sddl-test`：
  - 有所有者 SID 时，SDDL 包含 `SY` 和该 SID，不包含 `BA`；
  - 无所有者 SID 时，回退 `SY + BA`；
  - SYSTEM 作为所有者时不重复添加。

### 7.2 需要管理员 + 真实对象（VM）

- `--wfp-dacl-test`：
  - 读取子层与至少一条过滤器的安全描述符；
  - 断言 `SYSTEM` 与所有者 SID 有 `0xF01FF`；
  - 断言 `BA` 没有 `DELETE` / `WRITE_DAC`。
- 双账户：
  - 所有者：能删规则、能 `--recover`、能卸载；
  - 非所有者管理员：删除被拒绝，卸载被拒绝，服务仍正常防护。

### 7.3 回归

- `--wfp-rule-test` / `--wfp-test` / `--service-tamper-test`；
- 3.1 的 `--service-auth-test`、`--service-acl-test`；
- 服务启动时间不得明显变长（迁移只在首次/换所有者时执行）。

## 9. 回滚

如果迁移在 VM 上出现问题：

- 标记文件存在时不会重复迁移；
- 删除标记文件并重启服务即可重试；
- 代码回滚到 3.3 后，旧代码会用旧 SD 创建新对象，不会影响已有规则。
