# 5.11：协议 v4 与强类型载荷层

> 5.11 是协议层硬切换：v4 上线后不再回退 v3/v2。
> 5.10.1 只是界面/托盘文案版本；5.10.0 是协议 v3 的最终版。

## 1. 版本与握手

| 项目 | 值 |
| --- | --- |
| 产品版本 | `5.11.1`（hotfix） |
| 协议版本 | `4` |
| 管道名 | `WinAppGuard.Control.v4` |
| 握手 | `hello` → `challenge` → `auth` → `welcome` |
| 请求 | 每帧带 `seq`，服务端严格递增校验 |
| 签名 | `nonce || 原始帧字节`；不重新序列化 |
| 会话 | 线程级复用，服务端 30 秒空闲超时 |

`hello.V` 必须等于 4。版本不一致时服务端返回 `VersionMismatch`，客户端不会降级。

## 2. 载荷契约

源码位置：

```text
src/WinAppGuard.Contracts/Protocol/Payloads.cs
src/WinAppGuard.Contracts/Protocol/PayloadCatalog.cs
```

### 2.1 请求载荷（22 个）

`EmptyPayload`、`RulesQuery`、`RuleAdd`、`RuleDelete`、`RuleDeleteForProgram`、
`RuleClear`、`RuleImport`、`RuleSetGroup`、`StrictCommand`、`PidsQuery`、
`AuditSettings`、`TrafficConfig`、`IdsCommand`、`NetworkSettings`、`GuardDecision`、
`AntiScanCommand`、`LanCommand`、`DnsTrust`、`Ipv6Trust`、`NameBlock`、
`ClearOnly`、`Rebaseline`。

每条命令只发送自己声明的字段；未声明字段不会上线。

### 2.2 响应载荷（9 个）

| 类型 | 用途 |
| --- | --- |
| `StatusView` | 状态、严格模式、审计设置/清空 |
| `RulesView` | 规则列表、到期清理 |
| `FilterMapView` | 过滤器 id → 规则名 |
| `AllowTargetsView` | 本工具/系统/其它软件的放行目标 |
| `ProcessPathsView` | PID → 映像路径 |
| `TrafficView` | 精确流量快照、暂停/继续、清空 |
| `QueryView` | 12 个检测/记录特性的真实字段 |
| `WriteResult` | 通用写命令（`Affected` / `Message`） |
| `ErrorView` | 失败信封（无业务数据） |

`ResponsePayload` 只保留传输元数据：`Ok`、`Error`、`ErrorCode`、`Affected`、
`Revision`、`RevisionEpoch`。新增检测特性只能加到 `QueryView` 或新的专用结果类型，
**不允许**再恢复万能响应类。

## 3. 客户端

```text
ServiceClient.TryRequest(...)          -> ResponsePayload?
ServiceClient.TryRequestAs<T>(...)     -> T?
ElevatedClient.TryRequest(...)         -> ResponsePayload?
ServiceSession.TrySend(...)            -> ResponsePayload?
```

界面入口统一为 `ApplicationGateway`：

- `TryQuery` / `TryTraffic` / `TryRules` / `TryAllowTargets` /
  `TryProcessPaths` / `TryFilterMap` 返回对应强类型视图；
- `TryRequestAsync` / `TryElevatedRequestAsync` 返回 `GatewayResult`，
  其中 `Payload` 是 `ResponsePayload`，`Failure` 区分 Offline / Timeout /
  Unauthorized / VersionMismatch / Error。

写命令通过泛型帮助方法落到具体类型：

```csharp
var result = await CallServiceAsync<WriteResult>(...);
var strict = await CallServiceAsync<StatusView>(...);
var ids = await CallServiceAsync<QueryView>(...);
```

## 4. 服务端结构

| 文件 | 职责 |
| --- | --- |
| `PipeHost.cs` | 监听、握手、逐帧验签、限流、会话循环 |
| `ControlServer.cs` | 生命周期、命令分发、进程路径、健康信息 |
| `StatusBuilder.cs` | 从各 Host 汇总 `ServiceStatus` |
| `RuleHandlers.cs` | 规则/严格模式/审计写入 |
| `ServiceCatalog.cs` | 命令 → Handler 唯一注册点 |

`ControlServer` 已收敛到 400 行以内。v3 的 `LegacyPayloadAdapter` 与所有
`Legacy` 字段已删除。

## 5. 测试

```text
dotnet test tests/WinAppGuard.Architecture.Tests
```

覆盖：

- 76 条命令都有请求/响应载荷类型；
- 9 个响应载荷的 JSON 往返；
- `QueryView` 的 12 类真实特性字段；
- 写命令只暴露 `Affected` / `Message`；
- 失败信封的 `Ok` / `Error` / `ErrorCode`；
- 无签名密钥时客户端拒绝发送。

## 5.1 覆盖安装修复（5.11.1 hotfix）

5.11.0 在慢速虚拟机上从 5.10 覆盖安装时，第一次可能因为服务 exe 仍被
旧进程短暂锁定而复制失败，留下 v3 服务；第二次安装才成功。5.11.1 的安装器现在：

- 停止服务后等待服务进程退出与文件锁释放；
- 先写 `.new` 再原子替换，遇到文件锁自动重试；
- 先换服务再换界面，失败时保留旧的可用组合；
- 校验安装后的界面/服务 `ProductVersion`，不一致直接报错并重启旧服务。

## 6. VM 验收清单

> 本机运行中的 5.10.1 服务不会被 5.11 客户端连接，这是预期行为。
> 必须在一台 VM 上同时部署 v4 服务和 v4 界面。

1. 安装 5.11.0 服务与界面；
2. `WinAppGuard --doctor`：`protocol` 与 `payload-contract` 均为 OK；
3. 规则页：新增/删除/分组/导入导出/严格模式；
4. 10 个检测页刷新、告警已读、清空、设置保存；
5. 流量页：暂停/继续/清空；
6. 审计页：开关、保留天数、域名查询、清空；
7. 普通权限界面写操作弹出 UAC，提权助手能回写结果；
8. 停止服务后界面进入离线只读，不崩溃；
9. 重新启动服务后会话自动重连一次。
