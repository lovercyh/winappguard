# 4.4 IPv6 邻接安全设计（RA / DHCPv6 / NDP）

> 状态：已实现（2026-10-30），待 VM 验收与 WFP 阻断 POC。
> 范围：Windows 主机侧的 IPv6 邻接安全检测；默认只告警，RA/DHCPv6 阻断需 POC 通过。
> 不做：交换机级 RA Guard、主动 MITM、NDP 阻断、IPv6 流量统计/DPI。
> 诊断支持包放 4.5（等功能更多、数据更全时再做）。

## 1. 已定决策

| # | 决策 |
|---|---|
| D1 | 4.4 只做 IPv6 邻接安全；诊断支持包放 4.5 |
| D2 | 入口：「防护 → 局域网」内新增二级子标签 **IPv6 邻接**（顶层仍是四个子标签） |
| D3 | 事件独立存 `%ProgramData%\WinAppGuard\ipv6\events-*.jsonl`，不混入 `lan/events` |
| D4 | 基线学习 **5 分钟**，或直到看到“路由器 + DHCPv6 服务器 + 前缀” |
| D5 | 16 条规则全部实现；低危/易吵规则严格冷却，必要时 4.4.1 再加“低危规则”开关 |
| D6 | 默认只告警；RA/DHCPv6 阻断先做 WFP POC，通过后才提供；NDP 不阻断 |
| D7 | 保留期跟随 4.2 设置（7/15/30 天）；IPv6 清空只删 `ipv6_*` |
| D8 | 信任粒度：路由器（链路本地 + MAC）、DHCPv6（Server ID/DUID + MAC） |

## 2. 目标与边界

### 能发现

- 非基线路由器发 RA、多个路由器、前缀/标志/生命周期变化、RA 洪水；
- 非基线 DHCPv6 服务器、多服务器、DNS/IA/租期变化、短租期；
- 路由器 NA 的 MAC 变化、邻居缓存不一致、同一 MAC 声称多地址/频繁换 MAC、
  免费 NA 突发、SLLA/TLLA 与以太网源不一致、非网关 Redirect、DAD 冲突。

### 不能发现 / 不做

- 交换机端口上的 RA Guard（真正的 RA Guard 是交换机/网桥功能）；
- 加密/隧道内的 IPv6 邻接报文；
- IPv6 流量统计、DPI、载荷保存；
- 默认阻断；NDP 阻断；
- 主动投毒、ARP/NDP MITM。

## 4. 采集

BPF：

```text
arp or (udp and (port 67 or 68 or 53))
or (ip6 proto 58)
or (ip6 and udp and (port 546 or 547))
```

- snaplen 600；混杂模式关闭；
- 只解析头部/选项，不保存报文；
- `ip6 proto 58` 对带扩展头的 ICMPv6 是否命中，POC 验证；必要时退化为 `ip6` 后在代码里过滤；
- 虚拟网卡排除（沿用 4.2），VPN 保留。

## 5. 解析

- IPv6 头 + 扩展头链（0/43/44/60，最多 8 层，严格边界检查）；
- ICMPv6：
  - RA（134）：hop limit、M/O/A/L、router lifetime、reachable/retrans、
    SLLA、MTU、Prefix Info、Route Info、RDNSS、DNSSL；
  - NS（135）：target、SLLA；
  - NA（136）：R/S/O、target、TLLA；
  - Redirect（137）：target、destination；
- DHCPv6：
  - 消息类型、transaction ID、Client ID、Server ID、
    IA_NA/IA_PD、DNS、域名、preferred/valid lifetime；
- 地址规范化：`fe80::/10`、`ff02::/16`、全局地址；MAC 统一小写冒号格式。

## 6. 16 条规则

| # | 规则 | 级别 | 触发 |
|---|---|---|---|
| 1 | `ipv6_ra_unexpected_router` | 高 | RA 源不在基线路由器表 |
| 2 | `ipv6_ra_multiple_routers` | 中 | 同时出现多个路由器 |
| 3 | `ipv6_ra_prefix_changed` | 高 | 已知路由器的 on-link 前缀/长度变化 |
| 4 | `ipv6_ra_flags_or_lifetime_changed` | 中 | M/O/A/L 或 router lifetime/reachable/retrans 异常 |
| 5 | `ipv6_ra_flood` | 低 | 10 秒内 RA 超过阈值（默认 20） |
| 6 | `ipv6_dhcpv6_unexpected_server` | 高 | ADVERTISE/REPLY 来自非基线服务器 |
| 7 | `ipv6_dhcpv6_multiple_servers` | 中 | 同时出现多个 DHCPv6 服务器 |
| 8 | `ipv6_dhcpv6_option_mismatch` | 中 | DNS/域名/IA 前缀/生命周期变化 |
| 9 | `ipv6_dhcpv6_short_lease` | 低 | preferred/valid lifetime < 60 秒 |
| 10 | `ipv6_na_router_mac_changed` | 高 | 路由器 NA 的 MAC 与基线不一致 |
| 11 | `ipv6_na_cache_mismatch` | 中 | 已知邻居地址的 MAC 变化 |
| 12 | `ipv6_na_mac_behavior` | 中 | 同一 MAC 声称多个地址 / 频繁换 MAC |
| 13 | `ipv6_na_unsolicited_burst` | 低 | 免费 NA 突发（默认 20/10 秒） |
| 14 | `ipv6_nd_sender_mismatch` | 中 | SLLA/TLLA 与以太网源 MAC 不一致 |
| 15 | `ipv6_redirect_unexpected` | 中 | 非网关发 Redirect |
| 16 | `ipv6_dad_conflict` | 中 | DAD 的地址已被占用 |

- 冷却：同一（规则 + 关键值）10 分钟；
- 关键值：路由器链路本地/MAC、DHCPv6 Server ID、邻居地址/MAC；
- 高/中/低分级；低危规则的阈值和冷却更严格。

## 7. 基线与信任

- 学习 5 分钟，或直到“路由器 + DHCPv6 服务器 + 前缀”出现；
- 路由器基线：链路本地地址、MAC、前缀、M/O/A/L、lifetime；
- DHCPv6 基线：Server ID/DUID、MAC、DNS/域名、IA 前缀、lifetime；
- 邻居基线：地址、MAC、router flag、首次/最后发现；
- 信任：路由器（链路本地+MAC）、DHCPv6（Server ID+MAC）；
- 「重置基线」只清 IPv6，不影响 4.2/4.3；
- 信任后不清除历史事件。

## 8. WFP 阻断（POC 门禁）

### 8.1 目标

- DHCPv6：阻断非信任服务器的 ADVERTISE/REPLY；
- RA：阻断非信任路由器的 ICMPv6 type 134；
- NDP：不阻断。

### 8.2 POC 方案

在现有 `LanWfp`（4.2 DHCPv4）基础上扩展：

- DHCPv6：
  - 层：`FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V6`，备选 `FWPM_LAYER_INBOUND_TRANSPORT_V6`；
  - 条件：`IP_PROTOCOL=17`、本地端口 546、远端端口 547、远端地址 = 非信任服务器；
- RA：
  - 层：`FWPM_LAYER_INBOUND_TRANSPORT_V6` / `ALE_AUTH_RECV_ACCEPT_V6`；
  - 条件：`IP_PROTOCOL=58`、`ICMP_TYPE=134`、远端地址 = 非信任路由器；
  - 若上述层拦不住，尝试 `FWPM_LAYER_INBOUND_MAC_FRAME_NATIVE`：
    EtherType 0x86DD + 源 MAC，拦该 MAC 的全部 IPv6（10 分钟，范围更宽）；
- 只放行信任路由器/DHCPv6，其余阻断；默认关闭，10 分钟自动解除。

### 8.3 成功标准

- 加过滤器后，Windows 不再安装 rogue RA 的前缀/默认路由；
- 合法路由器/合法 DHCPv6 仍工作；
-  rogue DHCPv6 的地址/DNS 不再被接受；
- `Get-NetRoute` / `Get-NetIPAddress` / 抓包三方一致；
- 不造成 IPv6 整体断网（除明确选择“按 MAC 阻断”的 10 分钟窗口）。

### 8.4 失败回退

- RA 拦不住 → **只告警**；不提供“阻断此 RA”按钮；
- 只有按 MAC 能拦住 → 提供“临时阻断此设备的 IPv6（10 分钟）”，
  仅对路由器/DHCPv6 行可用，明确提示会阻断该 MAC 的全部 IPv6；
- 都不行 → 只告警，文档记录 POC 结论。

## 9. 存储

```text
%ProgramData%\WinAppGuard\ipv6\state.json
%ProgramData%\WinAppGuard\ipv6\events-YYYYMMDD.jsonl
```

- 保留期跟随 4.2 的 7/15/30 天；
- 只写事件元数据（时间/规则/级别/网卡/MAC/IPv6 地址/摘要）；
- 不保存报文、不保存载荷。

## 10. 协议与 DTO

```text
query.ipv6-security
write.ipv6-security.clear
write.ipv6-security.trust
write.ipv6-security.reset-baseline
```

POC 通过后可选：

```text
write.ipv6-security.block
```

`ServiceStatus` 追加：

```text
Ipv6SecurityCollecting
Ipv6SecurityEventCount
```

DTO：

- `Ipv6SecurityStatusDto`：Collecting、BaselineReady、BaselineUtc、EventCount、
  RouterCount、DhcpServerCount、NeighborCount、LastError；
- `Ipv6RouterDto`：LinkLocal、Mac、Prefixes、Flags、Lifetime、Trusted；
- `Ipv6DhcpServerDto`：ServerId、Mac、Dns、Domain、Lease、Trusted；
- `Ipv6NeighborDto`：Address、Mac、IsRouter、State、FirstSeenUtc；
- 事件复用 `LanEventDto`。

## 11. 界面

「防护 → 局域网」内改为二级标签：

```text
局域网
├─ IPv4（ARP / DHCP）   ← 4.2 现有内容
└─ IPv6 邻接            ← 4.4 新增
```

IPv6 页：

- 状态行：采集状态、基线时间、事件数、路由器数、DHCPv6 数、邻居数；
- 上半部分：二级标签 **路由器 / DHCPv6 / 邻居**，各一张表；
- 下半部分：事件表（时间/类型/级别/网卡/详情）；
- 工具条：刷新、清空…、重置基线…、信任此路由器、信任此 DHCPv6、
  每 3 秒自动刷新；
- 默认无阻断按钮；POC 通过后才加“临时阻断此 DHCPv6 / 临时阻断此 RA”；
- 托盘高危 IPv6 事件气泡，点击定位到「局域网 → IPv6 邻接」；
- 中英文、100%/150% DPI。

## 12. 自检与验收

### 离线 `--ipv6-security-test`

- 合成 RA/NS/NA/Redirect/DHCPv6 字节：解析、16 条规则、基线、信任、冷却；
- 事件存储/清空/保留期；
- DTO 往返。

### VM `--service-ipv6-security-test`

- 状态/路由器/DHCPv6/邻居/事件返回；
- 信任/取消信任；
- 清空只删 `ipv6_*`；
- 若 POC 通过，验证阻断过滤器创建/解除。

### 无 IPv6 环境的测试方案

当前网络没有 IPv6，必须搭一个实验网：

- 方案 A（推荐）：增加一台 Linux 路由器 VM（`radvd`），
  在 Host-Only 网络播 `fd00:4:4::/64`；Windows 与 Kali 同网；
- 方案 B（资源不足）：Kali 先当合法路由器（`radvd`），
  再停止并换 `fake_router6` / `dnsmasq` 当 rogue；
  “非基线路由器”场景用第二个 link-local/MAC（macvlan 或第二网卡）；
- Kali 工具：`thc-ipv6`（`fake_router6` / `fake_advertise6` / `parasite6` / `redir6`）、
  `dnsmasq`、`radvd`、`python3-scapy`；
- 测试必须在隔离网络/快照里做，RA 投毒可能改掉 Windows 的 IPv6 默认路由。

### 手工用例

1. Rogue RA（新前缀）→ `ipv6_ra_unexpected_router` 高危；
2. 两个路由器 → `ipv6_ra_multiple_routers` 中危；
3. 前缀变化 → `ipv6_ra_prefix_changed` 高危；
4. 标志/生命周期变化 → 中危；
5. RA 洪水 → 低危；
6. Rogue DHCPv6 → 高危；
7. 多 DHCPv6 → 中危；
8. 选项变化 → 中危；
9. 短租期 → 低危；
10. 路由器 NA MAC 变化 → 高危；
11. 邻居缓存不一致 → 中危；
12. 同一 MAC 多地址/频繁换 MAC → 中危；
13. 免费 NA 突发 → 低危；
14. SLLA/TLLA 不一致 → 中危；
15. 非网关 Redirect → 中危；
16. DAD 冲突 → 中危；
17. 信任/取消信任；
18. 双栈关联（同一 MAC 的 ARP + IPv6 事件）；
19. 24h 误报；
20. 3.4–4.3 回归。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| RA Guard 预期过高 | 文档/UI 明确“主机侧 RA 防护”，不是交换机 RA Guard |
| WFP 拦不住 RA | POC 门禁；失败只告警 |
| WFP 阻断范围过宽 | 默认关闭；优先按源地址；按 MAC 时明确提示 10 分钟 |
| 无 IPv6 环境 | 路由器 VM + radvd + thc-ipv6；隔离网络 |
| 扩展头导致漏包 | POC 验证；必要时抓 `ip6` 后代码过滤 |
| 虚拟网卡自带 RA/DHCPv6 | 沿用 4.2 虚拟网卡排除；VPN 保留 |
| 16 条规则噪声 | 低危严格冷却；24h 后必要时 4.4.1 加“低危规则”开关 |
| 局域网页二级标签拥挤 | 980px/150% DPI 先做布局自检；必要时缩短标签 |
| 阻断导致 IPv6 断网 | 默认关闭；10 分钟 TTL；只拦非信任对象 |
