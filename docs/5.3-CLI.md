# 5.3 CLI 扩展

> 状态：已实现，待 VM 验收
> 日期：2026-11-05
> 范围：只读查询、JSON、精确规则操作、反网络攻击命令、诊断。不改自动拦截 / 自动更新 / 内核驱动边界。

## 1. 权限边界

| 命令 | 权限 |
|---|---|
| `--version` / `--log-path` | 无 |
| `--status` / `--service-status` | 所有者账户（不提权） |
| `--list-blocked` / `--list-rules` | 所有者账户（不提权） |
| `--export-rules` | 所有者账户（不提权） |
| `--network-status` / `--network-alerts` | 所有者账户（不提权） |
| `--network-ack` / `--network-clear` | 所有者账户（不提权；clear 需 `--yes`） |
| `--audit-tail` | 当前用户可读审计目录即可 |
| `--doctor` | 所有者账户 |
| `--block` / `--unblock` / `--unblock-all` | 管理员 |
| `--import-rules` | 管理员 |
| `--network-block` / `--network-unblock` / `--network-unblock-all` | 管理员 |
| `--network-set-adapter` / `--network-set-categories` | 管理员 |
| `--migrate` / `--recover` | 管理员 |

只读命令仍然要过服务管道的所有者认证（SYSTEM + 所有者 SID + ECDSA 签名），只是不再要求额外的管理员提权。

## 2. 常用命令

```text
WinAppGuard --version
WinAppGuard --status
WinAppGuard --status --json
WinAppGuard --list-rules --json
WinAppGuard --list-rules --action block

WinAppGuard --block "C:\Tools\a.exe"
WinAppGuard --block "C:\Tools\a.exe" --minutes 30
WinAppGuard --block "C:\Tools\a.exe" --until-reboot
WinAppGuard --block @C:\list.txt --dry-run
WinAppGuard --block @C:\list.txt --yes
WinAppGuard --unblock "C:\Tools\a.exe"
WinAppGuard --unblock @C:\list.txt --dry-run
WinAppGuard --unblock @C:\list.txt
WinAppGuard --unblock --name AppGuard_Block_a.exe_xxxx
WinAppGuard --unblock "C:\Tools\a.exe" --require-match

WinAppGuard --export-rules rules.json --action block
WinAppGuard --import-rules rules.json --action block --dry-run
WinAppGuard --import-rules rules.json --action block --yes

WinAppGuard --network-status --json
WinAppGuard --network-alerts --limit 20 --unread --json
WinAppGuard --network-ack <alert-id>
WinAppGuard --network-clear --yes
WinAppGuard --network-block <alert-id> --scope ip-port --minutes 10 --yes
WinAppGuard --network-unblock <block-id>
WinAppGuard --network-unblock-all --yes
WinAppGuard --network-set-adapter auto
WinAppGuard --network-set-adapter <GUID>
WinAppGuard --network-set-categories malware,exploit,dns

WinAppGuard --audit-tail --limit 50 --json
WinAppGuard --doctor --json
WinAppGuard --log-path
```

## 3. JSON 约定

```json
{
  "schemaVersion": 1,
  "toolVersion": "5.3",
  "ok": true,
  "data": {}
}
```

错误：

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "NOT_ELEVATED",
    "message": "Administrator rights required."
  }
}
```

- key 固定英文，不做本地化；
- `--json` / `--format json` 等价；
- 错误也走 JSON，方便脚本判断；
- 默认人读输出保持不变，避免破坏已有脚本。

## 4. 退出码

```text
0  成功
1  参数错误 / 需要确认
2  执行失败
3  缺少管理员权限
4  未找到（--unblock --require-match、告警/拦截 id 不存在）
```

## 5. 安全规则

- 写命令不因为 5.3 放宽权限；需要管理员的仍然需要。
- 批量 / 不可逆操作要求 `--yes`：
  - `--block @列表`
  - `--import-rules`
  - `--network-clear`
  - `--network-block`
  - `--network-unblock-all`
  - `--unblock-all`
- 支持 `--dry-run` 的命令先预览，再执行。
- `--export-rules` 覆盖已存在文件时需要 `--yes`。
- `--unblock` 只删除「阻止」规则，不会误删白名单。
- `--recover` / `--migrate` 保持原有管理员恢复路径。
- 不自动拦截、不自动更新规则、不上传任何数据。

## 6. 验收

### 非管理员

1. `--version`、`--help`、`--log-path` 正常。
2. `--status --json`、`--list-blocked`、`--list-rules --json` 正常，不弹 UAC。
3. `--network-status --json`、`--network-alerts --json` 正常。
4. `--audit-tail --json` 正常。
5. `--doctor --json` 正常。
6. `--export-rules` 正常。
7. `--block` / `--unblock` / `--import-rules --yes` / `--network-block` 返回 3。
8. `--block @list --dry-run` 正常；不带 `--yes` 的实际批量阻止返回 3（未提权）。

### 管理员

1. `--block --minutes 30` 创建限时规则。
2. `--block --until-reboot` 创建到下次重启的规则。
3. `--block @list --yes` 批量创建。
4. `--unblock <path>` 删除对应阻止规则，白名单不动。
5. `--unblock --require-match` 未找到返回 4。
6. `--export-rules` / `--import-rules --dry-run` / `--import-rules --yes`。
7. `--network-block` / `--network-unblock` / `--network-unblock-all`。
8. `--network-set-adapter auto|<GUID>` 后状态栏显示实际网卡。
9. `--network-set-categories` 后规则数变化。
10. `--doctor` 所有项为 OK / WARN，没有 FAIL；非管理员下 `npcap-open` 显示“未检查（需要管理员权限）”，不会弹 UAC。

## 7. 不在 5.3 范围

- 审计按时间 / 程序过滤（先做最近 N 条）。
- IDS / LAN / DNS 的完整 CLI（先通过 `--status` 查看状态）。
- 自动拦截 / 自动更新 / 内核驱动 / 逐条规则开关。
