# 5.13：文件夹批量添加黑名单 / 白名单

> 版本：5.13.0  
> 协议：v4，无新增命令；复用 `write.rules.import`  
> 语义：**快照**——只添加扫描时已经存在的 `.exe`

## 1. 功能

### 黑名单

```text
黑名单页 → 添加文件夹…
→ 选择文件夹
→ 扫描 .exe
→ 预览 / 勾选
→ 批量添加为“阻止联网”规则
```

### 严格模式白名单

```text
白名单页 → 添加文件夹…
→ 选择文件夹
→ 扫描 .exe
→ 预览 / 勾选
→ 批量添加为“允许联网”规则
→ 严格模式开启时立即刷新会话
```

### 快照语义

- 本次只添加扫描时存在的 `.exe`；
- 之后新放进文件夹的 exe **不会自动加入**；
- 动态监视文件夹是 5.14 的候选功能。

## 2. 限制

- 只扫描 `.exe`；
- `.bat` / `.cmd` / `.ps1` / `.msi` / `.lnk` 不是独立进程映像，不能按路径拦截；
- 不跟随 junction / symlink；
- 不访问 UNC 网络路径；
- 最多 2000 条；
- 跳过受保护进程和已存在规则；
- 白名单文件夹必须勾选风险确认；
- 不建议把 Downloads / Desktop / Temp 等可写目录加入白名单。

## 3. 实现

### UI

- `FolderRuleBatchForm`：共享对话框，黑名单/白名单只传不同 `FirewallAction`；
- `FolderRuleScanner`（Core）：只做文件枚举，不碰 WFP，可单元测试；
- 扫描在后台线程执行，可取消；
- 预览显示「可添加 / 已存在 / 受保护」；
- 默认分组：`文件夹黑名单：<名称>` / `文件夹白名单：<名称>`。

### 服务端

复用 `write.rules.import`：

- 单引擎批量添加；
- 跳过已存在 / 受保护；
- 分组、到期时间、严格模式刷新；
- `WriteResult` 返回 `Affected` / `Skipped` / `Failed`。

### 为什么不用新命令

文件夹扫描在客户端完成，服务端只需要接收路径列表。现有导入文档格式已经支持：

```text
program + action + expiry + scope + group
```

并且已经是单引擎批处理，所以 5.13 复用导入路径，避免再增加一套协议命令。

## 4. 修复

`RuleImport` 请求载荷补回 `Action` 字段。5.11/5.12 中客户端投影会丢掉
`Action`，导致服务端导入时无法判断黑名单/白名单；5.13 一并修复。

### 4.1 统计显示 0 条

普通权限运行时，写命令经提权助手执行：

```text
界面写请求（默认 PascalCase）
→ 提权助手执行
→ 助手写 camelCase 响应
→ 界面用默认选项按 PascalCase 读回
→ affected / skipped / failed / error 全部丢失
→ 显示“成功 + 0 条”
```

现在统一用 `ElevatedIpcFile` + `ServiceProtocol.JsonOptions` 读写临时文件；
另外文件夹添加和清空黑名单在显示前会以刷新后的规则数量兜底。
回归测试见 `ElevatedIpcFileTests`（3 项）。
