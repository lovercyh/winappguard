# 5.9 架构统一实施

> 状态：进行中
> 分支：`arch/5.9`
> 目标：把 12 个相似但不相同的检测子系统收敛成“一套特性框架 + 各特性策略”。
> 边界：5.9 不改跨进程协议；协议 v3 放到 5.10。

## 1. 已确认的决策

- 5.9 做完整架构统一，不按“只做地基”缩小范围。
- 旧数据必须可读；状态文件只允许“读旧写新 + 迁移”，不允许静默清空。
- dev-only 测试使用 xUnit；真实 UI / WFP / 服务 / CLI 仍由 SelfCheck 验收。
- 5.8 的 `guard.new-program.*` 是独立权限策略 `OwnerTemporaryWfp`，不能归入 Read / Write / Alert。
- 后台检测（新程序提醒、默认阻止、IDS 通知）与 UI 可见页刷新分离。
- 5.9 内完成内部模块/存储/页面统一；协议 v3、信封化跨进程载荷在 5.10 完成。
- 完成前不 push main、不打 tag；保留 `v5.8` 作为回滚点。

## 2. 阶段

### 阶段 0：基建与测试骨架（已完成）

- `ErrorCode` / `Result<T>`
- `CommandPolicy` / `CommandPolicyTable`
- `JsonStateFile<T>` / `JsonlEventLog<T>`
- `FeatureEvent` / `FeatureSettings`
- `ExpiringBlockRegistry<TKey>`
- `Baseline<T>`
- `IClock`
- dev-only xUnit 测试工程
- CI 增加架构测试

完成标准：新增代码有测试，旧代码零行为改动，构建 0 警告。

### 阶段 1：命令策略与路由（已完成）

- `ICommandHandler` / `CommandRouter` / `ServiceCatalog`
- `ServiceCatalog` 逐条登记全部协议命令，`ControlServer.Dispatch` 不再保留大 switch
- 启动期 `Validate()` 校验：声明命令恰好一个 Handler、无协议外 Handler、策略显式、只有 guard 命令允许 `OwnerTemporaryWfp`
- `auth.challenge` 仍由握手流程单独处理；路由层保留防御性拒绝
- 仍使用协议 v2 的 `ServiceRequest/ServiceResponse`

完成标准：全部命令经路由分发；`CommandPolicyGuard` 的提权/告警/新程序例外行为与 5.8 一致。

### 阶段 2：存储/事件/设置迁移（已完成）

- IDS
  - 状态改为 `JsonStateFile<IdsState>`
  - 告警改为 `JsonlEventLog<IdsAlert>`
- NetworkDetection
  - 状态与告警迁移到同一套实现，旧 `alerts.jsonl` 可读
- AntiScan / LAN / IPv6 / ConfigIntegrity
  - 旧无外壳 `state.json` 可读，读到后立即重写新 schema
- FirstSeenProgramStore
  - 兼容 5.8 的顶层数组格式，读取后重写为 `schema/data` 外壳
- LAN / IPv6 / Config 事件
  - 旧 `events-yyyyMMdd.jsonl` 可读，新记录写入可轮转分片
- 安全敏感与专用存储保持原实现
  - OwnerKey、受保护模式、WFP DACL 标记
  - AuditStore：保留专用流式写入和持久文件句柄，避免审计吞吐回退
  - RuleGroupStore、UiLanguageStore：不属于检测状态

### 阶段 3：服务模块化（已完成）

- `IServiceModule` / `ModuleHost`
- 14 个 Host 收敛为 12 个生命周期模块：

| 模块 | 包含 |
|---|---|
| `rules` | `RuleHandlers` 定时清理 / 篡改检测 / 锁网到期 + `StrictModeHost`、`LockdownHost` 停止 |
| `audit` | `AuditHost` |
| `traffic` | `TrafficHost` |
| `traffic-capture` | `TrafficCaptureHost` |
| `dns` | `DnsHost` |
| `ids` | `IdsHost` |
| `antiscan` | `AntiScanHost` |
| `lan` | `LanHost`（ARP/DHCP、DNS 安全、IPv6、名称解析） |
| `config-integrity` | `ConfigHost` |
| `network-detection` | `NetworkDetectionHost` + `SuricataHost` + `NetworkBlockHost` |
| `new-program-guard` | `NewProgramGuardHost`（保留无 UAC 临时 WFP 例外） |
| `control-plane` | 命名管道与命令路由，最后启动、最先停止 |

- 启动按 `Order` 正序，停止反序
- 单个模块启动失败只记录并标记 `Failed`，其它模块继续启动
- 只对幂等模块启用有限自动重启：`audit`、`config-integrity`、`new-program-guard`
- 最多重启 3 次，间隔 30 秒；超过后保持失败状态并等待人工处理
- 健康快照写入服务日志，不改协议 v2 载荷

### 阶段 4：UI 网关与页面统一

- `IApplicationGateway`
- `PageBase` / `UiRefreshScheduler`
- `EventTable<T>` / `BlockTable` / `BaselineTable`
- 保留 5.6 滚动修复、5.7 导出/汇总/诊断包、5.8 默认阻止弹窗
- 后台定时器不交给可见页调度器

### 阶段 5：收口

- 删除旧 Host / 旧 StateStore / 旧重复实现
- 全量 SelfCheck + 架构测试 + VM 验收
- 版本 5.9
- 本地提交，等你批准后 push / tag / Release

## 3. 兼容性硬约束

- 旧 `state.json`、事件 `.jsonl`、`settings.json`、`first-seen-programs.json` 必须可读。
- 坏文件保留 `.corrupt-*`，不静默覆盖。
- CLI `--json` 字段与退出码保持兼容。
- 5.8 的临时阻止释放、删除记录后重新弹窗、全部已读必须回归通过。
- WFP 权重、DACL、严格模式、OwnerKey 的行为不得改变。
