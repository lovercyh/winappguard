# 4.5 三功能设计（UDP/ICMP 扫描 · 名称解析投毒 · 本机配置篡改）

> 状态：**已实现（4.5，2026-11-01）**，待 VM 验收。
> 范围：4.5 = 三个功能；诊断支持包顺延到 4.6。
> 前提：不引入内核驱动、不读载荷、不依赖云查杀；阻断一律临时、可解除。

## 0. 已确认的决策

| # | 决策 |
|---|---|
| D1 | 名称解析投毒的阻断**只封来源**：只拦该来源地址的 UDP 5355/137/5353，不整机封禁 |
| D2 | mDNS 默认只开「WPAD」和「地址冲突」两类规则；「一 MAC 多名称」对 mDNS 默认关闭 |
| D3 | 本机配置篡改使用**新的二级页**「防护 → 本机配置」 |
| D4 | UDP 扫描检测默认开启；**自动阻断默认关闭**（与 4.0 的 AutoBlock 保持一致） |
| D5 | 事件存储：名称解析事件进 `lan/`（`name_*`），配置事件进新目录 `config/`（`config_*`） |

## 1. 总体结构

```text
NpcapLanCapture（现有会话）
  ├─ ARP / DHCP / DNS / IPv6（现有）
  ├─ + LLMNR / NBNS / mDNS 解析 → NameResolutionAnalyzer
  └─ + DHCP option 252（WPAD） → LanAnalyzer

AntiScan NpcapCapture（独立会话）
  └─ + UDP / ICMP / ICMPv6 → AntiScanAnalyzer（协议字段）

LanHost Tick（1s）
  ├─ NameResolutionAnalyzer.Tick（冷却、缓存清理）
  ├─ ConfigIntegrityAnalyzer（30s 一次快照比对，不依赖 Npcap）
  └─ 到期阻断回收
```

## 2. 功能 A：UDP / ICMP 扫描检测

### 2.1 采集

`src/WinAppGuard.Core/Diagnostics/AntiScan/NpcapCapture.cs`

- BPF 扩展为：

```text
(tcp and (tcp[tcpflags] & tcp-syn) != 0 and (tcp[tcpflags] & tcp-ack) == 0)
or (icmp and icmp[icmptype] == 8)
or (icmp6 and ip6[40] == 128)
or udp
```

- 解析模型 `InboundSyn` → `InboundProbe`：

```csharp
public readonly record struct InboundProbe(
    DateTime TimeUtc,
    byte Protocol,      // 6=TCP, 17=UDP, 1=ICMP, 58=ICMPv6
    IPAddress SourceAddress,
    ushort SourcePort,  // ICMP 为 0
    IPAddress LocalAddress,
    ushort LocalPort);  // ICMP 为 0
```

- 保持现有兜底：只处理“目的地址是本机”的包（沿用 `TryParseInboundSyn` 的本地地址判断）。

### 2.2 UDP 降噪（核心）

- 每 5 秒刷新一次本机 UDP 监听端口集合：
  `IPGlobalProperties.GetActiveUdpListeners()` → `HashSet<ushort>`（按端口匹配，保守）；
- 只有**目标端口不在监听集合**的入站 UDP 才交给分析器；
- 排除组播/广播目的地址（`224.0.0.0/4`、`255.255.255.255`、`ff00::/8`）；
- 目的端口 0、源地址不可用（0.0.0.0、回环、组播）直接丢弃。

### 2.3 判定阈值

| 协议 | 窗口 | 高危 | 中危 |
|---|---|---|---|
| TCP SYN | 60s / 10s | 沿用 4.0 现值 | 沿用 4.0 现值 |
| UDP 非监听端口 | 60s | ≥30 个不同本地端口 | ≥15 个不同本地端口 |
| UDP 突刺 | 10s | ≥12 个不同本地端口 | — |
| ICMP/ICMPv6 Echo | 60s | 单源 ≥40 个 | 单源 ≥20 个 |

> 保守模式把所有阈值约放大一倍。“快速阈值必须低于中危阈值”，否则 1 秒一个端口的
> 慢速扫描会先被快速规则判成高危，中危分支永远走不到（离线测试已覆盖）。

- 同一来源 30 分钟冷却（沿用现有冷却机制）；
- 命中后按来源聚合成一条事件，`Protocol` 标明来源协议。

### 2.4 阻断

- 复用 `AntiScanWfp`（ALE 入站按来源 IP 封禁），TCP 已验证，UDP/ICMP 在 VM 复验；
- 若 ALE 对 UDP/ICMP 无效：改用 transport 层（v4 需新增 `FWPM_LAYER_INBOUND_TRANSPORT_V4`，v6 已有）；
- **AutoBlock 默认关闭**；手动「临时封禁此来源」保持 10/30/60 分钟。

### 2.5 开销与安全阀

- 只解析头部、零分配；
- 统计 Npcap 丢包率（`ps_drop`）与每秒包数；
- 丢包率 >1% 或持续 60s 超过阈值 → 自动暂停 UDP 检测、状态行提示、写日志；
- 设置项 `DetectUdp` / `DetectIcmp` 可单独关闭。

### 2.6 界面 / DTO / 自检

- 端口扫描页：事件表加「协议」列；设置加两个勾选；
- `AntiScanEventDto` 加 `Protocol`；`AntiScanStatusDto` 加各协议计数；
- 新增 `--antiscan-proto-test`：合成 TCP/UDP/ICMP 探针、监听端口过滤、阈值、白名单、冷却断言。

## 3. 功能 B：LLMNR / NBNS / mDNS 投毒 + WPAD

### 3.1 采集

`NpcapLanCapture` BPF 追加：

```text
or (udp and (port 5355 or 137 or 5353))
or (ip6 and udp and (port 5355 or 5353))
```

新增解析器（`NameResolutionModels.cs`）：

```csharp
public sealed class NameMessage
{
    public DateTime TimeUtc;
    public string Adapter;
    public string Protocol;        // llmnr / nbns / mdns
    public string SourceAddress;   // 链路本地/内网地址
    public string? SourceMac;
    public string DestinationAddress;
    public bool IsResponse;
    public ushort TransactionId;
    public string Question;
    public List<string> Addresses; // A/AAAA
    public uint Ttl;
}
```

- 名称解码复用/抽出 DNS 压缩指针解析（深度上限 8、指针必须回退，防环）；
- NBNS 名称按 first-level encoding 解码（32 字节 → 16 字符）；
- mDNS 只取 A/AAAA，PTR/TXT 忽略；
- 边界检查：所有长度/计数都做上限（问题 ≤4、答案 ≤16、名称 ≤255）。

### 3.2 规则（首版）

| 规则 id | 名称 | 级别 | 默认 |
|---|---|---|---|
| `name_conflict` | 同一名称 60s 内被不同来源解析到不同地址，或与 DNS 结果冲突 | 高 | 开 |
| `name_unsolicited` | QR=1 但 10s 内没有匹配 TXID 的查询（仅 LLMNR/NBNS） | 中 | 开 |
| `name_many_names` | 同一源 MAC 60s 内应答 ≥5 个不同名称（仅 LLMNR/NBNS） | 高 | 开 |
| `name_wpad` | 查询/应答 `wpad` 或 `wpad.*`，来源不是网关/DNS | 高 | 开 |
| `name_mdns_conflict` | mDNS 地址与 DNS 结果冲突（仅当地址同时有 DNS 记录时） | 中 | 开 |
| `name_mdns_many` | mDNS 一 MAC 多名称 | 低 | **关**（D2） |

- 冷却键：`规则 + 名称 + 来源`，10 分钟；
- 不做基线学习：名称解析没有稳定的“正常值”，用冲突判定更准；
- 名称冲突的比对对象：内存中 60s 内的其它应答 + DNS 最近解析结果 + hosts 快照。

### 3.3 WPAD 三条路径

1. DNS：`DnsAnalyzer` 中 `QuestionName` 为 `wpad` / `wpad.<域>` → 事件；
2. LLMNR/NBNS/mDNS：同上；
3. DHCP：`ParseDhcp` 增加 option 252（字符串），`DhcpMessage` 加 `Wpad` 字段；
   命中即事件，并可直接复用 4.2 的「临时阻断此 DHCP」。

### 3.4 阻断（D1：只封来源）

- 新增 `LanNameWfp`：动态会话（模式同 `Ipv6BlockHost`，进程退出自动清）；
- 过滤器：transport 层，远端地址 + UDP + **源端口 5355/137/5353**，
  每个端口一条，key = `name|地址|端口`；
- 时长 10 分钟；服务重启即解除；UI 显示「阻断」列与剩余分钟；
- 不提供整机封禁（后续版本再评估）。

### 3.5 界面 / 协议

- 「局域网」二级标签变为：`IPv4（ARP / DHCP） / IPv6 邻接 / 名称解析`；
- 名称解析页：来源表（地址/MAC/协议/最后应答/阻断）+ 事件表 + 刷新/清空/临时阻断；
- 事件进 `lan/`，kind 前缀 `name_`；「清空局域网告警」会一并清除（它们是 LAN 事件）；
- 命令：
  - `query.name-resolution`
  - `write.name-resolution.clear`
  - `write.name-resolution.block`（address + enabled + minutes）
- DTO：
  - `NameResolutionStatusDto`（Collecting/SourceCount/EventCount/BlockedCount/LastError）
  - `NameSourceDto`（Address/Mac/Protocols/AnswerSummary/LastSeenUtc/Blocked/BlockExpiresUtc）

### 3.6 自检 / 验收

- 新增 `--name-resolution-test`：合成 LLMNR/NBNS/mDNS 报文（含压缩指针、非法长度、循环指针）、
  5 条规则、冷却、WPAD、阻断列表逻辑（不碰 WFP）；
- VM：
  - Kali `Responder.py -I eth0 -wrv` → 冲突/多名称事件，阻断后 LLMNR 请求无应答；
  - avahi 模拟 mDNS 冲突；
  - dnsmasq `--dhcp-option=252,"http://1.2.3.4/wpad.dat"` → WPAD 事件 + 可阻断 DHCP；
  - 正常网络 24h 无误报。

### 3.7 风险

- mDNS 在打印机/IoT 多的网络很吵 → 默认只开 WPAD + 冲突；
- Windows 只有 DNS 失败时才发 LLMNR，测试需主动查不存在的主机名；
- 攻击者可用非标准源端口 → 本轮接受“拦不住”的边界，文档写明。

## 4. 功能 C：hosts / 代理 / PAC / DNS 设置篡改

### 4.1 监控项与读取位置

| 项 | 位置 | 备注 |
|---|---|---|
| hosts | `%SystemRoot%\System32\drivers\etc\hosts`、`hosts.ics` | 去注释/空行后解析为 (IP, names) |
| WinINET 代理 | `HKEY_USERS\<SID>\Software\Microsoft\Windows\CurrentVersion\Internet Settings` | ProxyEnable/ProxyServer/AutoConfigURL/AutoDetect |
| 策略代理 | `HKLM\SOFTWARE\Policies\Microsoft\Windows\CurrentVersion\Internet Settings` | 企业策略变化单独标注 |
| WinHTTP 代理 | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\Connections` | `WinHttpSettings`、`DefaultConnectionSettings` |
| DNS 服务器 | 现有 `LanEnvironment.GetDnsHints()` | 与基线比对 |

**已知约束（写进文档与界面提示）**：

- 服务以 SYSTEM 运行，读不到“当前用户 HKCU”，只能遍历 `HKEY_USERS` 下**已加载**的 hive；
- 用户未登录 → 该 hive 不存在，属于正常缺失，不告警；
- 多用户同时登录 → 按 SID 分别记录，事件里带 SID 对应的显示名（拿不到就显示 SID）。

### 4.2 基线、比对与事件

- 首次运行立即建立基线（不做 5 分钟学习），并落盘 `config/state.json`；
- 每 30 秒比对一次；变化 → 事件：
  - `config_hosts_changed`
  - `config_proxy_changed`
  - `config_pac_changed`
  - `config_winhttp_proxy_changed`
  - `config_dns_servers_changed`
- 级别：hosts 新增非默认条目 / 代理 / PAC = 高；WinHTTP / DNS = 中；
- 冷却：同一项 10 分钟；一次改多项合并成一条事件；
- 摘要只留前 10 条差异（新增/删除/修改），不落盘完整 hosts 内容。

### 4.3 不自动修复

只告警，不自动回滚 hosts/代理：这些可能是有意配置（企业 PAC、开发环境）。
提供「重新采基线」按钮；后续版本再评估“一键恢复基线”。

### 4.4 界面 / 协议

- 新二级页「防护 → 本机配置」（D3）：
  - 状态行：基线时间、监控项数、事件数；
  - 监控项表格：项目 / 当前值摘要 / 基线值摘要 / 状态 / 最后变更；
  - 事件表；按钮：刷新、重新采基线、清空事件；
- 命令：`query.config-integrity`、`write.config-integrity.clear`、
  `write.config-integrity.rebaseline`；
- DTO：`ConfigIntegrityStatusDto`、`ConfigItemDto`；事件复用 `LanEventDto`（`config_*`）。

### 4.5 存储

```text
%ProgramData%\WinAppGuard\config\state.json
%ProgramData%\WinAppGuard\config\events-YYYYMMDD.jsonl
```

- 保留期跟随 4.2 的 7/15/30 天；清空只删 `config_*`；
- 服务停止/启动不影响基线。

### 4.6 自检 / 验收

- 新增 `--config-integrity-test`：分析器与 IO 解耦，喂快照测差异/冷却/多 SID；
- VM：
  - 手工改 hosts → 高事件；还原后不重复；
  - 改 ProxyServer / AutoConfigURL → 事件；
  - 两个用户同时登录，只报被改的 hive；
  - 24h 不改配置 → 0 事件。

## 9. 明确不做

- 整机封禁（名称解析只封来源的 3 个端口）；
- 自动回滚 hosts / 代理；
- NDP 阻断、永久自动封禁、流量整形；
- 内核驱动、HTTPS/DoH 解密、云查杀。

## 10. 风险台账

| 风险 | 影响 | 对策 |
|---|---|---|
| 全量 UDP 抓包 CPU 高 | 卡顿/丢包 | 监听端口过滤、零分配解析、丢包安全阀自动暂停 |
| ALE 对 UDP/ICMP 封禁无效 | 阻断不生效 | VM 复验；失败退 transport 层（新增 v4 常量） |
| mDNS 误报 | 告警疲劳 | 默认只开 WPAD + 冲突，严格冷却 |
| 多用户 HKCU 读不到 | 漏报 | 只监控已加载 hive，界面说明；不做静默假设 |
| 名称压缩指针恶意构造 | 崩溃 | 深度上限 8、指针必须回退、长度全校验 |
| 事件量增加 | 存储增长 | 冷却 + 聚合 + 保留期沿用 |
