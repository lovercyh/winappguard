# 4.3 VM 验收说明

> 4.3 = 本地 DNS 劫持 / 投毒检测 + 明文 DNS 绕过检测；只告警、不阻断。
> 事件与 4.2 共用 `lan/events-YYYYMMDD.jsonl`，用 `dns_` 前缀区分。
> 只抓 **IPv4 UDP 53**；IPv6 DNS、DoH/DoT 不在 4.3 范围。

## 1. 准备

- 验收机：Windows 10/11，已安装 4.3 验收包与 Npcap 1.90。
- 攻击机：Kali Linux，与验收机在同一二层网络（桥接 / Host-Only，不要 NAT）。
- **IPv4 DNS**：验收机网卡要有一个可用的 IPv4 DNS，建议固定为
  `223.5.5.5` 或网关。4.3 以网卡配置的 DNS 作为“已知服务器”；
  如果 DHCP 没有下发 IPv4 DNS，`Get-DnsClientServerAddress -AddressFamily IPv4`
  会是空的，4.3 会把所有 DNS 都当成“非配置服务器”，24h 误报会失真。
- 确认命令：

```powershell
Get-DnsClientServerAddress -AddressFamily IPv4
ipconfig /all
```

- 记录基线：验收前先正常上网 5 分钟，确认「防护 → DNS 安全」基线已就绪。

> 如果 DHCP 默认看不到 IPv4 DNS：不要切回 DHCP。直接给网卡固定一个 IPv4 DNS
> （223.5.5.5 或网关），再开始验收。

## 2. 一键自动验收

管理员 PowerShell：

```powershell
cd <项目>\dist-tools
& .\4.3-验收脚本.ps1 -LogPath "$env:USERPROFILE\Desktop\wag-4.3-验收.txt"
```

如果不想让脚本做“临时锁网 / 清空流量”（会短暂断网），加 `-SkipDisruptive`：

```powershell
& .\4.3-验收脚本.ps1 -SkipDisruptive -LogPath "$env:USERPROFILE\Desktop\wag-4.3-验收.txt"
```

脚本会重启服务、跑离线与服务端自检，但不修改规则 / 白名单 / 防火墙。
自动检查全部通过后，再做下面的手工项。

## 3. 手工验收

### A. 真实工具投毒（dnsspoof / ettercap）

先用 ARP 把验收机的 DNS 流量引到 Kali：

```bash
# Kali
sudo sysctl -w net.ipv4.ip_forward=1

# 终端 1
sudo arpspoof -i eth0 -t <验收机IP> <网关IP>

# 终端 2
sudo arpspoof -i eth0 -t <网关IP> <验收机IP>
```

dnsspoof：

```bash
cat > /tmp/hosts.txt <<'EOF'
192.168.56.20 bank.example
EOF
sudo dnsspoof -i eth0 -f /tmp/hosts.txt
```

或 ettercap：

```bash
# /etc/ettercap/etter.dns 里加：bank.example A 192.168.56.20
sudo ettercap -T -q -i eth0 -M arp:remote -P dns_spoof /<网关IP>// /<验收机IP>//
```

验收机：

```powershell
ipconfig /flushdns
nslookup bank.example
```

预期：

- dnsspoof / ettercap 默认把“被查询的 DNS 服务器 IP”作为伪造应答的源 IP，
  所以通常命中 **`dns_server_not_gateway`（中危，源 MAC 不是网关）**；
- 常见还会命中 **`dns_ttl_suspicious`（低危，TTL=0）**；
- 如果真 DNS 的应答也在 2 秒内到达，可能命中 **`dns_conflicting_answers`（中危）**；
- **高危规则用 B 的 Scapy 精确构造**，不要期待 dnsspoof 默认就出高危。

### B. 精确高危规则（Kali / Scapy）

脚本在 `dist-tools\4.3-DNS投毒验收.py`（Kali 上运行）。依赖：

```bash
sudo apt install -y python3-scapy
```

每个模式换一个域名，验收机先 `ipconfig /flushdns`，再用
`nslookup <域名> <Kali-IP>` 把查询直接发给 Kali（不需要改系统 DNS）：

```powershell
ipconfig /flushdns
nslookup unexpected.example 192.168.56.20
```

| 模式 | Kali 命令 | 预期规则 |
|---|---|---|
| unexpected | `sudo python3 4.3-DNS投毒验收.py <验收机IP> unexpected` | `dns_response_unexpected_server` 高危 |
| txid | `... txid` | `dns_transaction_mismatch` 高危 |
| name | `... name` | `dns_answer_name_mismatch` 高危 |
| nxdomain | `... nxdomain` | `dns_nxdomain_with_answer` 高危 |
| conflict | `... conflict` | `dns_conflicting_answers` 中危 |
| ttl | `... ttl` | `dns_ttl_suspicious` 低危 |

> 这些模式通常还会同时出现 `dns_server_not_gateway`（中危），因为回包 MAC 是 Kali；
> 这是预期，不是误报。

### C. 明文 DNS 绕过 + 信任 / 取消信任

不改系统 DNS，直接把查询发给 Kali：

```powershell
ipconfig /flushdns
nslookup bypass.example 192.168.56.20
```

预期：

- 出现 **`dns_plaintext_bypass`（中危）**，目标为 Kali IP；
- 服务器表里 Kali IP 显示为「观察到」；
- 点「信任此 DNS 服务器」后再查一次 → 不再新增绕过告警；
- 点「取消信任此 DNS 服务器」后再查 → 绕过告警恢复。

> 顺序建议：先做 B 的高危测试，再做 C 的信任测试。
> 一旦信任 Kali，来自它的应答侧高危规则也会被抑制，这是设计行为。

### D. 正常 24h 误报

保持服务运行，正常浏览、视频、游戏、系统更新 24 小时：

- 高危 / 中危 DNS 事件应为 **0**；
- `dns_ttl_suspicious`（低危）若出现，人工确认是否为合法 CDN；
- DoH/DoT 不告警是预期；
- 记录服务资源占用（只记录，不设门禁）。

统计命令：

```powershell
$dir = "$env:ProgramData\WinAppGuard\lan"
$events = foreach ($file in Get-ChildItem "$dir\events-*.jsonl") {
    foreach ($line in Get-Content $file.FullName) {
        if ([string]::IsNullOrWhiteSpace($line)) { continue }
        try { $line | ConvertFrom-Json } catch {}
    }
}
$dns = $events | Where-Object { $_.kind -like 'dns_*' }
"DNS 事件总数 = $($dns.Count)"
$dns | Group-Object kind, severity | Sort-Object Count -Descending |
    Format-Table Count, Name -AutoSize
```

### E. 落盘 / 清空 / 保留期

- 重启服务后 DNS 事件仍在。
- 「DNS 安全 → 清空」只删 `dns_*`，ARP/DHCP 事件保留。
- 「局域网 → 清空」不影响 DNS 事件。
- 保留期跟随 4.2 设置（7/15/30 天）。

### F. 界面

- 防护页四个子标签：端口扫描 / 局域网 / DNS 安全 / IDS。
- 托盘高危 DNS 气泡点击定位到 DNS 安全子标签。
- 中英文、100% / 150% DPI 不截断。
- 「每 3 秒自动刷新」默认开；取消后表格不再变化。

## 4. 通过标准

1. dnsspoof / ettercap 真实投毒能被发现（至少 `dns_server_not_gateway` 中危）；
2. Scapy 构造的 4 条高危规则 5 秒内命中，详情指出请求 / 应答来源；
3. 信任后不再重复，取消信任后恢复；
4. 明文 DNS 绕过命中，可信任；
5. 正常 24h 高危/中危误报 0；
6. 事件重启后仍在；清空只删 DNS 事件；保留期与 4.2 一致；
7. 四个防护子标签、托盘深链、中英文、150% DPI 正常；
8. 3.4–4.2 回归全过，构建 0 警告 0 错误。
