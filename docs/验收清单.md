## 一、自动化已验证（结论已确认，无需重跑）

### 1.1 出厂审计：读**编译产物元数据**（不是搜源码）

```powershell
WinAppGuard.SelfCheck.exe --audit ..\src\WinAppGuard\bin\Release\net10.0-windows\win-x64\WinAppGuard.dll
```

| 检查项 | 结论 |
|---|---|
| **零第三方库** | ✅ 引用的 25 个程序集**全部**来自 .NET 框架（`System.*` / `Microsoft.*`） |
| **联网边界受控** | ✅ 网络类型只有 `TcpClient` / `NetworkStream` 两个，**都在预期清单内**；无 `HttpClient` / `Dns` / `SslStream` 等意外类型 |
| **无绕过** | ✅ 没有用 P/Invoke 直接调网络 API（`ws2_32` / `winhttp` / `wininet` / `dnsapi` 均为 0） |
| 原生 API 调用总数 | ✅ **只有 16 个** |
| 注册表访问 | ✅ **完全没有** |
| 文件写入 | ✅ `AppendAllText`（日志）、`WriteAllText` + `Move`（设置文件原子写入） |

**全部原生 API 调用清单**（这是程序能碰到的底层接口的完整列表）：

```
iphlpapi.dll!GetExtendedTcpTable                    读 TCP 连接表
kernel32.dll!OpenProcess                            打开进程（查路径用）
kernel32.dll!QueryFullProcessImageNameW             查进程可执行文件路径
kernel32.dll!CloseHandle                            关句柄
user32.dll!RegisterWindowMessageW                   注册单实例用的自定义消息
user32.dll!PostMessageW                             广播单实例消息
wintrust.dll!WinVerifyTrust                         验证内嵌数字签名
wintrust.dll!CryptCATAdminAcquireContext2           打开目录签名上下文
wintrust.dll!CryptCATAdminCalcHashFromFileHandle2   算文件哈希
wintrust.dll!CryptCATAdminEnumCatalogFromHash       按哈希找所属目录
wintrust.dll!CryptCATCatalogInfoFromContext         取目录文件路径
wintrust.dll!CryptCATAdminReleaseCatalogContext     释放目录上下文
wintrust.dll!CryptCATAdminReleaseContext            释放目录管理上下文
wintrust.dll!WTHelperProvDataFromStateData          从验证状态取数据
wintrust.dll!WTHelperGetProvSignerFromChain         取签名者
wintrust.dll!WTHelperGetProvCertFromChain           取签名者证书
```

> **16 个**（6 个基础 + 10 个签名验证）。除此之外它碰不到任何系统底层。
> 注意：**1.2 没有新增任何原生调用** —— 联网走的是托管 `TcpClient`。

## 二、需要你在虚拟机里手动验证

### A. 联网连接列表

- [ ] A1 启动后表格有数据，**没有任何行被自动选中**，两个操作按钮都是灰的
- [ ] A2 点一行 → 按钮按状态启用，右侧提示显示程序名 / 连接数 / 当前状态
- [ ] A3 四个过滤开关各勾一次，都能看到对应的行冒出来，鼠标悬停有中文说明
- [ ] A4 勾上「每 3 秒自动刷新」，选中一行等 30 秒 → **选中不丢**
- [ ] A5 自动刷新中关掉被选中的程序 → **选中被清空、按钮变灰**，不会跳到第一行
- [ ] A6 勾上「显示监听中」「显示已结束」「显示无进程归属」并取消「隐藏本机回环」，与 `netstat -ano -p tcp` 对比 → 条数接近，**netstat 出现的 PID 一个不少**
- [ ] A7 放大缩小窗口、拖到不同 DPI 的显示器 → 表格正常，文字不模糊

### B. 阻止 / 允许

- [ ] B1 选中一个在联网的程序 → 点「阻止选中程序联网」→ 弹出确认框（**不确认就不生效**）
- [ ] B2 确认框里显示：程序名、**完整路径**、当前连接数、生效范围、**即将创建的规则名**
- [ ] B3 点「取消」→ `wf.msc` 里没有任何变化
- [ ] B4 确认后 → 该行「阻止状态」变「已阻止」，行底色变淡红，状态栏计数 +1
- [ ] B5 打开 `wf.msc` → 规则分组为 `AppGuard`，动作阻止、方向出站、协议任何、配置文件所有
- [ ] B6 **实测拦截效果**：确认该程序**新发起**的连接连不上
- [ ] B7 选中 `svchost.exe` 或 `lsass.exe` → 「阻止」按钮是灰的，提示说明原因
- [ ] B8 在**第 5 行**上点右键 → **第 5 行**被选中（不是上一次选中的行）
- [ ] B9 右键「复制程序路径」→ 剪贴板里是完整路径

### C. 恢复联网（重点：这是用户报过 bug 的地方）

- [ ] C1 阻止 Chrome → 它从「联网连接」页消失（正常现象）
- [ ] C2 切到「规则」页 → **Chrome 一定在这里**
- [ ] C3 选中它 → 点「允许选中程序联网」→ 确认框列出将删除的规则名
- [ ] C4 确认 → Chrome 恢复联网
- [ ] C5 阻止一个程序 → **重启电脑，且不让那个程序运行** → 切到「规则」页，**规则仍在列表里，随时可恢复**
- [ ] C6 点「删除全部 AppGuard 规则」→ **连续弹两次**确认框，第一次列出全部待删规则
- [ ] C7 两次都确认 → `wf.msc` 里 `AppGuard` 规则为 0，**其他规则一条不少**

### D. 托盘

- [ ] D1 托盘出现蓝色盾牌图标，悬停显示程序名
- [ ] D2 点窗口的 X → 窗口消失、**进程还在**、弹一次气泡说明
- [ ] D3 再点一次 X → 仍收托盘，**不再弹气泡**
- [ ] D4 托盘双击 → 窗口回到前台
- [ ] D5 托盘右键 →「退出」→ 确认框写明「**规则依然生效**」
- [ ] D6 退出后开 `wf.msc` → **规则还在，被阻止的程序依然上不了网**
- [ ] D7 关机 / 注销 → **不被拦**，程序正常退出
- [ ] D8 **连续双击 exe 三次** → 窗口回到前台，**托盘只有一个图标**，任务管理器里只有一个进程
- [ ] D9 `WinAppGuard.exe --autostart` → **窗口完全不出现**（连闪都不该有），托盘有图标 + 气泡

### E. 开机自启（本项目唯一写系统持久化配置的地方）

- [ ] E1 「设置」页显示「当前状态：未开启」
- [ ] E2 点「开启开机自启」→ 确认框**逐项列出**将创建的内容（任务名 / 位置 / 程序 / 参数 / 运行级别 / 触发器）
- [ ] E3 确认后 → 状态变绿「已开启」，任务详情和**原始 XML** 都显示出来
- [ ] E4 打开 `taskschd.msc` → 根目录有 `WinAppGuard`，**未勾选「隐藏」**，勾选「使用最高权限运行」
- [ ] E5 任务「触发器」→「登录时」，状态「已启用」
- [ ] E6 任务「操作」→ 程序 = WinAppGuard.exe，参数 = `--autostart`
- [ ] E7 任务「设置」→ **「如果任务运行时间超过以下时间，停止任务」未勾选**（默认 3 天会把常驻托盘的程序杀掉）
- [ ] E8 任务「设置」→ 没有勾选「只有在计算机使用交流电源时才启动」
- [ ] E9 **注销 → 重新登录** → 托盘出现图标，**没有主窗口**，弹一次气泡
- [ ] E10 重启电脑 → 同上
- [ ] E11 自启起来之后再手动启动一次 → 窗口能打开，**不会出现两个托盘图标**
- [ ] E12 点「关闭开机自启」→ 确认框写明「防火墙规则依然有效」→ 确认后任务消失
- [ ] E13 注销 → 重新登录 → **不会**自动启动
- [ ] E14 在 `taskschd.msc` 里**手动删掉**任务 → 回界面点「重新读取状态」→ 显示「未开启」（不能一直显示过期的「已开启」）
- [ ] E15 把 exe 挪到别的目录 → 点「重新读取状态」→ 橙色提示「指向的不是当前程序」

### F. 加固与隐私

- [ ] F1 启动后看 `%LOCALAPPDATA%\WinAppGuard\logs\` → 有日志，第一条是启动记录
- [ ] F2 做一次阻止 / 允许 → 日志里出现对应的「操作」记录

### I. 临时阻断（限时拦截，1.3.0 新增）

- [ ] I1 阻止某个程序时，确认框里有 **4 个时长选项**（永久 / 30 分钟 / 2 小时 / 直到下次重启），**默认选「永久」**

## 三、端到端场景（三个完整故事）

### 场景 1：「我想让某个软件彻底不能联网」

- [ ] 1. 打开 WinAppGuard，在「联网连接」页找到它（或看它正在联网的行）
- [ ] 2. 选中 → 右键 → 阻止该程序联网 → 阅读确认框 → 确认
- [ ] 3. 用它试一下 → 连不上
- [ ] 4. **重启电脑** → 它仍然连不上

### 场景 2：「我后悔了，想恢复」

- [ ] 1. 切到「规则」页
- [ ] 2. 选中它 → 允许选中程序联网 → 确认
- [ ] 3. 立刻就能联网；如果它自己没恢复，重启该程序即可

### 场景 3：「我不想用了，要清理干净」

- [ ] 1. 「规则」页 → 删除全部 AppGuard 规则
- [ ] 2. 「设置」页 → 关闭开机自启
- [ ] 3. 托盘右键 → 退出
- [ ] 4. 删除 `WinAppGuard.exe`
- [ ] 5. （可选）删除 `%LOCALAPPDATA%\WinAppGuard` 目录
- [ ] 6. 打开 `wf.msc` 搜 `AppGuard` → **0 条**
- [ ] 7. 打开 `taskschd.msc` 搜 `WinAppGuard` → **0 条**
- [ ] 8. 重启电脑 → 什么都不再发生
