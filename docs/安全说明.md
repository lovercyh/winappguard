# WinAppGuard 安全说明

本文档回答两个问题：

1. **这个程序会对我的系统做什么？**
2. **我怎么自己验证它确实没做别的？**

每一条都给出**可执行的验证方法**，而不是只说「我们很安全」。

---

## 先跑这一条

如果你只打算做一件事，就跑这个：

```powershell
WinAppGuard.SelfCheck.exe --audit
```

它**不搜源码**，而是直接读**编译出来的程序集的元数据** —— 包括间接引用
和框架自动带进来的东西。输出会告诉你：

```
引用的程序集            27 个，全部来自 .NET 框架    → 零第三方库
网络相关类型引用        2 个：TcpClient / NetworkStream
                        → 都在预期清单内，属于 IP 归属查询
原生 API 调用（P/Invoke）  29 个（17 个 Win32 + 12 个 WFP）
网络相关原生调用        无                          → 没有绕过托管检查直接用网络 API
注册表访问              无
```

那 29 个原生调用就是程序能碰到的**全部**非托管函数，逐条列出来带着用途。
其中 12 个是 WFP 规则引擎的调用（开引擎、建子层、增删枚举过滤器、取程序身份），
全部集中在 `Interop/WfpNativeMethods.cs` 一个文件里，方便逐条核对。

**⚠️ 从 1.2 起，「本程序零网络代码」这句话已经不再成立**：本程序确实有一处联网代码
（IP 归属查询，见下方第 6 条）。所以审计的口径已经从「网络类型必须为零」
改成「**联网边界受控**」：

- 网络类型必须**全部落在预期清单内**（出现 `HttpClient` / `Dns` / `SslStream` 之类会直接判失败）；
- 新增一项**防绕过检查**：不允许用 P/Invoke 直接调 `ws2_32` / `winhttp` / `wininet` 等网络 API
  （只看托管类型的话，那种写法会让审计显示得很干净，但程序照样能联网 —— 那就成了假报告）。

`--audit` 不需要管理员权限 —— 刻意这样设计，好让它能在 CI（无法弹 UAC）里跑。
`--ownership-test` / `--ownership-core-test` 也一样不需要。

## 一、这个程序到底改了什么

WinAppGuard 对系统的全部写入只有三类，**没有第四类**：

| 写什么 | 在哪 | 代码位置 |
|---|---|---|
| WFP 过滤器（出站） | Windows 筛选平台，本工具的**专属子层** | `Core/Wfp/*` |
| 一条计划任务 | 任务计划程序库根目录 | `Core/AutoStartManager.cs` |
| 一个设置文件 | `%LOCALAPPDATA%\WinAppGuard\settings.json` | `Core/AppSettings.cs` |

> 2.0 起**不再使用 Windows 防火墙**：规则全部以 WFP 过滤器的形式落在一个固定 GUID 的
> 专属子层里。它**不出现在 `wf.msc` 里** —— 用界面「黑名单」页或
> `WinAppGuard.SelfCheck.exe --wfp-status` 查看。
> Windows 防火墙自身的设置（是否启用、默认动作、别人的规则）**一个字节都不改**。

> 过滤器可能是「临时」的：阻止时选了 30 分钟 / 2 小时 / 直到下次重启的话，
> 到期后会被**自动删除**。到期时间写在过滤器的**说明字段**里
> （形如 `AppGuard|1|Block|C:\Tools\a.exe|自动解除=2026-10-16T12:42:54Z`），
> 详见下方「临时阻断到期会被自动解除」。

> **严格模式**不再修改任何系统设置：它只是在本进程内建立一个动态 WFP 会话，
> 进程退出（含崩溃、被强杀）时由系统自动删除。详见「二、第 1 条」与
> 下方「严格模式不会改动任何系统设置」。

前两类会**影响系统行为**；第三类只是本机的一个开关记录，里面**只存布尔值**，
不存任何 IP、路径或时间戳（见下方「日志与隐私」）。

除此之外，它只读四样东西：

- TCP 连接表（`GetExtendedTcpTable`）
- 进程的可执行文件路径（`QueryFullProcessImageName`）
- 上述三类配置的当前状态
- 上述设置文件

以及在本机写日志（见下方「日志与隐私」）。

**往外发数据的地方只有一处**：IP 归属查询（`Core/IpOwnershipLookup.cs`），
而且只发远程 IP。它是本项目**主动连接外部主机**的唯一出口（另有 DNS 查询与证书吊销检查，
见第 6 条，都可关闭）——
审计联网行为只需要看这一个文件，这和「防火墙出口只有 `FirewallManager`、
计划任务出口只有 `AutoStartManager`」是同一套约定。

## 二、九条安全约定的实现与验证

### 1. 不修改任何 Windows 防火墙设置（2.0 起连严格模式也不改）

**实现**：2.0 的规则全部落在 WFP 的专属子层里，Windows 防火墙的
「是否启用」「默认入站/出站动作」「别人的规则」**只被读取、从未被写入**。

历史上（1.x）严格模式会改「默认出站动作」，所以文档里留过"唯一例外"的说法。
2.0 把严格模式也换成了 WFP 动态会话：开启 = 建立一个会话内的
「白名单放行 + 阻止全部」，关闭或进程结束 = 系统自动删除。
**它同样一个字节都不写系统设置。**

**自己验证**（不开严格模式、开严格模式，前后各跑一次）：

```powershell
# 三次输出必须完全一致
netsh advfirewall show allprofiles | Select-String "State|Firewall Policy"

# 想连"三套配置文件"一起看：
WinAppGuard.SelfCheck.exe --status
```

想验证严格模式真的"退出即撤销"，跑这个（需要管理员；**只断开未放行程序的网络**，
结束即恢复，不碰系统设置）：

```powershell
WinAppGuard.SelfCheck.exe --strict-mode-test            # 开 / 关 / 放行清单 / 过滤器条数
WinAppGuard.SelfCheck.exe --strict-mode-lifecycle-test  # 白名单变化后重建会话、且不写 1.x 标志
```

---

### 2. 不关闭 Windows 防火墙

**实现**：同第 1 条。代码里不存在写入 `FirewallEnabled` 的路径。

**自己验证**：

```powershell
Get-NetFirewallProfile | Select-Object Name, Enabled, DefaultInboundAction, DefaultOutboundAction
```

---

### 3. 只删除自己子层里的过滤器

**实现**：枚举过滤器时按**子层 GUID** 过滤，只有属于本工具子层
（`6b1f0d2a-8e34-4c77-9f5b-2a7d3c8e1b60`）的才会被列出或删除。
别的软件、系统自带、以及 Windows 防火墙自己的 WFP 对象一概不碰。

**这是硬性代码约束，不是靠调用方自觉**：即使界面有 bug、传进来一个错误的规则名，
`RuleEngine.DeleteRule` 也只会删掉**从自己子层里读出来的那一条**。

**自己验证**：

```powershell
# 操作前后各跑一次，条数必须完全一致（这是 Windows 防火墙的规则数）
(Get-NetFirewallRule | Measure-Object).Count

# 本工具自己的过滤器（在 wf.msc 里看不到，要看这个）
WinAppGuard.SelfCheck.exe --wfp-status
```

自检工具里也有这一项：`--wfp-recover-test` 会先造一条 **Windows 防火墙规则**，
再执行恢复，然后断言那条规则**还在**。

---

### 4. 不阻止系统关键进程

**实现**：保护名单在 `Core/ProtectedProcesses.cs`，检查点在 `FirewallManager.ValidateProgramPath` ——
也就是**规则写入的底层入口**（1.x 兼容层和 2.0 的 `RuleEngine` 都走它），而不是界面层。
界面上的置灰只是体验优化，绕过界面也照样会被拒绝。

名单：`System` / `Idle` / `Registry` / `Memory Compression` /
`smss.exe` `csrss.exe` `wininit.exe` `winlogon.exe` `services.exe` `lsass.exe` `svchost.exe` `dwm.exe` `audiodg.exe` /
`MsMpEng.exe` `NisSrv.exe` `SecurityHealthService.exe`，以及 **WinAppGuard 自身**。

> ⚠️ **这道护栏只管「阻止」，不管「允许」**（1.3 起，见 `ValidateProgramPath` 的 `forBlocking` 参数）。
> 理由有两条：放行永远不会把用户锁在外面；而严格模式**必须**能放行本程序自己
> （否则它自己连 IP 归属都查不了），用户也常常需要主动放行 `svchost.exe` 这类进程。
> 自检里有一条断言专门守着这个方向（"受保护进程可以被允许"）。

**自己验证**：自检工具的完整测试里，这 8 个系统进程 + 自身一共 9 项，**每一项的「阻止」都必须被拒绝**；
另有 1 项反向断言：对它们建「允许」规则是**被接受**的。

`svchost.exe` 特别说明：它承载了 DNS 客户端、DHCP、Windows 更新等大量系统服务，
拦掉它会让整台机器的网络出现难以排查的异常，所以必须保护。

### 5. 所有危险操作必须弹出确认框（**唯一例外：命令行模式**）

**实现**：所有会改动系统状态的操作都走 `Forms/ConfirmForm.cs`。它和 MessageBox 的区别是
**必须结构化地列出**：程序名、完整路径、影响范围、即将创建/删除的规则名，
并用醒目颜色单独列出风险。

需要确认的操作：阻止联网 / 允许联网 / **加入白名单 / 移出白名单** / 删除单条规则 /
删除全部规则 / 开启自启 / 关闭自启 / 退出程序。

另外两处**要求更严**：

- **删除全部规则**：连续确认两次。
- **开启严格模式**：连续确认两次，而且第二次会把**"开启后会上不了网的程序清单"**列出来 ——
  因为这一步会让那些程序立刻断网，用户必须有机会先去放行它们。
  （关闭严格模式是"安全方向"，所以只要一次确认。）

> ⚠️ **唯一例外：命令行模式**（`--block` / `--unblock-all`）。
> 无人值守的脚本没法弹确认框 —— 弹了自动化就无从谈起。所以 CLI 的约定是
> **「命令行参数本身就是明确指令」**（和 netsh 那类工具的习惯一致），并有三道补偿：
>
> 1. 程序要求管理员权限（未提权时 Windows 会先弹 UAC）；
> 2. 唯一不可逆的批量操作 `--unblock-all` **必须再加 `--yes`**，否则只打印清单、什么都不删；
> 3. 每条命令都**逐条打印**它做了什么，并给出明确的退出码（0/1/2/3）。
>
> **图形界面里的操作一条都没放宽** —— 那边照旧每条都要确认。
> 详见下方「命令行模式没有确认框（这是有意的）」一节。

> **临时阻断的「事先同意」**：阻止联网时，确认框里还会让你选**阻断时长**
> （永久 / 30 分钟 / 2 小时 / 直到下次重启）。选限时的话，规则到期会被
> **自动删除** —— 而自动删除没法再弹一次确认框（弹了后台程序就永远解不开），
> 所以这个确认框就是你**事先同意**的地方：它会写清「规则会在几点几分自动解除」。
> 详见下方「临时阻断到期会被自动解除」一节。

> **严格模式的「事先同意」在此不再需要**：2.0 的严格模式不改任何系统设置，
> 进程退出即自动撤销，不存在"需要还原却弹不了框"的情形。

**自己验证**：随便点一个操作，确认框会先出现；点「取消」后 `wf.msc` 或 `taskschd.msc` 里不应有任何变化。

> 已确认保留的行为：确认框上按回车**会**确认。这是产品负责人明确选择保留的（符合 Windows 用户普遍预期）。

### 6. 往外发的数据只有三类，都可以关掉

本程序有且只有两处会产生网络流量，**两者默认都开启、也都能在「设置 → 数据与隐私」里关掉**：

| | 联网由谁发起 | 发什么 | 发给谁 | 代码位置 |
|---|---|---|---|---|
| **6.1** | **本程序自己的代码** | 远程 IP（不含任何其它本机信息） | `whois.cymru.com:43` | `Core/IpOwnershipLookup.cs` |
| **6.2** | Windows 的证书服务（本程序只是调用 `WinVerifyTrust`） | 证书吊销查询 | 该证书的 CA 服务器 | 不是我们的代码 |
| **6.3** | **本程序自己的代码**（仅在「记录 → 域名推测」开启时） | DNS 查询（只查系统缓存里已有的名字） | **本机配置的 DNS 服务器** | `Core/Audit/DnsCacheReader.cs` |

两处都关掉之后，本程序**不再产生任何网络流量**。

> **⚠️ 一句必须说清的更正**：1.1 及更早的版本确实「自身不含网络代码」。
> 1.2 加入 IP 归属查询后，这句话**不再成立** —— 所以本文档改成上面这张表，
> 而不是继续含糊下去。

#### 6.1 IP 归属查询会联网（默认开启）

用来在「联网连接」页显示每个远程 IP 的归属（国家/地区、运营商 AS），
好让你判断「这个连接在跟谁通信」。

- **发给谁**：只连 `whois.cymru.com:43` 这一个固定地址（Team Cymru 的 WHOIS 服务）。
- **发什么**：只发远程 IP 字符串。不发进程名、程序路径、PID、端口，或任何其它本机信息。
- **不发什么**：局域网、回环、链路本地、`0.0.0.0` 这类地址**在发送之前就被过滤掉了**，
  根本不会出本机。
- **一个必须说清的细节**：按主机名连接时，.NET 运行时会先对 `whois.cymru.com`
  做一次 DNS 解析。这不是 HTTP 请求，但确实是一次额外的域名查询。

**怎么关掉**：「设置 → 数据与隐私」→ 取消勾选「查询 IP 归属」。
关闭是**持久生效**的（记在 `settings.json` 里），重启不会自己打开。

**自己验证**：

```powershell
# 1) 打开资源监视器 → 网络 → 找 WinAppGuard.exe
#    勾选时：能看到它连 whois.cymru.com:43
#    取消勾选后：完全消失
# 2) 或者跑自检工具，它会打印真实结果：
#    .\dist-tools\WinAppGuard.SelfCheck.exe --ownership-test
#    输出里标「本地拦截」的地址，就是没有发出去的
# 3) 看源码里联网类型出现在哪（应当只有唯一那个出口）：
Select-String -Path .\src\WinAppGuard\**\*.cs -Pattern 'TcpClient|NetworkStream'
```

#### 6.2 证书吊销检查会联网（默认开启）
「数字签名」这一列默认会检查证书吊销状态。此时 **Windows 的证书服务（Crypt32）
会代表本程序去联系 CA 服务器**查询 CRL / OCSP。在资源监视器里，这些连接**记在
`WinAppGuard.exe` 名下** —— 虽然不是本程序的代码发起的，但从观察者的角度看是一样的。

**为什么这么设计**：不查吊销的话，一张已经被吊销的证书仍会被判定为「签名有效」，
结论不可靠。

**怎么关掉**：「设置 → 数据与隐私」→ 取消勾选「检查证书吊销状态」。
关掉之后使用 `WTD_CACHE_ONLY_URL_RETRIEVAL`，只读本机缓存，**完全不留任何网络流量**。

#### 6.3 域名推测会查 DNS（默认开启）

「记录」页的「域名（推测）」来自 **Windows 的 DNS 客户端缓存**（不是抓包）。读取有两种模式：

| 模式 | 行为 | 覆盖率（实测） |
|---|---|---|
| **缓存优先（默认）** | 缓存里有就直接用；条目刚好过期时，Windows 会向**本机配置的 DNS 服务器**补发一次查询 | 约 **29%** 的连接能带上域名 |
| **关闭「域名推测」** | 只用 `DNS_QUERY_NO_WIRE_QUERY`，**绝不发包** | 约 **8%** |

**边界**（这些必须知道）：

- 程序**只查缓存表里已经存在的名字**，不会主动解析任意域名 —— 它也不知道你想查什么；
- 浏览器自己开 DoH（加密 DNS）时，查询根本不进系统缓存 → 那一列显示「未知」，任何纯用户态工具都看不到；
- 一个 IP 可能对应多个域名（CDN），此时会列出多个候选并标注"不唯一"；
- 域名**永远只作参考**，不会被用来做任何自动决策（2.3 的域名黑名单也必须先解析成 IP 才落地）。

**怎么关掉**：「记录」页取消勾选「域名推测（会向本机 DNS 服务器发查询）」。关闭后本程序**不再发任何 DNS 查询**。

**自己验证**：

```powershell
# 1) 打开资源监视器 → 网络 → 在「网络活动」里找 WinAppGuard.exe
#    设置页勾选吊销检查时：能看到它连接 CA 服务器
#    取消勾选后：完全消失
# 2) 或者用抓包工具按进程过滤，观察同样的差异
```

### 7. 不在运行时调用任何在线服务（含 AI 接口）

**实现**：本程序运行时只访问 `whois.cymru.com:43` 这一个外部服务（第 6.1 条，可关闭），
**不调用任何其它在线服务** —— 没有遥测、没有更新检查、没有崩溃上报，
也没有任何 AI 接口。DeepSeek 只参与了开发阶段写代码，最终产物里不含任何相关调用。

**自己验证**：同第 6 条；另外可搜索源码确认没有任何 HTTP / API 调用：

```powershell
Select-String -Path .\src -Pattern 'api\.|token|apiKey|Authorization|HttpClient' -CaseSensitive:$false
```

### 8. 开机自启必须透明可见

**实现**（四层透明）：

| 层面 | 做法 |
|---|---|
| 命名 | 任务名固定 `WinAppGuard`，**不是随机名**，放在任务计划程序库根目录 |
| 不隐藏 | 任务**没有**勾选「隐藏」；代码里也没有写 `<Hidden>` |
| 界面可见 | 「设置」页直接显示任务的**原始 XML**，看到的就是系统里实际存的东西 |
| 状态真实 | 状态每次都是**实时读取**系统；你在 `taskschd.msc` 里手动删掉，界面点「重新读取状态」立刻变回「未开启」 |

**自己验证**：

1. 打开 `taskschd.msc` → 任务计划程序库 → 找到 `WinAppGuard`；
2. 右键 →「属性」→ 逐个标签核对（界面上的 XML 应该和这里完全对得上）；
3. 「常规」标签里「隐藏」**必须未勾选**。

### 9. 用户必须能关闭开机自启

**实现**：「设置」页的「关闭开机自启」按钮，一次确认后删除任务。
另外**用户也可以完全绕过本程序**，直接打开 `taskschd.msc` 手动删除这条任务 —— 程序不会阻止、也不会重新创建。

**自己验证**：

1. 点「关闭开机自启」→ 任务从 `taskschd.msc` 消失；
2. 注销 → 重新登录 → 不会自动启动；
3. 再手动在 `taskschd.msc` 里删掉任务后回到界面点「重新读取状态」→ 显示「未开启」。

> **同一原则也适用于联网查询**：1.2 加入的 IP 归属查询默认开启，但它同样
> 必须能关、且关得住 —— 见下方第 6.1 条（关掉后零流量，且重启不会自己打开）。

## 三、其它风险提示

### 命令行模式没有确认框（这是有意的）

`WinAppGuard.exe --block "…"` / `--list-blocked` / `--unblock-all [--yes]` 都**不弹确认框** ——
否则脚本化、批量部署就无从谈起。补偿措施见「二、第 5 条」：需要管理员权限、
`--unblock-all` 必须加 `--yes`（否则只预览不删）、逐条打印 + 明确退出码（0/1/2/3）。

**它和图形界面用的是同一套底层**（`Core/FirewallManager.cs`），所以那几条护栏一条都没少：
只碰 `AppGuard_` 前缀的规则、受保护进程（含本程序自己）拒绝**阻止**、不覆盖别人的规则。

**图形界面启动时会先出现一个控制台窗口。** 本程序是**控制台子系统**的 exe ——
这样命令行模式才能同步输出、退出码才对（图形界面程序 Windows 的 shell 不会等，
实测过命令会并发、`$LASTEXITCODE` 拿不到）。没有命令行指令时，程序会立刻调用
`FreeConsole` 把它收掉。

实测代价：稳态约 **0.5 秒**；发布后**第一次**运行因为杀毒软件要扫这个 49MB 的新文件，
可能**几秒到十几秒**。产品负责人在虚拟机里实测后认可了这个取舍。

### 严格模式不会改动任何系统设置（它只在进程内生效）

「设置 → 严格模式（高级）」开启后，本工具在**自己的进程里**建立一个动态 WFP 会话：
白名单程序的放行过滤器（高权重）压住一条「阻止全部」（低权重）。
于是**只有白名单能上网**，而 Windows 防火墙、注册表、系统策略**一个字节都没改**。

**撤销方式只有一种，而且不需要本程序参与**：会话结束。程序正常退出、崩溃、
被任务管理器强杀，效果都一样 —— BFE 会把会话内的对象全部删掉
（POC 实测：强杀后过滤器 0 条、连接恢复）。

**自己验证**：

1. 开启严格模式后跑 `WinAppGuard.SelfCheck.exe --status`：三套配置文件的默认出站动作
   **仍然是「允许」**（1.x 时代这里会变成「阻止」）；
2. 找一个没加白名单的程序让它联网 → 应当连不上；
3. 把它加入白名单 → 会话会**立即重建**，应当马上能连上；
4. 严格模式开着时，**用任务管理器直接结束 `WinAppGuard.exe`** → 网络立刻恢复，
   不需要重新打开程序、也不需要点任何「还原」。

**必须知道的三条边界**（这三条我们不掩饰）：

| 限制 | 说明 |
|---|---|
| **程序没在运行时严格模式不生效** | 它是**会话级**的：限制只存在于本进程的动态会话里。这不是缺陷，而是"崩溃也不会把用户锁在断网状态"的实现方式。 |
| **它是真白名单，所以必须内置一份系统放行清单** | 2.0 的 block 压得过 Windows 防火墙的 allow，不显式放行的话连 DNS、时间同步、Windows 更新都会被挡掉。内置清单放行 `svchost.exe`（DNS / DHCP / NTP / 更新的宿主）、`lsass` / `services` / `wininit`、Defender 平台程序。⚠️ 副作用：宿主在 svchost 里的第三方服务会被一并放行 —— 这是 Windows 的进程模型决定的。 |
| **以前"被别的软件放行过"的程序不再有豁免** | 1.x 的白名单是"叠加在 Windows 防火墙之上的默认阻止"，别人放行过的程序照样能上网。2.0 是**真白名单**：没进白名单就没网。连接列表的「已放行·其它来源」现在只作参考，不再代表"能上网"。 |

**为什么"开启"要确认两次**：这一步会让没有白名单的程序立刻断网，而用户手上可能正开着
浏览器、正连着 VPN。所以第一次讲清后果，第二次把**具体会被影响的程序清单**摊开 ——
如果他发现清单里有自己要用的程序，可以取消、先去加白名单、再回来开启。

### 临时阻断到期会被自动解除（含限制）

阻止程序联网时，确认框里可以选**阻断时长**：
**永久**（默认）/ **30 分钟** / **2 小时** / **直到下次重启**。

选限时的话，规则到期后会被**自动删除**，被拦的程序随之恢复联网，并弹一次托盘气泡告知。

**为什么"自动删除"也需要你同意**：项目的硬性约定是「所有会改系统状态的操作必须弹确认框」。
但自动删除没法再弹框（真弹了，后台程序就永远解不开），所以把「事先同意」放在**创建时**——
确认框里会写清「规则会在几点几分自动解除」。

**自己验证**：

1. 阻止某个程序时选「30 分钟」，确认框里应当出现一句
   「限时：规则会在 HH:mm 自动解除……」；
2. 「规则」页会多出一列「自动解除」，显示「剩余 X 分钟」；
3. 界面「黑名单」页的「自动解除」列会显示剩余时间；
   或跑 `WinAppGuard.SelfCheck.exe --wfp-status`，规则行里带着 `[剩余 X 分钟]`。

**三条必须知道的限制**：

| 限制 | 说明 |
|---|---|
| **本程序退出后不会再清理** | Windows 防火墙没有「定时规则」这种能力，必须有程序在运行才能清理。所以你从托盘退出后，「30 分钟后解除」不会发生，要等程序再次运行。 |
| **「直到下次重启」在开启开机自启时最可靠** | 它靠两个信号判断：①本次进程是「登录触发的自启」拉起的；②开机时刻变了。**没开自启**又用了「关机 → 开机」（Windows 快速启动）时，系统不会重置开机时长，本工具就判断不出「重启过」，规则会一直留着 —— 这种情况请手动解除，或者改用「30 分钟 / 2 小时」。 |
| **5 分钟容差** | 判断「开机时刻变了」时留了 5 分钟容差（休眠、时钟校准会让推算值漂移）。宁可偶尔提前解除，也不要让规则卡住不动。**时钟被大幅改动时可能提前解除。** |

> **一个刻意的取舍**：要完全消除第 2 条限制，只能去查 WMI 或事件日志，那会引入额外依赖。
> 本项目坚持**零第三方依赖**（`--audit` 会验证这一点），所以选择把限制**如实写清楚**，
> 而不是为了一个边角情形引入依赖。

### 提权持久化会被安全软件关注（已知现象）

「计划任务 + 最高权限 + 登录时触发」这个组合在技术上等同于提权持久化，
杀毒软件和 EDR 可能会给出提示。这是**机制本身的性质**，不是本程序做了什么隐蔽的事。
所有内容都可见、可删，见上方第 8、9 条。

### 未签名的 exe 会被 SmartScreen 拦截

发布出来的 exe 没有代码签名，Windows 首次运行会提示「未知发布者」。
要消除这个提示需要购买代码签名证书，这属于发布流程之外的事情。

### 阻止规则按「可执行文件路径」生效

WFP 的过滤器不支持按 PID 拦截（PID 会被复用）。所以程序规则按可执行文件路径匹配：

- 同一个 exe 开多个实例、带不同参数，会被**一起**拦掉；
- 同一个程序换到别的目录运行，**不受影响**；
- 程序更新后如果安装路径变了，旧规则会失效，需要重新设置。

**另有一类「封禁 IP」规则**（2.1 新增）：按**远端 IP** 拦截（IPv4 / IPv6），不经过域名解析。
它拦的是 IP 本身，所以：

- 同一个 IP 上的其它服务**会一起被拦**（共享主机 / CDN）；
- 大网站会更换 IP，封一个 IP 不一定能封住整个网站；
- 规则名形如 `AppGuard_BlockIp_1.2.3.4`，删除规则即解除。

### 「退出程序」不等于「放行程序」

关掉界面（包括从托盘退出）**不会**删除任何防火墙规则，被阻止的程序依然上不了网。
托盘退出时的确认框会明确写出这一点。
要放行，必须用「解除阻止（允许联网）」或「删除全部 AppGuard 规则」。

## 四、日志与隐私

### 记什么

| 级别 | 内容 |
|---|---|
| `信息` | 启动（版本 / 是否有管理员权限 / 启动模式）、退出 |
| `操作` | 阻止联网、允许联网、删除规则、开关开机自启（含目标程序路径和规则名） |
| `警告` | 未以管理员身份运行等 |
| `错误` | 各操作失败的原因和堆栈 |

**不记录**每次扫描到的连接明细 —— 连接列表每 3 秒刷新一次，把明细写进去会迅速撑爆文件，而且没有价值。

### 写在哪

```
%LOCALAPPDATA%\WinAppGuard\logs\winappguard-yyyyMMdd.log
```

- 按天分文件，**只保留最近 7 天**，更早的自动删除；
- 「设置」页里直接显示这个路径，并提供「打开日志目录」按钮；
- **日志只写本机，不会发送到任何地方**；IP 归属查询也**不会**把日志内容发出去。

### 设置文件

```
%LOCALAPPDATA%\WinAppGuard\settings.json
```

本程序有两个**只在本机**的状态文件：

- `settings.json` —— 开关状态（**只存布尔值**）；
- `ui-state.json` —— 窗口大小/位置与列宽（2.1.1 起），**只有尺寸和列宽**。

`settings.json` 里不存 IP、不存进程名、不存路径、不存时间戳 —— 它是设置，不是历史记录。

- 写入采用「先写临时文件再改名」，中途断电也不会留下半个文件把设置弄丢；
- 文件损坏或缺失时会回落到默认值，**不会因此报错**；
- 删掉它 = 恢复默认（IP 归属查询会重新变成开启）。

> 为什么需要这个文件：IP 归属查询默认开启。如果开关不落盘，
> 你关掉之后重启程序又会被自动打开 —— 你对隐私的选择被静默回滚，那是缺陷不是取舍。

### 界面状态文件（2.1.1 新增）

```
%LOCALAPPDATA%\WinAppGuard\ui-state.json
```

只是为了让你下次打开时窗口还是原来的大小、列宽还是你拖好的样子。

- 里面只有：**窗口宽高、屏幕坐标、是否最大化、各列宽度**；
- **不含**程序名、路径、IP、域名或任何时间戳；
- 坐标落在屏幕外（比如上次在副屏关闭、这次副屏拔了）时会**自动忽略**，
  不会把窗口卡在看不见的地方；
- 删掉它 = 回到默认布局。

### 想彻底清干净？

关闭开机自启 → 退出程序 → 跑一条命令：

```powershell
WinAppGuard.exe --recover
```

它会清掉三样东西：本工具在 WFP 里的过滤器与子层、1.x 遗留的全局默认阻止、
以及 1.x 遗留的 `AppGuard_*` 防火墙规则。然后删掉 `%LOCALAPPDATA%\WinAppGuard` 目录即可，
系统里不会残留任何东西。

## 五、完整的卸载步骤

```
1. 打开 WinAppGuard
2. 「黑名单」页 → 清空黑名单（或者跑：WinAppGuard.exe --recover）
3. 「设置」页 → 关闭开机自启
4. 托盘右键 → 退出
5. 删除 WinAppGuard.exe
6. （可选）删除 %LOCALAPPDATA%\WinAppGuard 目录（只剩日志）
```

第 2、3 步不做就直接删 exe 的话，过滤器子层和计划任务会**留在系统里继续生效**。
真遇到这种情况，跑 `WinAppGuard.exe --recover`（它会删掉本工具在 WFP 里的全部对象）
和 `WinAppGuard.SelfCheck.exe --autostart-disable` 即可。
