# 5.9 架构统一实施

> 状态：进行中
> 分支：`arch/5.9`
> 目标：把 12 个相似但不相同的检测子系统收敛成“一套特性框架 + 各特性策略”。
> 边界：5.9 不改跨进程协议；协议 v3 放到 5.10。

## 1. 已确认的决策

- 5.9 做完整架构统一，不按“只做地基”缩小范围。
- 旧数据必须可读；状态文件只允许“读旧写新 + 迁移”，不允许静默清空。
- dev-only 测试使用 xUnit；真实 UI / WFP / 服务 / CLI 仍由 SelfCheck 验收。
- 5.8 的 `guard.new-program.*` 是独立权限策略 `OwnerTemporaryWfp`，不能归入 Read / Write / Alert。
- 后台检测（新程序提醒、默认阻止、IDS 通知）与 UI 可见页刷新分离。
- 5.9 内完成内部模块/存储/页面统一；协议 v3、信封化跨进程载荷在 5.10 完成。
- 完成前不 push main、不打 tag；保留 `v5.8` 作为回滚点。

## 2. 阶段

### 阶段 0：基建与测试骨架（已完成）

- `ErrorCode` / `Result<T>`
- `CommandPolicy` / `CommandPolicyTable`
- `JsonStateFile<T>` / `JsonlEventLog<T>`
- `FeatureEvent` / `FeatureSettings`
- `ExpiringBlockRegistry<TKey>`
- `Baseline<T>`
- `IClock`
- dev-only xUnit 测试工程
- CI 增加架构测试

完成标准：新增代码有测试，旧代码零行为改动，构建 0 警告。

### 阶段 1：命令策略与路由（已完成）

- `ICommandHandler` / `CommandRouter` / `ServiceCatalog`
- `ServiceCatalog` 逐条登记全部协议命令，`ControlServer.Dispatch` 不再保留大 switch
- 启动期 `Validate()` 校验：声明命令恰好一个 Handler、无协议外 Handler、策略显式、只有 guard 命令允许 `OwnerTemporaryWfp`
- `auth.challenge` 仍由握手流程单独处理；路由层保留防御性拒绝
- 仍使用协议 v2 的 `ServiceRequest/ServiceResponse`

完成标准：全部命令经路由分发；`CommandPolicyGuard` 的提权/告警/新程序例外行为与 5.8 一致。

### 阶段 2：存储/事件/设置迁移

- IDS 作为第一个全链路样板
- 旧状态文件迁移器与 fixture
- 安全敏感文件（OwnerKey / 受保护模式 / WFP DACL 标记）保持专用实现

### 阶段 3：服务模块化

- `IServiceModule` / `ModuleHost`
- 14 个 Host 收敛为 12 个 Module
- 健康状态、启动顺序、失败隔离、重启策略
- 新程序默认阻止模块保留“无 UAC 临时 WFP”例外

### 阶段 4：UI 网关与页面统一

- `IApplicationGateway`
- `PageBase` / `UiRefreshScheduler`
- `EventTable<T>` / `BlockTable` / `BaselineTable`
- 保留 5.6 滚动修复、5.7 导出/汇总/诊断包、5.8 默认阻止弹窗
- 后台定时器不交给可见页调度器

### 阶段 5：收口

- 删除旧 Host / 旧 StateStore / 旧重复实现
- 全量 SelfCheck + 架构测试 + VM 验收
- 版本 5.9
- 本地提交，等你批准后 push / tag / Release

## 3. 兼容性硬约束

- 旧 `state.json`、事件 `.jsonl`、`settings.json`、`first-seen-programs.json` 必须可读。
- 坏文件保留 `.corrupt-*`，不静默覆盖。
- CLI `--json` 字段与退出码保持兼容。
- 5.8 的临时阻止释放、删除记录后重新弹窗、全部已读必须回归通过。
- WFP 权重、DACL、严格模式、OwnerKey 的行为不得改变。
