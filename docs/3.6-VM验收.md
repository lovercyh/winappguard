## 1. 准备

1. 把整个 `默认项目` 文件夹复制到 VM。
2. 管理员运行安装/修复：

   ```powershell
   cd C:\Users\VM\Downloads\默认项目\dist
   .\WinAppGuardSetup.exe --install
   ```

3. 确认版本：

   ```powershell
   (Get-Item 'C:\Program Files\WinAppGuard\WinAppGuard.exe').VersionInfo.ProductVersion
   (Get-Item 'C:\Program Files\WinAppGuard\WinAppGuardSvc.exe').VersionInfo.ProductVersion
   ```

   应为 `3.6+*`。

## 2. 自动检查

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
powershell -ExecutionPolicy Bypass -File .\3.6-验收脚本.ps1
```

脚本按顺序执行：

1. 版本 / 安装包一致性；
2. 重启服务；
3. `--traffic-records-test`（离线：排序 / 搜索 / 未知路径 / 合计）；
4. `--etw-network-test`（独立 ETW）；
5. `--service-35-test`（3.5 流量 + DNS 回归）；
6. `--service-lockdown-test`（临时锁网）；
7. `--service-traffic-clear-test`（清空流量统计，**放在最后**）；
8. ETW 会话与服务日志检查。

## 3. 人工检查：流量页

1. 打开「流量」页，确认顶部显示：
   `统计自 …（服务本次运行） · 共 N 个程序 · 合计 上传 … / 下载 …`。
2. 同时用两个程序下载（例如浏览器 + PowerShell `Invoke-WebRequest`）。
3. 等待 3–5 秒，确认两个程序各自出现一行，且总量会增长。
4. 依次点击表头：

   - 总计：从大到小 / 从小到大；
   - 上传 / 下载：数值排序；
   - 最后活动：时间排序；
   - 程序 / 路径：名称排序；
   - 确认表头箭头方向与顺序一致。

5. 在搜索框输入程序名片段、再输入路径片段，确认只显示匹配行。
6. 关闭其中一个下载程序，确认它的记录仍在，最后活动时间不再变化。
7. 点「清空…」：

   - 应弹一次管理员授权；
   - 确认后表格清空、统计起点更新；
   - 托盘提示「流量统计已清空」。

8. 重新产生一点流量，然后重启服务：

   ```powershell
   Restart-Service WinAppGuardSvc -Force
   ```

   重新打开流量页，确认程序数从 0 开始、统计起点更新。

## 5. 已知边界（不是失败）

- 只统计**服务本次运行**；重启服务或点清空后从 0 开始，不写盘；
- 流量是 ETW 近似值，短连接可能漏计；
- 路径拿不到时按 PID 显示；
- 同一路径的多个实例合并为一行，不区分 PID。
