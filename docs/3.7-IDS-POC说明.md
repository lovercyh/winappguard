# 3.7 IDS POC 说明（VM）

> 目的：在写产品代码之前，用实测数字回答「用户态 flow IDS 是否值得做、CPU/误报能不能接受」。
> 只在验收 VM 上跑；POC 只读采集 + 本机合成流量，不阻断、不改防火墙。

## 0. 文件

`dist-tools\WinAppGuard.IdsPoc.exe`（单个 exe，36 MB 左右）。

`publish.ps1` 不会自动构建它；本次已经手动同步到 `dist-tools`。

## 1. 合成场景自检

管理员 PowerShell：

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
.\WinAppGuard.IdsPoc.exe --selftest
```

它会依次生成：

- beacon：每 2 秒连接本机回环端口，共 8 次；
- scan：连接 127.0.0.2–127.0.0.16，以及 15 个关闭端口；
- lateral：尝试本机内网网段 6 个地址的 445/3389/5985；
- DNS：查询 30 个随机长域名（`.invalid`）；
- upload：向回环发送 12 MiB。

合计约 30–40 秒。

请记录完整输出，重点：

| 项 | 期望 |
|---|---|
| 时长 | ~30–40 秒 |
| 事件明细 | TCP/UDP 收发、连接事件都有数 |
| flow 峰值 | 小于 20k |
| CPU 平均/峰值 | 目标 <5% |
| 内存峰值 | 目标 <50 MB |
| 告警 | beaconing / scan / lateral / dns / exfil 都应命中 |

如果某条规则**未命中**，把输出贴回来；我先调阈值/解析，不急着写产品。

## 2. 正常使用误报观察

管理员 PowerShell：

```powershell
.\WinAppGuard.IdsPoc.exe --monitor 600
```

运行期间正常使用 10 分钟：

- 浏览网页、看视频；
- 下载一个大文件；
- 打开 Teams / 微信 / 网盘之类的常驻程序；
- 不要运行扫描/beacon 脚本。

记录：

- CPU 平均/峰值、内存峰值；
- flow 峰值、事件总数；
- **是否出现误报**；每条误报的规则、进程、目标、证据。

判定（建议）：

- 0 个高严重度误报；
- 中严重度 ≤2 条/小时；
- CPU <5%，内存 <50 MB。

达不到就缩小规则范围或调整阈值，不硬上。

## 3. 需要回传

把两段完整输出贴回来即可：

1. `--selftest` 的「===== POC 结果 =====」和告警列表；
2. `--monitor 600` 的同样的汇总和告警列表。

不用上传任何抓包/ETL；POC 不写文件，只在控制台输出。

## 4. 边界

- POC 只看连接元数据和 DNS 域名，不解析载荷、不做 DPI/HTTPS 解密；
- `--selftest` 只连本机/回环/本机内网网段，不对外扫描；
- 如果 ETW 启动失败，通常是没提权；用管理员 PowerShell 重跑；
- POC 与服务可同时运行（会话名不同），但合成流量也会被服务的流量页统计到，属于正常现象。
