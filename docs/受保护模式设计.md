# 3.1 受保护模式设计（Owner + ECDSA + DPAPI）

> 状态：第 2 步（密钥存储 + 安装器生命周期）已实现并通过 VM 验收（2026-10-23）；协议/服务鉴权尚未接入。
> 版本：3.1。
> 本文只描述设计，不代表代码已完成。

---

## 1. 目标

- **单所有者**：只有执行安装的那个账户（UAC 提权后的当前账户）能使用服务；
- 其他本地账户（包括其他管理员账号）**连查看都拒绝**；
- 服务只保存**公钥**；私钥用 **DPAPI 用户级**加密，只有所有者能解密；
- 所有 IPC 请求都要 **ECDSA P-256 签名**，防篡改、防重放；
- 密钥生命周期可验证：卸载彻底删除、重装生成全新密钥、升级/修复保留；
- 关键操作留痕：谁连接、谁被拒、谁改了什么。

## 2. 非目标（明确不做）

- **不防**能 dump LSASS、偷所有者令牌、注入所有者进程、替换服务二进制、直接操作 WFP 的本机管理员；
- 不防物理取证（SSD 磨损均衡、卷影副本、页面文件、崩溃转储）；
- 3.1 **不收紧 WFP 对象自身的 DACL**：其他管理员直接删过滤器仍可能，现有「篡改防护」会重建并记录；该收紧放到 3.2；
- 不做多所有者、首次运行绑定、PPL、内核驱动、代码签名。

> 一句话：3.1 保护的是**服务入口**，不是整台机器。管理员仍然可以让保护失效（停服务/杀进程/直接删规则），但不能再“悄悄用服务改规则”。

---

## 3. 所有者与安装

### 3.1 定义

**所有者 = 运行 `WinAppGuardSetup.exe` 的提权账户**（UAC 之后的当前进程身份）。

- 正常 UAC（登录用户自己提权）：所有者就是日常用户；
- 借用其他管理员账户提权（over-the-shoulder）：所有者是那个管理员；
- **标准用户不能成为所有者**：标准用户无法以自己身份运行提权安装器。

### 3.2 跨账户处理

安装器比较：

- 当前进程账户（`WindowsIdentity.GetCurrent().User`）；
- 当前交互会话账户（`WTSQuerySessionInformation`，取用户名/域并解析为 SID）。

| 情况 | 行为 |
|---|---|
| 相同 | 直接安装 |
| 不同 | **默认取消安装**，提示“之后只有提权账户能使用界面”；加 `--allow-owner-mismatch` 才继续（所有者=提权账户） |
| 无法检测会话账户 | 记日志，按“相同”处理 |

`--repair` 保留现有所有者与密钥，不弹选择；如果当前账户不是所有者，明确提示“修复不会改变所有者，当前账户仍无法使用界面”。

### 3.3 恢复

| 命令 | 作用 |
|---|---|
| `--reset-owner` | 以当前账户为新所有者：删除旧密钥、重建 ACL/服务 DACL、重启服务 |
| `--rotate-key` | 同一所有者换新密钥；旧 blob 删除 |
| `--repair` | 只换二进制，**不动**密钥与所有者 |

`--reset-owner` 与“另一个管理员强制接管”都依赖管理员权限；文档不承诺防住这种接管。

## 4. 密钥与文件

### 4.1 文件

| 路径 | 内容 |
|---|---|
| `%ProgramData%\WinAppGuard\protected-mode\config.json` | 版本、所有者 SID、公钥（SPKI Base64）、entropy（Base64）、公钥指纹、创建时间 |
| `%ProgramData%\WinAppGuard\protected-mode\client-key.dpapi` | ECDSA 私钥（PKCS#8）经 DPAPI 用户级加密后的二进制 |

### 4.2 ACL

`protected-mode` **目录**和两个文件都关闭继承：

- `SYSTEM`：完全控制；
- **所有者 SID**：完全控制（安装器轮换/删除需要；界面日常只读）；
- **不添加 Administrators 组**、不添加 Users/INTERACTIVE。

父目录 `%ProgramData%\WinAppGuard` 保持 Users 可读（用于规则快照/审计）；
`protected-mode` 子目录有独立 DACL，父目录的继承 ACE 不会进去。
管理员仍然可以夺取所有权（Windows 固有规则），文档如实说明。

### 4.3 密码学

- 曲线：ECDSA **P-256**；
- 签名：`ECDsa.SignData(data, SHA256)`（DER 编码）；
- 私钥格式：PKCS#8；
- 公钥格式：SubjectPublicKeyInfo（SPKI）；
- DPAPI：`CryptProtectData` / `CryptUnprotectData`，**用户级**（不带 `CRYPTPROTECT_LOCAL_MACHINE`），`CRYPTPROTECT_UI_FORBIDDEN`；
- entropy：安装时生成 32 字节随机数，存 `protected-mode\config.json`（非机密，用于绑定安装实例）；
- 私钥只在 UI/助手内存中解密，用后 `CryptographicOperations.ZeroMemory`；
- **服务端从不解密私钥**，只持公钥验签；
- 日志/临时文件/注册表**绝不出现私钥或 DPAPI blob**。

### 4.4 指纹

`SHA-256(SPKI 公钥)` 的十六进制前 16 位作为“密钥指纹”：

- 写入 `protected-mode\config.json`、服务日志、设置页；
- 用于确认“还是同一把钥匙”，不是秘密。

## 5. 生命周期

| 事件 | 密钥/所有者行为 |
|---|---|
| **首次安装（同账户）** | 生成密钥对 → DPAPI 加密 → 写两个文件 → 设置 ACL → 安装后签名自检 |
| **跨账户安装** | 默认取消；`--allow-owner-mismatch` 继续，所有者=提权账户 |
| **`--repair` / 3.0→3.1 升级** | 保留现有密钥与所有者；只换二进制 |
| **服务已安装但配置缺失/损坏** | 修复时以当前账户为新所有者重建，日志明确；或由所有者 `--reset-owner` |
| **卸载** | 删除两个文件并**校验不存在**；删不掉登记重启删除 |
| **`--keep-data`** | 保留规则/记录/设置，但**始终删除密钥与所有者配置** |
| **卸载后重装** | 服务不存在 → 清理残留 → **生成全新密钥**（指纹必须不同） |
| **卸载不完整（服务已删、密钥还在）** | 安装器检测残留 → 清理 → 新建 |
| **`--rotate-key`** | 同一所有者生成新密钥；旧 blob 删除；服务重启 |
| **`--reset-owner`** | 新所有者、新密钥、重建 ACL/服务 DACL |
| **用户密码被管理员重置** | DPAPI 解不开 → 界面提示 `--rotate-key`；不静默失败 |

### 5.1 安装后自检

服务启动后，安装器（所有者身份）用新密钥签名调用一次 `status`：

- 必须 `Ok=true`；
- `Status.ProtectedMode=true`；
- `Status.OwnerSid` 与配置一致；
- 失败则安装失败并打印原因（3.1 不做自动回滚，回滚在 3.5）。

### 5.2 “完全清除”的定义

- 保证：**应用不再持有任何可用副本**（两个文件、临时、日志、安装目录、配置）；
- 保证：重装生成**全新**密钥并能正常认证；
- 不保证：磁盘物理不可恢复（SSD/卷影/页面文件/转储）。

## 6. IPC 协议 v2

### 6.1 管道

- 名称：`WinAppGuard.Control.v2`；
- 协议版本：2；
- 3.0 客户端连 v2 失败 → 界面提示“版本不匹配，请运行 Setup --repair”。

### 6.2 握手

每个连接：

1. 客户端发普通 `ServiceRequest { Command = "auth.challenge" }`；
2. 服务返回 `ServiceResponse { Ok = true, Nonce = <32 字节 Base64> }`；
3. 客户端把真正的请求序列化成 UTF-8 JSON，计算
   `signature = ECDSA-P256-SHA256(privateKey, nonce || payload)`；
4. 客户端发送二进制封套：

```
[4 字节小端 签名长度][签名 DER 字节]
[4 字节小端 请求长度][请求 JSON 字节]
```

5. 服务读封套，用公钥验签，再反序列化请求；
6. 处理并返回普通 `ServiceResponse`。

### 6.3 限制

- nonce：32 字节，连接级、一次性；
- 签名长度：1..256 字节；
- 请求长度：1..4 MB；
- 每个连接只处理一个请求；
- 缺失/错误签名、重放、长度越界 → `Ok=false, Error="认证失败"`，详细原因只写服务日志；
- 只有 `auth.challenge` 免签；其它命令（含 `status`）全部要签。

### 6.4 失败策略

- 配置缺失/公钥损坏：服务**失败关闭**（不创建控制管道），只记日志；由 Setup 修复；
- 不做“无保护降级”，避免 3.1 装上后实际仍是旧行为。

## 7. 权限与审计

### 7.1 管道 ACL

- SYSTEM：完全控制；
- 所有者 SID：读写；
- 其他所有账户：无。

### 7.2 服务 DACL

- SYSTEM + 所有者：完全控制（含停止/配置）；
- Administrators：只允许 `SERVICE_QUERY_STATUS | SERVICE_START | READ_CONTROL`；
- 其他账户：无；
- 目的：其他管理员不能直接 `sc stop`；但可以夺取所有权/杀进程，文档如实说明。

### 7.3 连接审计

连接建立后记录：

- 客户端 SID；
- PID、镜像路径、镜像 SHA-256；
- 命令名；
- 允许/拒绝原因。

写操作、拒绝、服务启停、密钥指纹都写服务日志；关键事件可后续加 Windows 事件日志（3.1 先服务日志）。

界面状态显示：

- 受保护模式：开启；
- 所有者：`DOMAIN\user`；
- 密钥指纹前 16 位；
- 最近拒绝次数/时间。

---

## 8. CLI 与自检

- CLI 的 `--block / --list-blocked / --unblock-all` 改为**签名 IPC**，不再直接写 WFP；
- `--migrate / --recover` 保留为管理员恢复命令（直接 WFP），文档标注；
- CLI 必须以所有者身份运行；否则明确报“当前账户不是所有者”；
- SelfCheck 使用同一签名客户端；非所有者运行会被拒（预期）；
- `--help` 无需认证。

---

## 9. 失败与恢复

| 现象 | 处理 |
|---|---|
| 界面提示“不是所有者” | 用所有者账户运行，或 `--reset-owner` |
| 界面提示“密钥不可用” | DPAPI 解不开：所有者运行 `--rotate-key` |
| 服务起不来 / 控制管道不存在 | 服务日志；`--repair` 重建配置 |
| 所有者账号被删 | 管理员运行 `--reset-owner`（会接管所有权） |
| 服务被其他管理员停止 | 严格模式撤销；界面显示离线；日志有记录；重启服务后恢复 |
| 密钥文件被占用 | 卸载登记重启删除；下次安装清理 |
| 3.0→3.1 升级 | `--repair` 生成密钥（所有者=当前账户）；保留规则/分组/记录 |

## 10. 验收

### 10.1 自动化

- `--key-primitive-test`（离线）：生成/DPAPI 往返/签名验签/篡改/错误 entropy；
- `--protected-mode-store-test`（离线）：目录/文件 ACL、DPAPI 往返、轮换、删除；
- `--auth-codec-test`：挑战、签名、篡改、重放、长度越界；
- `--service-auth-test`（需管理员 + 服务 + 所有者）：正确/错误密钥、重放、缺失配置；
- 原有服务/UI/规则/审计自检全部适配。

### 10.2 VM 手工矩阵

1. 同账户安装 → 密钥/ACL/签名自检通过；
2. 跨账户安装 → 默认取消；`--allow-owner-mismatch` 继续后所有者=提权账户；
3. 卸载 → 两个密钥文件不存在；
4. 重装 → 新指纹，认证成功；
5. 连续 3 轮安装/卸载/安装；
6. 3.0→3.1 升级；`--repair` 指纹不变；
7. 密钥被占用 / 卸载不完整 / 重装；
8. 第二个管理员账号：读密钥失败、连服务失败、停服务失败（或留痕）；
9. `--rotate-key` / `--reset-owner`；
10. 删除 DPAPI blob → 界面提示修复；
11. 日志、临时目录、安装目录中无密钥副本。

---

## 11. 3.1 不包含（后续）

- WFP 过滤器/子层 DACL 改为 owner-only 与旧过滤器迁移（3.2）；
- 多所有者；
- 自动更新/回滚（3.5）；
- PPL/内核/代码签名（不做）。

---

## 12. 残留风险（必须写进 README/SECURITY）

- 管理员可以停服务、杀进程、替换二进制、直接改 WFP；
- 管理员可以夺取文件/服务所有权，或 dump LSASS 后以所有者身份签名；
- DPAPI 在密码被重置时可能失效，需要重新生成密钥；
- 没有代码签名，SmartScreen 会提示未知发布者；
- “完全清除”只是应用层逻辑清除，不是物理不可恢复。
