# 3.1 第 2 步 VM 验收（密钥存储 + 安装器生命周期）

> 这一步**只验证密钥文件和安装器**。服务/界面还没有接入签名协议：
> 其他账户仍然能打开界面，要等第 4 步（管道 ACL + 服务 DACL）。
> 现在能验证的是：只有所有者能**读密钥文件**。

## 0. 环境

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
```

确认版本是 3.1：

```powershell
(Get-Item .\WinAppGuardSetup.exe).VersionInfo.ProductVersion
```

期望以 `3.1+` 开头。

## 1. 从 3.0 升级 / 首次生成密钥

```powershell
.\WinAppGuardSetup.exe --repair
```

期望看到：

```text
受保护模式：未发现密钥（首次升级/配置缺失），按当前账户生成。
受保护模式：已生成密钥（指纹 XXXXXXXX…）。
修复完成，服务正在运行。
```

记录指纹前 16 位，后面步骤要对比。

## 2. 只读检查已安装密钥

```powershell
.\WinAppGuard.SelfCheck.exe --protected-mode-owner-test --no-pause
```

期望：**8/8**。输出应包含：

```text
所有者 = <你的账户>（S-1-5-...）
指纹   = <与 Setup 一致>…
```

这一步验证：配置和私钥存在、当前账户是所有者、DPAPI 能解开、签名能验、
配置不含私钥、目录/文件 ACL 正确。

## 3. 存储原语（离线）

```powershell
.\WinAppGuard.SelfCheck.exe --protected-mode-store-test --no-pause
```

期望：**13/13**。

## 4. 看 ACL（手工核对）

```powershell
icacls "C:\ProgramData\WinAppGuard\protected-mode"
icacls "C:\ProgramData\WinAppGuard\protected-mode\config.json"
icacls "C:\ProgramData\WinAppGuard\protected-mode\client-key.dpapi"
```

期望：

- 只有 `SYSTEM` 和当前所有者；
- 没有 `BUILTIN\Administrators`；
- 没有 `BUILTIN\Users`；
- 没有 `NT AUTHORITY\INTERACTIVE`；
- 目录/文件都**没有继承**（不应出现 `(I)`）。

示例（账户名会不同）：

```text
protected-mode NT AUTHORITY\SYSTEM:(OI)(CI)(F)
               VM\VM:(OI)(CI)(F)

config.json    NT AUTHORITY\SYSTEM:(F)
               VM\VM:(R,W,D)
```

## 5. 再修复一次：密钥必须保留

```powershell
.\WinAppGuardSetup.exe --repair
.\WinAppGuard.SelfCheck.exe --protected-mode-owner-test --no-pause
```

期望：

- Setup 输出 `受保护模式：保留现有密钥（指纹 …）。`
- 指纹与第 1 步**相同**；
- 8/8。

## 6. 轮换密钥

期望：

- 新指纹与之前**不同**；

再跑：

```powershell
.\WinAppGuard.SelfCheck.exe --protected-mode-owner-test --no-pause
```

期望 8/8，指纹等于新指纹。

## 7. 重置所有者（同一账户）

```powershell

```

期望：

- `所有者已切换为：<你的账户>`
- 指纹再次变化；
- 服务已启动；
- `--protected-mode-owner-test` 8/8。

## 8. 卸载：密钥必须消失

先记录当前指纹，然后：

```powershell
.\WinAppGuardUninstall.exe --uninstall
Test-Path "C:\ProgramData\WinAppGuard\protected-mode"
```

期望：

- 卸载输出 `受保护模式密钥：已删除并校验不存在。`
- `Test-Path` 返回 **False**；
- 安装目录、数据目录也按原卸载逻辑删除。

## 9. 重装：必须生成全新密钥

```powershell
.\WinAppGuardSetup.exe --install
.\WinAppGuard.SelfCheck.exe --protected-mode-owner-test --no-pause
```

期望：

- Setup 输出 `已为 <账户> 生成新密钥（指纹 …）`；
- 新指纹与卸载前**不同**；
- 8/8。

## 10. --keep-data 也必须删密钥

```powershell
.\WinAppGuardUninstall.exe --uninstall --keep-data
Test-Path "C:\ProgramData\WinAppGuard\protected-mode"   # 期望 False
Test-Path "C:\ProgramData\WinAppGuard\rules.json"       # 期望 True（数据保留）
.\WinAppGuardSetup.exe --install
```

期望：

- 密钥目录不存在；
- 规则/数据目录还在；
- 重装生成新密钥，8/8。

## 11. 跨账户只读（可选，需要第二个管理员账户）

前提：当前所有者是 A；用 B（另一个管理员）登录，打开**管理员** PowerShell：

```powershell
Get-Content "C:\ProgramData\WinAppGuard\protected-mode\config.json"
```

期望：**拒绝访问**（B 不是所有者）。

> 这一步只验证文件 ACL；B 仍然能打开界面/调用服务，因为签名协议还没接。
> 不要把它当成“B 已经被完全挡住”。

跨账户安装（可选，操作较绕）：

1. 先由 A 卸载；
2. 以 B 登录，运行 Setup 并在 UAC 里输入 A 的凭据（over-the-shoulder）；
3. 默认应取消，并提示加 `--allow-owner-mismatch`；
4. 加 `--allow-owner-mismatch` 后继续，所有者应为 A（提权账户），不是 B。

## 13. 手工检查：没有密钥副本

```powershell
# 安装目录、日志、临时目录里不应该有 client-key.dpapi / config.json 的副本
Get-ChildItem "C:\Program Files\WinAppGuard" -Recurse -Force |
    Where-Object { $_.Name -match 'client-key|protected-mode|config\.json' }

Get-ChildItem "$env:TEMP" -Recurse -Force -ErrorAction SilentlyContinue |
    Where-Object { $_.Name -match 'client-key|protected-mode' }

Get-ChildItem "C:\ProgramData\WinAppGuard\logs" -File |
    Select-String -Pattern 'PRIVATE KEY|client-key'
```

期望：没有输出。日志里可以出现指纹，但**不能出现私钥或 DPAPI blob**。

- 安装后的“签名 status 自检”还没有（第 3 步补）。
