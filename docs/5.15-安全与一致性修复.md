# 5.15：严格模式、双栈写入与导入一致性修复

> 版本：5.15.0  
> 协议：v4（`ResponsePayload` 增加可选 `Warning`）

## 1. 严格模式按范围放行

### 问题

白名单规则可以选择协议/远端端口，但严格模式只按程序路径放行：

```text
GetAllowRulePrograms() → 只有路径
WfpStrictSession → 每个路径一条 app-id permit
```

结果：`chrome TCP 443` 在严格模式下变成“chrome 全部放行”。

### 修复

```text
StrictAllowPlanner：
  同一程序有任意范围规则 → 只放行整个程序
  否则不同范围各一条
  系统程序 / 界面自身 / 额外程序 → 任意范围
```

会话对非任意范围使用 `AddScopedAppIdFilter`。

## 2. 严格模式重建失败保留旧会话

### 问题

旧实现：

```text
RefreshIfEnabled → Disable() → Enable()
```

读取白名单或创建新过滤器失败时，旧会话已经被拆掉，表现为“刷新失败 = 全网放行”，
而添加白名单的请求仍然返回成功。

### 修复

- 在同一个动态会话里用 WFP 事务替换：
  - Begin → 删除旧 strict 过滤器 → 添加新过滤器 → Commit；
  - 失败 → Abort，旧过滤器原样保留。
- 读取白名单失败时根本不碰会话。
- 失败结果向上返回：
  - 手动刷新严格模式：命令失败；
  - 添加/导入/删除白名单：规则成功 + `Warning`；
  - 界面显示警告并立即刷新严格模式状态。

## 3. IPv4 / IPv6 原子写入

### 问题

```text
foreach layer { delete old; add new; }
```

V4 成功、V6 失败时，V4 过滤器留在系统里，列表按规则去重回显，
看起来“已阻止”，实际 IPv6 未拦截。

### 修复

- `WfpEngine.RunInTransaction`。
- `WfpRuleStore.Add/Remove` 两层操作放在一个事务里。
- 失败回滚，计数只在提交后返回。
- 删除同样事务化，避免只删掉一层。

## 4. 「解除阻止」只删阻止规则

### 问题

界面只列出阻止规则，服务端却调用 `DeleteRulesForProgram` 删除该程序的
**全部**规则（阻止 + 允许），并清理分组。

### 修复

- 新增 `RuleDeletionPlanner.SelectBlockRulesForProgram`；
- 服务端只删除 `Action == Block`；
- 确认框明确说明不会动白名单/允许规则和严格模式白名单。

## 5. 导入保留多个范围

### 问题

规则显示名其实已经带范围后缀，但导入用**不带范围的基础名**去重：

```text
existing.Add(BuildBlockRuleName(path))
```

同一程序的第二条范围规则被当成重复跳过；分组也写到基础名上，
和真实规则名（带范围后缀）对不上。

### 修复

- 新增 `RuleImportPlanner`，身份为：
  - 程序：动作 + 完整路径 + `scope.Encode()`；
  - IP：地址。
- 文件内重复 / 已存在 / 受保护 → skipped；
- 不同范围 → 都创建；
- 分组使用 `CreateBlockRule/CreateAllowRule` 返回的真实规则名；
- `allow + ip` 组合判为无效，不再静默创建成阻止规则。

## 6. 新程序开关改名

```text
旧：新程序默认阻止并弹窗询问（高风险）
新：发现新程序联网后自动阻止（高风险；只阻止后续连接）
```

确认框同步说明：检测发生在连接建立之后，只能阻止后续连接。

## 7. 测试

新增：

- `StrictAllowPlannerTests`：范围保留 / 任意范围覆盖 / 系统程序 / 去重；
- `RuleImportPlannerTests`：多范围 / 文件内重复 / 已存在 / allow+ip；
- `RuleDeletionPlannerTests`：只选阻止规则；
- `WriteResultWarningRoundTrips`：`Warning` 字段往返。

## 8. VM 验收

```text
1. 白名单 chrome 设为 TCP 443：
   - 443 可连；
   - 80 被严格模式阻断；
2. 白名单再加一个程序：严格模式状态保持开启；
   故障注入让重建失败：旧白名单仍生效，界面显示 Warning；
3. 添加阻止规则：IPv4 / IPv6 都阻断；
   事务 Abort 后无残留过滤器；
4. 同一程序同时有阻止 + 白名单：
   点「解除阻止」→ 阻止规则消失，白名单和分组保留；
5. 导出程序的两条范围规则 → 导入：
   两条都恢复，范围正确，分组正确；
   重复导入 → 全部 skipped；
6. 新程序开关、确认框、托盘提示文案一致。
```
