# 3.7 用户态 Flow IDS 设计

> 状态：设计待批准（2026-10-26）。
> 范围：基于 ETW 连接元数据 + DNS 的**只检测、不 inline** 的可疑行为告警。
> **不做**：抓包 / DPI / HTTPS 解密 / 自动阻断 / 内核驱动 / 外部威胁情报 / 云上传。
> 真正的 inline IPS 留给 4.0（驱动 POC）。

## 1. 定位

3.7 的 IDS 不是杀毒软件，也不是「看到内容就能判定恶意」的引擎。它只看：

- PID、程序路径；
- 远端 IP / 端口、协议、方向；
- 连接时间、次数、间隔、字节数；
- DNS 域名、查询类型、结果。

输出是**可疑行为告警**，带证据，供用户判断；不自动阻断。用户确认后可以回到现有规则页手动阻止。

## 2. POC 实测结论

2026-10-26 在 VM 上实测（`tools/IdsPoc`）：

| 场景 | 结果 |
|---|---|
| 合成 selftest | beaconing / scan / lateral / dns / exfil 全部命中 |
| 正常使用 10 分钟 | **0 条告警** |
| CPU（正常） | 平均 0.0%，峰值 0.1%（16 核） |
| 内存（正常） | 峰值 56 MB |
| flow 峰值 | 535 |
| 10 分钟事件 | 11,724（TCP/UDP 收发 + 连接） |
| DNS 观察 | 113 条 |

第一轮 selftest 曾出现 `svchost` / `chrome` 误报，调整后：

- scan 只统计 TCP 连接/接受事件，按「同一主机多端口」或「同一非 80/443 端口多主机」判；
- beaconing 排除组播/广播/链路本地和 53/5353/5355/1900/3702/137/138；
- DNS 按同一父域分组，并忽略系统进程；
- lateral 用本机管理端口监听验证。

结论：**性能完全可接受；规则需要保守阈值 + 抑制机制**。

## 3. 检测规则（3.7 MVP）

所有阈值都按「标准敏感度」，数值与 POC 已验证的规则一致；另提供「保守」预设（阈值约 2 倍）。

### 3.1 Beaconing（周期性外联）

- 数据：同一 PID + 同一远端 IP:端口 的 TCP 连接时间；
- 窗口：10 分钟；
- 条件：
  - 连接 ≥6 次；
  - 相邻间隔 4 秒–5 分钟；
  - 间隔抖动系数 ≤0.35；
  - 平均每次数据量 <256 KB；
- 排除：
  - 组播/广播/链路本地；
  - 端口 53、5353、5355、1900、3702、137、138；
  - 系统进程（可在设置里放开）；
- 级别：中；
- 证据：连接次数、平均间隔、抖动、平均每次字节、远端。

### 3.2 端口 / 主机扫描

只使用 TCP 连接/接受事件。

- 垂直扫描：同一 PID 对**同一远端主机**，60 秒内 ≥15 个不同端口；
- 水平扫描：同一 PID 对**同一非 80/443 端口**，60 秒内 ≥15 台不同主机；
- 排除：组播/广播/链路本地；
- 级别：中；达到 30 个端点升为高；
- 证据：主机、端口数 / 端口、主机数、时间窗口。

> 不按「端点总数」判：浏览器正常会连很多 CDN，第一轮 POC 已实测误报。

### 3.3 内网横向

- 条件：同一 PID 在 10 分钟内连接 ≥3 台**内网地址**的
  445 / 3389 / 5985 / 135 / 139；
- 排除回环、组播、系统进程（可配置）；
- 级别：高；
- 证据：内网主机数、端口集合。

### 3.4 DNS 异常

按 **PID + 父域** 分组：

- 10 分钟内同一父域下 ≥20 个唯一子域；或
- ≥10 个长度 ≥40 的子域；或
- 查询 ≥20 且 NXDOMAIN/NO_RECORDS ≥70%；
- 排除系统进程（`svchost`、`WinAppGuardSvc`、`System`、`services`、`lsass`、`dns`）；
- 级别：中；
- 证据：父域、唯一子域数、长域名数、NXDOMAIN 比例。

### 3.5 异常上传（可选，默认开）

- 条件：单程序 5 分钟上传 ≥10 MB 且上传/下载 ≥5；或 1 小时 ≥100 MB；
- 排除：用户可对备份/网盘程序抑制；
- 级别：高；
- 证据：上传/下载字节、时间窗口、远端。

### 3.6 明确不做

- 不做 payload/URL 检测、不做 HTTPS 解密；
- 不接外部 IP/域名信誉库；
- 不自动阻断；
- 不做「新程序首次外联」这类低置信度告警（避免噪音）。

## 4. 架构

```text
ETW Kernel-Network ──> FlowCollector ──> IdsRuleEngine ──> AlertStore
ETW DNS-Client     ──> DnsCollector  ──┘
                                      └──> 托盘提示 / 安全页
```

### 4.1 复用现有 ETW 会话

3.5/3.6 已经有一个网络 ETW 会话和一个 DNS 会话。3.7 **不新开会话**：

- `NetworkEtwMonitor` 增加可选 fan-out：
  - 流量采集继续只读 `PID + size`；
  - IDS 开启时额外解析地址/端口/连接事件，交给 `FlowCollector`；
- `DnsEtwMonitor` 增加 `QueryType`，并把观察交给 `DnsCollector`；
- IDS 关闭时保持 3.6 的低开销，不解析五元组。

### 4.2 FlowCollector

- 键：`PID + 协议 + 远端 IP + 远端端口`；
- 字段：首次/最后时间、BytesIn/Out、TCP 连接时间列表（最多 64）；
- 内存上限：20,000 个 flow；超过时按最后时间淘汰；
- 只保留 30 分钟；
- 事件丢失/flow 淘汰计数暴露在状态里。

### 4.3 IdsRuleEngine

- 每 5 秒评估一次滑动窗口；
- 规则独立开关；支持「保守 / 标准」预设；
- 生成 `IdsAlert`；
- 去重键 `(规则, PID, 目标)`；同一键默认冷却 30 分钟；
- 每条告警保存证据摘要，不保存原始事件流。

### 4.4 AlertStore

- 内存环形 1000 条；
- 可选落盘：`%ProgramData%\WinAppGuard\ids\alerts-YYYYMMDD.jsonl`；
- 默认保留 7 天，可改 1/3/7/30 天；
- 原子追加；坏文件跳过，不影响服务；
- 只存元数据和证据摘要，不存载荷；
- 清空需提权。

### 4.5 抑制

- 按规则 + 进程路径 + 目标（IP/域名/父域）抑制；
- 可设 1 小时 / 24 小时 / 永久；
- 抑制表持久化到 `ids/suppressions.json`；
- 界面可见、可取消。

## 5. 协议（仍为 v2，只新增命令）

| 命令 | 类型 | 说明 |
|---|---|---|
| `query.ids.alerts` | 读 | 最近告警；支持关键词过滤 |
| `query.ids.status` | 读 | 采集/规则/flow/丢弃计数（也可并入 `status`） |
| `write.ids.ack` | 写 | 确认一条告警（不改规则） |
| `write.ids.suppress` | 写 | 新增/取消抑制 |
| `write.ids.clear` | 写 | 清空告警（提权） |
| `write.ids.configure` | 写 | 开关 IDS / 规则 / 敏感度 / 保留期 |

DTO：

```text
IdsAlertDto {
  Id, TimeUtc, Severity, RuleId, RuleName,
  Pid, ProcessName, ProcessPath,
  Target, Evidence, Status,
  DedupKey, SuppressedUntilUtc
}

IdsStatusDto {
  Collecting, RulesEnabled, FlowCount, EventsSeen, EventsLost,
  AlertsNew, AlertsTotal, LastAlertUtc
}
```

`ServiceStatus` 增加只读字段：`IdsCollecting`、`IdsAlertsNew`、`IdsEventsSeen`。

## 6. 界面

- 新增「安全」页；如果 8 个页签在 980 宽放不下，退化为「记录」页里的子标签。
- 列表列：时间、级别、规则、程序、目标、证据摘要、状态。
- 筛选：级别 / 规则 / 程序 / 时间；搜索程序/目标。
- 详情：完整证据（次数、间隔、字节、远端/域名、时间范围）。
- 操作：确认、忽略、抑制、清空；不提供「一键阻断」（避免误操作）。
- 状态：显示「只检测、不阻断」；显示 flow 数、事件丢失、规则开关。
- 托盘：仅高严重度弹一次，5 分钟限流；**不弹模态框**。
- 设置：IDS 开关、规则开关、敏感度（保守/标准）、保留期、抑制管理。
- 中英文、100%/150% DPI。

### 6.1 默认值

- IDS **默认开启**，标准敏感度；
- 规则默认全开；
- 仅高严重度托盘提示；
- 告警保留 7 天；
- 系统进程默认不参与 beacon/DNS 规则（可在设置里放开）。

## 7. 隐私与安全

- 只存连接元数据、域名、计数和证据摘要；
- 不存载荷、URL、HTTPS 内容；
- 不上传任何数据，不接外部情报；
- 告警/抑制文件本地保存，可清空；
- 写命令仍要求提权；读命令只要求签名；
- 不改变 3.1/3.4 的权限模型与 WFP DACL；
- IDS 关闭时不做额外解析，保持 3.6 开销。

## 8. 性能与降级

- POC 实测：正常 10 分钟 CPU 0.0%/峰值 0.1%，内存 56 MB，flow 峰值 535；
- 生产 guard：
  - flow 上限 20,000；超过淘汰最旧；
  - 事件丢失/flow 淘汰计数显示在安全页；
  - 连续采样失败自动重启 ETW，日志 `WAG-IDS-*`；
  - 若 CPU 持续高于阈值，自动降为只记录高危规则（状态里说明）。
- 不承诺「零丢失」；界面明确写「启发式/近似」。

- 抑制：规则+进程+目标、到期、取消；
- 告警存储：原子追加、保留期、坏文件、清空；
- DTO 编解码 / 旧服务降级；
- UI 排序/筛选/中英文/DPI。

### 9.2 VM

- `--ids-selftest`：复用 POC 合成场景，5 条规则全部命中；
- `--ids-monitor 600`：正常使用 10 分钟，0 高/≤2 中误报；
- 24 小时 soak：CPU、内存、flow、事件丢失、告警量；
- 3.4–3.6 回归（DACL、规则、流量页、DNS、锁网）；
- 旧服务/旧客户端兼容。

## 11. 风险

| 风险 | 处理 |
|---|---|
| 误报 | POC 已把正常 10 分钟降到 0；保守阈值 + 系统进程过滤 + 抑制 |
| 加密/DoH 盲区 | 只做元数据检测，文案不承诺内容级 |
| 用户以为能自动阻断 | 界面/文档反复写「只检测」；阻断是 4.0 |
| ETW 事件量/CPU | 复用现有会话；flow 上限；实测 <0.1% |
| 告警刷屏 | 去重 + 冷却 + 托盘限流 |
| 隐私 | 只存元数据，本地、可清空、不上传 |
| 规则被绕过 | 用户态可被管理员停止；这是已知边界，不冒充内核级 |
