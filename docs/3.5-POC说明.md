# 3.5 POC 操作说明（VM）

> 目的：在写产品代码之前，先测出「每程序流量」和「DNS 事件」两条路线是否可用。
> 只在 VM 里跑；需要管理员 PowerShell。

## 0. 文件

`publish.ps1` 不会同步 POC；它放在：

- `build\_poc\WinAppGuard.TelemetryPoc.exe`
- `docs\3.5-POC-ETW.ps1`

把整个 `默认项目` 文件夹复制到 VM 后，按需从上面两个位置运行即可。

## 1. TCP 扩展统计

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
.\WinAppGuard.TelemetryPoc.exe --tcp 15
```

建议在运行前**先开始一个持续下载/视频播放**，否则 15 秒内可能没有可统计的流量。

记录：

- `TCP 连接数` / `ESTABLISHED` 数；
- `已启用统计` / `可读连接` / `读取失败`；
- 前几个 PID 的上传/下载；
- `合计` 字节数。

对比：

- 同一时间打开任务管理器 →「性能 → 以太网」，看发送/接收速率；
- 或者 `netstat -e` 看整机累计。

判定：

- 量级一致、CPU 可忽略 → TCP 路线可用；
- 大量连接读不到、数字明显不对 → 记录，等 ETW 结果。

## 2. ETW 网络事件量

```powershell
cd C:\Users\VM\Downloads\默认项目\dist-tools
powershell -ExecutionPolicy Bypass -File .\3.5-POC-ETW.ps1 `
    -Provider Microsoft-Windows-Kernel-Network -Seconds 30
```

建议同样在下载/视频播放时跑一次，再在空闲时跑一次。

记录：

- ETL 大小、CSV 大小、CSV 行数；
- 平均 CPU；
- 前 5 行预览里能不能看到 PID / 地址 / 字节字段。

判定：

- 空闲 CPU < 1%、下载时 < 5%、事件不丢 → ETW 完整路线可行；
- 事件量过大/CPU 过高 → 只做 TCP 近似，界面标注限制。

## 3. DNS ETW

```powershell
powershell -ExecutionPolicy Bypass -File .\3.5-POC-ETW.ps1 `
    -Provider Microsoft-Windows-DNS-Client -Seconds 60
```

期间打开几个网站（含一个 DoH 的浏览器/应用）。

记录：

- CSV 行数/CPU；
- 前 5 行里能否看到查询域名、PID；
- DoH 场景是否完全没有记录。

判定：

- 能拿到域名 + PID → 3.5 用 ETW DNS；
- 只有缓存命中 → 退回现有 `DnsCacheReader`，文案写「推测」。

## 4. 回传结果

把上面三段的命令输出（数字 + 前几行）贴回来即可，不需要上传 ETL/CSV。
