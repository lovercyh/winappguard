# 5.10 协议 v3 设计冻结

> 基线：5.9.2
> 分支：`arch/5.10`
> 目标：一个公开发布版本 5.10.0，完成 A（协议 v3）+ B（规则读缓存）+ C（抽象接入）+ D（分层修正）。
> 约束：不引入第三方库；不改 WFP 语义；升级失败可回退到 `v5.9.2`。

## 1. 安全不变量（以当前实现为准）

1. 管道 ACL：**SYSTEM + 所有者完全控制，owner-only**。不移交给 Administrators 或 INTERACTIVE。
2. 写命令：**提权令牌 + 所有者 ECDSA 签名**双闸，缺一不可。
3. 服务端重新校验所有输入：路径、受保护进程、端口、TTL 上限。
4. 缺少受保护模式配置时不创建管道（fail closed）。
5. 动态 WFP 会话语义不变：进程退出即撤销。
6. `guard.new-program.*` 保持独立策略 `OwnerTemporaryWfp`，不并入 Read/Write/Alert。

## 2. 帧与握手

保留 4 字节小端长度前缀 + UTF-8 JSON。

```text
client                                   server
  │  ── Hello {v, clientVersion, clientNonce} ──▶
  │  ◀── Challenge {sessionId, serverNonce, serverTimeUtc,
  │                  toolVersion, protocol, capabilities[], limits}
  │  ── Auth {sessionId, signature} ──▶
  │  ◀── Welcome {sessionId, expiresUtc}
  │  ── Request {seq:1, command, payload} ──▶
  │  ◀── Response {seq:1, ok, errorCode, revision, data}
```

- 会话级 nonce：`serverNonce` 每次连接随机生成。
- `seq` 从 1 开始严格递增，重复/跳号立即断连。
- 握手失败 3 次断开并记 `WAG-AUTH-*`。
- 连接上限先保持现有 4 个实例；只有压测后才能提高。
- 帧上限：
  - 普通请求 256 KB；
  - `write.rules.import` / `write.groups.import` 4 MB；
  - 响应按命令分级，规则列表/事件列表允许 1 MB 以上。

## 3. 信封与签名

```jsonc
{
  "v": 3,
  "id": "0f6c…",
  "seq": 1,
  "command": "write.rules.addProgram",
  "payload": { },
  "sinceRevision": null
}
```

```jsonc
{
  "v": 3, "id": "0f6c…", "seq": 1,
  "ok": true,
  "errorCode": "None",
  "message": null,
  "revision": 42,
  "data": { }
}
```

签名范围：

```text
ECDSA_P256_SHA256(serverNonce || UTF8(requestEnvelopeBytes))
```

响应签名本版本不做；客户端校验服务端身份：

- `GetNamedPipeServerProcessId`；
- 进程路径必须在安装目录下；
- 令牌必须是 SYSTEM；
- 失败断连并记录日志。

## 4. 错误码

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | None | 成功 |
| 1 | UnknownCommand | 未声明/未注册命令 |
| 2 | VersionMismatch | 协议或能力不匹配 |
| 3 | NotElevated | 写命令未提权 |
| 4 | NotOwner | 非所有者 / 无签名密钥 |
| 5 | InvalidArgument | 参数错误 |
| 6 | NotFound | 目标不存在 |
| 7 | Conflict | 状态冲突 |
| 8 | Busy | 正在导入/迁移 |
| 9 | TooLarge | 帧或载荷超限 |
| 10 | RateLimited | 超过限流 |
| 11 | Unavailable | 模块未运行 |
| 12 | Timeout | 操作超时 |
| 13 | Internal | 内部错误 |

`message` 固定英文短句；界面按 `errorCode` 本地化。CLI 退出码映射写进 `docs/5.3-CLI.md`。

## 5. revision 与增量

- 全局 `revision`：任何成功写操作 +1；
- 每个特性有独立 `revision`；
- 服务启动生成 `revisionEpoch`，服务重启后客户端不会误判“未变化”；
- 以下路径必须推进对应 revision：
  - 规则写入、删除、清空、严格模式、锁网；
  - 到期清理、篡改重建；
  - IDS/网络检测新告警；
  - 阻断新增/释放；
  - 模块健康状态变化。
- `sinceRevision` 只对同一 `revisionEpoch` 有效；
- 事件流使用 `lastEventId` / `sinceUtc`，不能只依赖全局写 revision。

## 6. QueryView / StatusView

### QueryView

```jsonc
{
  "status": { "health": "running", "collecting": true, "detail": "collecting" },
  "settings": { },
  "events": [
    {
      "type": "ids.alert",
      "id": "…",
      "timeUtc": "…",
      "severity": "high",
      "title": "…",
      "detail": "…",
      "data": { }
    }
  ],
  "blocks": [ { "target": "1.2.3.4", "untilUtc": "…", "reason": "…", "eventId": "…" } ],
  "baseline": { "learnedUtc": "…", "items": [] },
  "meta": { "generatedAtUtc": "…", "revision": 42, "revisionEpoch": "…", "truncated": false, "total": 128, "notModified": false }

```

`events[]` 必须有 `type` 判别字段；不能只靠字段猜测类型。
