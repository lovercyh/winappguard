# 4.3 DNS 安全（本地 DNS 劫持 / 绕过检测）设计

> 状态：已实现（2026-10-29），待 VM 验收。
> 范围：DNS 应答校验、DNS 投毒/劫持告警、明文 DNS 绕过检测；事件复用 4.2 的落盘与保留期。
> 不做：DoH/DoT 解密、TLS SNI、阻断 DNS、保存报文。

## 1. 目标与边界

- **能发现**：应答来自非请求服务器、事务 ID 不匹配、应答域名与请求不符、
  NXDOMAIN 带答案、同一请求收到冲突应答、TTL 异常、DNS 服务器 MAC 非网关、
  明文 DNS 发往非配置服务器。
- **不能发现**：DoH/DoT 内部的劫持（看不到内容）；上游 DNS 服务器自己返回假数据
  （除非与基线答案冲突）；加密 DNS 的绕过（只提示，不检测）。
- **处置**：**只告警**。不阻断 DNS——拦网关的 53 会把正常上网一起打断，
  与 4.2 的 DHCP 阻断（窄范围）不同。

## 3. 采集

复用 4.2 的第三个 Npcap 会话，不新增会话：

```
BPF: arp or (udp and (port 67 or 68 or 53))
snaplen: 600（DNS 应答可能较长）
混杂模式：关
```

- 只解析 DNS 头、问题段和 Answer 段的 A / AAAA / CNAME；
- 不解析其它记录类型的内容，不保存报文；
- 请求与应答都看：请求用于“发往哪个服务器”，应答用于校验。

## 4. 请求跟踪

对每个（网卡 + 客户端 IP:端口 + 事务 ID + 域名 + 类型）记录：

- 发送时间、目标服务器 IP、是否已收到应答；
- 超时 5 秒未应答则丢弃；
- 应答到达时按（客户端端口 + 事务 ID + 域名/类型）匹配；
- 同一请求的多个应答保留 2 秒用于“冲突检测”。

内存上限：同时跟踪 4096 条，超出按最旧淘汰。

## 5. 检测规则

| 规则 | 级别 | 触发条件 | 误报控制 |
|---|---|---|---|
| `dns_response_unexpected_server` | 高 | 应答来源 ≠ 请求发往的服务器 | 允许“信任此服务器” |
| `dns_transaction_mismatch` | 高 | 应答事务 ID 对不上任何未完成请求 | 2 秒窗口；冷却 10 分钟 |
| `dns_answer_name_mismatch` | 高 | 应答 Question 与请求域名/类型不一致 | 同上 |
| `dns_nxdomain_with_answer` | 高 | 返回 NXDOMAIN 但 Answer 段非空 | 同上 |
| `dns_conflicting_answers` | 中 | 同一请求 2 秒内收到不同 A/AAAA 集合 | 冷却；同一来源只报一次 |
| `dns_ttl_suspicious` | 低 | TTL = 0 或 < 10 秒 | 冷却；常见 CDN 可能合法 |
| `dns_server_not_gateway` | 中 | DNS 服务器 MAC ≠ 网关基线 MAC（同网卡） | 需 4.2 网关基线；无基线不报 |
| `dns_plaintext_bypass` | 中 | 明文 53 查询发往非配置、非信任服务器 | 排除 127.0.0.1；可信任 |

冷却：同一（规则 + 关键值）10 分钟只报一次。

## 6. 基线

- **配置的 DNS 服务器**：从系统网卡属性读取（每网卡一组），启动时与每 60 秒刷新；
- **信任列表**：用户手动“信任此服务器”后写入 `lan/state.json`；
- **观察到的服务器**：出现在 DNS 服务器表里，默认不信任，用于绕过检测；
- 首次启动静默学习 2 分钟（或直到拿到配置的 DNS），期间不告警；
- 4.2 的“重置基线”**不**清 DNS 信任（DNS 有自己的信任列表）；DNS 子页提供“清空信任”。

## 7. 落盘与协议

### 事件

- 复用 `%ProgramData%\WinAppGuard\lan\events-YYYYMMDD.jsonl`；
- 事件 `Kind` 以 `dns_` 开头，`Adapter`/`Detail`/`SourceMac`/`TargetIp` 语义与 4.2 一致；
- 保留期跟随 4.2 设置（7/15/30 天）；
- 「清空」只删除 `dns_*` 事件（重写当天文件，保留其它事件）。

### 新增命令

| 命令 | 类型 | 说明 |
|---|---|---|
| `query.dns-security` | 读 | 状态 + DNS 服务器列表 + 最近 200 条 `dns_*` 事件 |
| `write.dns-security.clear` | 写 | 只清空 DNS 安全事件 |
| `write.dns-security.trust` | 写 | 信任/取消信任某 DNS 服务器 |

`write.dns-security.trust` 复用 `LanState.TrustedDnsServers`（新增字段），
`write.lan.clear` 不清 DNS 信任。

### DTO

- `DnsSecurityStatusDto`：`Collecting`、`BaselineReady`、`BaselineUtc`、`ConfiguredCount`、
  `EventCount`、`NpcapVersion`、`LastError`；
- `DnsSecurityServerDto`：`Address`、`Adapter`、`Source`（configured/observed/trusted）、
  `Mac?`、`Trusted`；服务端用一张统一服务器表返回（已配置 → 已观察 → 仅信任），
  界面按 `Source` 显示“系统配置 / 观察到 / 已信任”；
- `DnsSecurityEventDto`：复用 `LanEventDto`（前端按 `kind` 过滤显示）；
- `ServiceStatus` 追加：`DnsSecurityCollecting`、`DnsSecurityEventCount`。

## 8. 界面

「防护 → DNS 安全」子页：

- 状态行：采集状态、配置的 DNS 服务器、基线时间、事件数；
- DNS 服务器表：地址 / 网卡 / 来源（系统配置 / 观察 / 已信任）/ MAC + 「信任 / 取消信任」；
- 事件表：时间 / 类型 / 级别 / 网卡 / 详情；
- 工具条：刷新、清空…（只清 DNS 事件）、「每 3 秒自动刷新」（默认开）；
- 无阻断按钮（DNS 不提供阻断）；
- 托盘提示：高危 DNS 事件弹一次（与 IDS 气泡共用通道，点击定位到该子标签）。

## 9. 测试

### 离线 `--dns-security-test`

- 合成 DNS 请求/应答（构造字节）：正常应答不告警；
- 服务器不符、事务 ID 不符、域名不符、NXDOMAIN 带答案、冲突应答、TTL=0、
  绕过查询分别命中；
- 信任后不再报；冷却生效；
- 事件读写复用 LanEventStore，清空只删 `dns_*`。

### VM `--service-dns-security-test`

- 状态/服务器列表/事件返回；
- 信任/取消信任；
- 清空只影响 DNS 事件。

### 手工

- Kali `dnsspoof` / `ettercap` DNS 投毒 → 5 秒内高危；
- Kali dnsmasq 作为“非配置 DNS” → 绕过命中；
- 正常浏览 24h 误报 0；
- 与 4.2 的 ARP 事件时间线对得上（先 MAC 变化，后 DNS 劫持）。

## 10. 风险

| 风险 | 对策 |
|---|---|
| DNS 应答被截断（snaplen） | 600 字节，覆盖绝大多数应答；截断时不报“冲突” |
| 上游轮询/多 A 记录 | 冲突规则只比“不同来源”或 2 秒内多应答，冷却 |
| 用户手动改 DNS | 绕过规则默认只告警 + 可信任 |
| DoH 看不到 | 文档写清；4.4/5.0 再考虑 SNI |
| 误伤网关阻断 | 不提供 DNS 阻断 |
| 事件与 4.2 混在同一文件 | 用 `dns_` 前缀区分，清空只删自己的 |
