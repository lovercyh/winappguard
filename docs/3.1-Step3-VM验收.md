# 3.1 第 3 步 VM 验收（协议 v2 + 服务端验签）

> **验收结果（2026-10-23，VM）：下列 1–6 全部通过。**
> 本轮实测：`--repair` 签名自检通过、service-auth 9/9、service-ping 2/2、
> auth-codec 9/9、ui-check 240/240。
>
> 这一步开始，服务只接受**所有者签名**的请求。
> 其他账户可以连上管道（管道 ACL 第 4 步才收紧），但拿不出有效签名。
> 验收包版本以 `WinAppGuardSetup.exe` 的 `ProductVersion` 为准。

## 一次性复制（管理员 PowerShell）

以后每轮验收的自动化命令都放在一个块里；任意一步失败就停下，
不要继续跑后面的。

```powershell
& {
    $ErrorActionPreference = 'Stop'
    cd C:\Users\VM\Downloads\默认项目\dist-tools

    $version = (Get-Item .\WinAppGuardSetup.exe).VersionInfo.ProductVersion
    Write-Host "版本 = $version"
    if ($version -notlike '3.1+*') { throw "版本不是 3.1+：$version" }

    .\WinAppGuardSetup.exe --repair
    if ($LASTEXITCODE -ne 0) { throw "Setup --repair 失败，退出码 $LASTEXITCODE" }
    Write-Host "[PASS] Setup --repair" -ForegroundColor Green

    .\WinAppGuard.SelfCheck.exe --service-auth-test --no-pause
    if ($LASTEXITCODE -ne 0) { throw "service-auth-test 失败，退出码 $LASTEXITCODE" }
    Write-Host "[PASS] service-auth-test" -ForegroundColor Green

    .\WinAppGuard.SelfCheck.exe --service-ping-test --no-pause
    if ($LASTEXITCODE -ne 0) { throw "service-ping-test 失败，退出码 $LASTEXITCODE" }
    Write-Host "[PASS] service-ping-test" -ForegroundColor Green

    .\WinAppGuard.SelfCheck.exe --auth-codec-test --no-pause
    if ($LASTEXITCODE -ne 0) { throw "auth-codec-test 失败，退出码 $LASTEXITCODE" }
    Write-Host "[PASS] auth-codec-test" -ForegroundColor Green

    .\WinAppGuard.SelfCheck.exe --ui-check --no-pause
    if ($LASTEXITCODE -ne 0) { throw "ui-check 失败，退出码 $LASTEXITCODE" }
    Write-Host "[PASS] ui-check" -ForegroundColor Green

    Write-Host "全部自动化验收通过。" -ForegroundColor Green
}
```

## 1. 修复/安装并做签名自检

```powershell
.\WinAppGuardSetup.exe --repair
```

期望完整看到：

```text
受保护模式：保留现有密钥（指纹 …）。
受保护模式：签名密钥已加载（指纹 …）。
服务已启动。
受保护模式：签名自检通过（所有者 VM\VM，指纹 …）。
修复完成，服务正在运行。
```

如果这里失败：

- `签名自检失败` / `认证失败`：服务没有认这把钥匙，**安装器会返回 6**；
- 不要继续后面的步骤，把完整输出和服务日志贴给我。

> 这一步本身就是“安装后签名自检”：服务没有正确加载公钥，
> 或客户端签名不被接受，安装器不会假装成功。

## 2. 服务端签名鉴权

```powershell
.\WinAppGuard.SelfCheck.exe --service-auth-test --no-pause
```

期望：**9/9**。覆盖：

- 正确签名能查询状态；
- status 报告 `ProtectedMode=true`、所有者、指纹、协议 2；
- challenge 返回 32 字节 nonce；
- 无签名请求被拒绝；
- 篡改签名被拒绝；
- 正确签名原始封套能通过；
- 重放旧签名被拒绝；
- 错误密钥被拒绝；
- 客户端没有 signer 时拒绝发送。

## 6. 手工：所有者界面

用**安装时的账户**普通权限打开桌面快捷方式：

- 状态栏正常，不显示离线；
- 能查看规则/记录；
- 改一条规则：应弹一次 UAC（提权助手），成功后规则生效；
- 标题/关于里的版本应为 3.1。

## 7. 手工：旧 3.0 界面（可选）

如果保留了 3.0 的 `WinAppGuard.exe`：

- 双击旧界面 → 应显示**离线**（连不上 v2 管道）；
- 不会出现“旧界面还能改规则”的情况。

## 8. 手工：配置缺失时失败关闭（可选）

> 会短暂停服务；做完必须恢复配置并重启服务。

```powershell
sc stop WinAppGuardSvc
Rename-Item "C:\ProgramData\WinAppGuard\protected-mode\config.json" "config.json.bak"
sc start WinAppGuardSvc
.\WinAppGuard.SelfCheck.exe --service-ping-test --no-pause
```

期望：

- 服务能启动（WFP/审计继续工作）；
- `--service-ping-test` 失败（控制管道不存在，失败关闭）；
- 服务日志出现：`受保护模式配置不可用，控制管道不会创建（失败关闭）。`

恢复：

```powershell
sc stop WinAppGuardSvc
Rename-Item "C:\ProgramData\WinAppGuard\protected-mode\config.json.bak" "config.json"
sc start WinAppGuardSvc
.\WinAppGuardSetup.exe --repair
```
