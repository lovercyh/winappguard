# 3.4 VM 验收（WFP 对象 owner-only DACL）

> 在虚拟机里验收；开发机只编译、打包。
> 需要管理员 PowerShell，以及**两个账户**：
> - A：安装时的所有者（提权账户）
> - B：另一个管理员账户（非所有者）

## 0. 准备

打包：

```powershell
powershell -ExecutionPolicy Bypass -File .\build\publish.ps1
```

把 `dist\` 复制到 VM，例如 `C:\Users\VM\Downloads\默认项目\dist-tools`。

`build\publish.ps1` 会自动把 4 个 exe、`WinAppGuard.SelfCheck.exe` 和验收脚本同步到 `dist-tools\`。
VM 上直接**整目录复制** `默认项目` 即可，不需要再单独拷文件。

## 一键脚本

`dist-tools\3.4-验收脚本.ps1` 已经由发布脚本同步好，按账户分三次运行：

```powershell
# 账户 A（所有者，管理员 PowerShell）
.\3.4-验收脚本.ps1 -Phase Owner

# 账户 B（另一个管理员）
.\3.4-验收脚本.ps1 -Phase NonOwner

# 回到账户 A，卸载
.\3.4-验收脚本.ps1 -Phase Cleanup
```

脚本会逐项打印 `[通过]/[失败]`；失败项直接贴回来即可。

如果不想用脚本文件，下面第 1–7 节是等价的逐条命令。

## 1. 版本与升级

```powershell
$version = (Get-Item .\WinAppGuardSetup.exe).VersionInfo.ProductVersion
$version
if ($version -notlike '3.4+*') { throw "版本不是 3.4+：$version" }

.\WinAppGuardSetup.exe --repair
if ($LASTEXITCODE -ne 0) { throw "repair 失败：$LASTEXITCODE" }
```

预期：

- 修复成功，服务启动；
- 服务日志出现 `WAG-WFP-011`（迁移成功）；
- 规则列表与 `before-3.4.txt` 一致（除到期时间自然变化）。

```powershell
# 迁移标记应存在，内容等于所有者 SID
$marker = Join-Path $env:ProgramData 'WinAppGuard\wfp-dacl-owner-only'
if (-not (Test-Path $marker)) { throw '没有迁移标记' }
Get-Content $marker
```

## 2. 真实 DACL 断言

先确保至少有一条规则（没有就加一条）：

```powershell
# 用界面或 CLI 加一条测试规则
.\WinAppGuardSvc.exe --cli --block "$env:WINDIR\System32\notepad.exe" --lang zh
```

运行（需管理员）：

```powershell
.\WinAppGuard.SelfCheck.exe --wfp-dacl-test --no-pause
if ($LASTEXITCODE -ne 0) { throw "wfp-dacl-test 失败：$LASTEXITCODE" }
```

预期：

- 子层 SDDL 包含 `(A;;0xF01FF;;;SY)` 和所有者 SID；
- 不包含 `(A;;0xF01FF;;;BA)`；
- 检查到的每条过滤器同样只包含 SYSTEM + 所有者；
- 退出码 0。

离线 SDDL 构造：

```powershell
.\WinAppGuard.SelfCheck.exe --wfp-dacl-sddl-test --no-pause
if ($LASTEXITCODE -ne 0) { throw "wfp-dacl-sddl-test 失败：$LASTEXITCODE" }
```

## 3. 非所有者管理员（账户 B）

用 B 登录（管理员），确认：

### 3.1 `--recover` 被拒绝

```powershell
.\WinAppGuardSvc.exe --cli --recover --lang zh
# 预期：退出码 2，提示「当前账户不是所有者」，规则不受影响
if ($LASTEXITCODE -ne 2) { throw "非所有者 --recover 退出码应为 2，实际 $LASTEXITCODE" }
```

### 3.2 卸载被拒绝

```powershell
.\WinAppGuardUninstall.exe --uninstall
# 预期：退出码 7，提示用所有者账户运行；服务/规则/文件都保持原样
if ($LASTEXITCODE -ne 7) { throw "非所有者卸载退出码应为 7，实际 $LASTEXITCODE" }
```

卸载后检查：

```powershell
sc.exe query WinAppGuardSvc
& .\WinAppGuardSvc.exe --cli --list-blocked --lang zh
```

预期：服务仍在运行、规则仍然存在（没有被半卸载）。

### 3.3 服务仍正常防护

- 打开界面（B 账户应显示非所有者/只读状态，与 3.1 一致）；
- 之前被阻止的程序仍然无法联网。

## 4. 所有者（账户 A）

### 4.1 `--recover` 可用

```powershell
.\WinAppGuardSvc.exe --cli --recover --lang zh
if ($LASTEXITCODE -ne 0) { throw "所有者 --recover 失败：$LASTEXITCODE" }
```

预期：WFP 对象被删除；随后恢复规则（重新添加或重新安装）。

> 注意：`--recover` 会删除本工具全部规则，属于救命命令，测完请重新安装/添加规则。

### 4.2 迁移重试

```powershell
# 删除标记 → 重启服务 → 应重新迁移且规则不丢
Remove-Item (Join-Path $env:ProgramData 'WinAppGuard\wfp-dacl-owner-only')
Restart-Service WinAppGuardSvc
Start-Sleep 3
& .\WinAppGuardSvc.exe --cli --list-blocked --lang zh
```

预期：日志再次出现 `WAG-WFP-011`；规则数量与迁移前一致。

### 4.3 卸载

最后再测：

```powershell
.\WinAppGuardUninstall.exe --uninstall
if ($LASTEXITCODE -ne 0) { throw "卸载失败：$LASTEXITCODE" }
```

预期：

- 服务、规则、快捷方式、数据目录、安装目录全部删除；
- `sc.exe query WinAppGuardSvc` 返回服务不存在；
- 迁移标记文件随数据目录一起删除。

## 5. 快照保护回归

验证「服务停止期间过滤器被删除，不会被快照覆盖」：

1. 添加一条规则；
2. 停服务：

```powershell
Stop-Service WinAppGuardSvc
```

3. 用管理员权限删除这条规则对应的 WFP 过滤器（可以用 `netsh wfp show filters` 找到本工具子层的过滤器 ID，再 `netsh wfp delete filter id=<id>`；也可以在 VM 快照里用测试工具）；
4. 启服务：

```powershell
Start-Service WinAppGuardSvc
Start-Sleep 5
& .\WinAppGuardSvc.exe --cli --list-blocked --lang zh
```

预期：规则被篡改防护按快照补回，日志出现 `WAG-RULE-913`，规则列表仍然有它。
