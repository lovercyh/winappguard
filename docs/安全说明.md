# WinAppGuard 安全说明

本文档回答两个问题：

1. **这个程序会对我的系统做什么？**
2. **我怎么自己验证它确实没做别的？**

每一条都给出**可执行的验证方法**，而不是只说「我们很安全」。

---

## 先跑这一条

如果你只打算做一件事，就跑这个：

```powershell
WinAppGuard.SelfCheck.exe --audit
```

它**不搜源码**，而是直接读**编译出来的程序集的元数据** —— 包括间接引用
和框架自动带进来的东西。输出会告诉你：

```
引用的程序集          22 个，全部来自 .NET 框架     → 零第三方库
会发起网络行为的类型   0 个                          → 程序自身零网络代码
原生 API 调用（P/Invoke）  16 个
注册表访问             无
```

那 16 个原生调用就是程序能碰到的**全部**非托管函数，逐条列出来带着用途。
除此之外它碰不到任何系统底层。

**⚠️ 但要分清两件事**：「程序自身不含网络代码」和「程序不会产生网络流量」不是一回事。
数字签名那一列默认会检查证书吊销状态，此时 Windows 的证书服务会代表本程序去联系 CA 服务器 ——
详见下方第 6 条的完整说明和自查方法。

`--audit` 是唯一一个**不需要管理员权限**的模式 —— 刻意这样设计，
好让它能在 CI（无法弹 UAC）里跑。

---

## 一、这个程序到底改了什么

WinAppGuard 对系统的全部写入只有两类，**没有第三类**：

| 写什么 | 在哪 | 代码位置 |
|---|---|---|
| 防火墙规则（出站） | Windows 防火墙 | `Core/FirewallManager.cs` |
| 一条计划任务 | 任务计划程序库根目录 | `Core/AutoStartManager.cs` |

除此之外，它只读三样东西：

- TCP 连接表（`GetExtendedTcpTable`）
- 进程的可执行文件路径（`QueryFullProcessImageName`）
- 上述两类配置的当前状态

以及在本机写一个日志文件（见下方「日志与隐私」）。

**所有危险操作都集中在 `Core/` 下的两个类里**，审计时只需要看这两个文件。

---

## 二、九条安全约定的实现与验证

### 1. 不修改全局防火墙策略

**实现**：`FirewallManager.cs` 里**没有任何**「关闭防火墙」「修改默认入站/出站动作」的代码 ——
这两个能力对应的 COM 属性（`FirewallEnabled`、`DefaultInboundAction`、`DefaultOutboundAction`）只被**读取**，从未被写入。

**自己验证**：

```powershell
# 操作前后各跑一次，输出必须完全一致
netsh advfirewall show allprofiles | Select-String "State|Firewall Policy"
```

或运行自检工具：`WinAppGuard.SelfCheck.exe --status`，它会打印全局状态。

---

### 2. 不关闭 Windows 防火墙

**实现**：同第 1 条。代码里不存在写入 `FirewallEnabled` 的路径。

**自己验证**：

```powershell
Get-NetFirewallProfile | Select-Object Name, Enabled, DefaultInboundAction, DefaultOutboundAction
```

---

### 3. 不删除非 AppGuard 前缀的规则

**实现**：`FirewallManager.DeleteRule` 的第一件事就是调 `EnsureAppGuardRuleName`，
规则名不以 `AppGuard_` 开头就**直接抛异常拒绝**，连尝试删除都不会。
`DeleteAllAppGuardRules` 也只能删掉按前缀筛选出来的那些。

**这是硬性代码约束，不是靠调用方自觉。** 即使界面有 bug、传进来一个错误的名字，底层也会拒绝。

**自己验证**：

```powershell
# 操作前后各跑一次，条数必须完全一致
(Get-NetFirewallRule | Measure-Object).Count
```

自检工具里也有这一项：完整测试会在操作前后对比「防火墙规则总数」，`421 -> 421` 才算通过。

---

### 4. 不阻止系统关键进程

**实现**：保护名单在 `Core/ProtectedProcesses.cs`，检查点在 `FirewallManager.ValidateProgramPath` ——
也就是**防火墙底层**，而不是界面层。界面上的置灰只是体验优化，绕过界面也照样会被拒绝。

名单：`System` / `Idle` / `Registry` / `Memory Compression` /
`smss.exe` `csrss.exe` `wininit.exe` `winlogon.exe` `services.exe` `lsass.exe` `svchost.exe` `dwm.exe` `audiodg.exe` /
`MsMpEng.exe` `NisSrv.exe` `SecurityHealthService.exe`，以及 **WinAppGuard 自身**。

**自己验证**：自检工具的完整测试里，这 8 个系统进程 + 自身一共 9 项，**每一项都必须被拒绝**。

`svchost.exe` 特别说明：它承载了 DNS 客户端、DHCP、Windows 更新等大量系统服务，
拦掉它会让整台机器的网络出现难以排查的异常，所以必须保护。

---

### 5. 所有危险操作必须弹出确认框

**实现**：所有会改动系统状态的操作都走 `Forms/ConfirmForm.cs`。它和 MessageBox 的区别是
**必须结构化地列出**：程序名、完整路径、影响范围、即将创建/删除的规则名，
并用醒目颜色单独列出风险。

需要确认的操作：阻止联网 / 允许联网 / 删除单条规则 / 删除全部规则 / 开启自启 / 关闭自启 / 退出程序。
其中**删除全部规则需要连续确认两次**。

**自己验证**：随便点一个操作，确认框会先出现；点「取消」后 `wf.msc` 或 `taskschd.msc` 里不应有任何变化。

> 已确认保留的行为：确认框上按回车**会**确认。这是产品负责人明确选择保留的（符合 Windows 用户普遍预期）。

---

### 6. 不发送用户数据

**实现**：程序里**没有任何网络代码**。没有 `HttpClient`、没有 `Socket`、没有 `WebRequest`、
没有遥测、没有崩溃上报。可以自行搜索源码确认：

```powershell
Select-String -Path .\src\WinAppGuard\**\*.cs -Pattern 'HttpClient|WebClient|Socket|WebRequest|TcpClient|UdpClient'
# 唯一会出现的是 ConnectionScanner 里读连接表用的 System.Net.IPAddress（只是数据格式化，不发起任何连接）
```

**⚠️ 必须区分两件事**：

| | 成立吗 |
|---|---|
| 本程序**自身不含网络代码** | ✅ 成立，可用 `--audit` 验证（会发起网络行为的类型 = 0） |
| 本程序**不会产生任何网络流量** | ⚠️ **默认不成立** —— 见下 |

### 6.1 证书吊销检查会联网（默认开启）

「数字签名」这一列默认会检查证书吊销状态。此时 **Windows 的证书服务（Crypt32）
会代表本程序去联系 CA 服务器**查询 CRL / OCSP。在资源监视器里，这些连接**记在
`WinAppGuard.exe` 名下** —— 虽然不是本程序的代码发起的，但从观察者的角度看是一样的。

**为什么这么设计**：不查吊销的话，一张已经被吊销的证书仍会被判定为「签名有效」，
结论不可靠。

**怎么关掉**：「设置 → 数据与隐私」→ 取消勾选「检查证书吊销状态（会联网查询 CA 服务器）」。
关掉之后使用 `WTD_CACHE_ONLY_URL_RETRIEVAL`，只读本机缓存，**完全不留任何网络流量**。

**自己验证**：

```powershell
# 1) 打开资源监视器 → 网络 → 在「网络活动」里找 WinAppGuard.exe
#    设置页勾选吊销检查时：能看到它连接 CA 服务器
#    取消勾选后：完全消失
# 2) 或者用抓包工具按进程过滤，观察同样的差异
```

**关掉之后**：

1. 打开「资源监视器」→「网络」标签 → 在「网络活动」里找 `WinAppGuard.exe`；
2. 或用 Wireshark 按进程过滤；
3. 让程序跑一段时间并做几次阻止/允许操作，**不应该出现任何由它发起的连接**。

---

### 7. 不在运行时调用任何在线服务（含 AI 接口）

**实现**：同第 6 条。程序运行时没有任何网络代码，也就无从调用任何在线服务。
DeepSeek 只参与了开发阶段写代码，最终产物里不含任何相关调用。

**自己验证**：同第 6 条；另外可搜索源码：

```powershell
Select-String -Path .\src -Pattern 'api\.|token|apiKey|Authorization' -CaseSensitive:$false
```

---

### 8. 开机自启必须透明可见

**实现**（四层透明）：

| 层面 | 做法 |
|---|---|
| 命名 | 任务名固定 `WinAppGuard`，**不是随机名**，放在任务计划程序库根目录 |
| 不隐藏 | 任务**没有**勾选「隐藏」；代码里也没有写 `<Hidden>` |
| 界面可见 | 「设置」页直接显示任务的**原始 XML**，看到的就是系统里实际存的东西 |
| 状态真实 | 状态每次都是**实时读取**系统；你在 `taskschd.msc` 里手动删掉，界面点「重新读取状态」立刻变回「未开启」 |

**自己验证**：

1. 打开 `taskschd.msc` → 任务计划程序库 → 找到 `WinAppGuard`；
2. 右键 →「属性」→ 逐个标签核对（界面上的 XML 应该和这里完全对得上）；
3. 「常规」标签里「隐藏」**必须未勾选**。

---

### 9. 用户必须能关闭开机自启

**实现**：「设置」页的「关闭开机自启」按钮，一次确认后删除任务。
另外**用户也可以完全绕过本程序**，直接打开 `taskschd.msc` 手动删除这条任务 —— 程序不会阻止、也不会重新创建。

**自己验证**：

1. 点「关闭开机自启」→ 任务从 `taskschd.msc` 消失；
2. 注销 → 重新登录 → 不会自动启动；
3. 再手动在 `taskschd.msc` 里删掉任务后回到界面点「重新读取状态」→ 显示「未开启」。

## 三、其它风险提示

### 提权持久化会被安全软件关注（已知现象）

「计划任务 + 最高权限 + 登录时触发」这个组合在技术上等同于提权持久化，
杀毒软件和 EDR 可能会给出提示。这是**机制本身的性质**，不是本程序做了什么隐蔽的事。
所有内容都可见、可删，见上方第 8、9 条。

### 未签名的 exe 会被 SmartScreen 拦截

发布出来的 exe 没有代码签名，Windows 首次运行会提示「未知发布者」。
要消除这个提示需要购买代码签名证书，这属于发布流程之外的事情。

### 阻止规则按「可执行文件路径」生效

Windows 防火墙规则不支持按 PID 拦截。所以：

- 同一个 exe 开多个实例、带不同参数，会被**一起**拦掉；
- 同一个程序换到别的目录运行，**不受影响**；
- 程序更新后如果安装路径变了，旧规则会失效，需要重新设置。

### 「退出程序」不等于「放行程序」

关掉界面（包括从托盘退出）**不会**删除任何防火墙规则，被阻止的程序依然上不了网。
托盘退出时的确认框会明确写出这一点。
要放行，必须用「允许选中程序联网」或「删除全部 AppGuard 规则」。

## 四、日志与隐私

### 记什么

| 级别 | 内容 |
|---|---|
| `信息` | 启动（版本 / 是否有管理员权限 / 启动模式）、退出 |
| `操作` | 阻止联网、允许联网、删除规则、开关开机自启（含目标程序路径和规则名） |
| `警告` | 未以管理员身份运行等 |
| `错误` | 各操作失败的原因和堆栈 |

**不记录**每次扫描到的连接明细 —— 连接列表每 3 秒刷新一次，把明细写进去会迅速撑爆文件，而且没有价值。

### 写在哪

```
%LOCALAPPDATA%\WinAppGuard\logs\winappguard-yyyyMMdd.log
```

- 按天分文件，**只保留最近 7 天**，更早的自动删除；
- 「设置」页里直接显示这个路径，并提供「打开日志目录」按钮；
- **日志只写本机，不会发送到任何地方。**

### 想彻底清干净？

关闭开机自启 → 点「删除全部 AppGuard 规则」→ 退出程序 → 删掉 `%LOCALAPPDATA%\WinAppGuard` 目录。
系统里不会残留任何东西。

---

## 五、完整的卸载步骤

```
1. 打开 WinAppGuard
2. 「已阻止的程序」页 → 删除全部 AppGuard 规则
3. 「设置」页 → 关闭开机自启
4. 托盘右键 → 退出
5. 删除 WinAppGuard.exe
6. （可选）删除 %LOCALAPPDATA%\WinAppGuard 目录（只剩日志）
```

第 2、3 步不做就直接删 exe 的话，防火墙规则和计划任务会**留在系统里继续生效**。
真遇到这种情况，用 `wf.msc` 搜 `AppGuard` 删规则、用 `taskschd.msc` 删任务即可。
